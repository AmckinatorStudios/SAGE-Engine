# Слияние в main и релиз

Каждое удалённое действие — только с прямого разрешения пользователя в этой
сессии. Прямое поручение «слей в main» разрешает пункты 4–5; резерв (3), релиз
и откат — только если названы. Не получено — остановиться и спросить. Навык
вызывает модель; если вызов заблокирован, слияние вручную в обход не делать:
назвать причину блокировки и остановиться.

1. `CHANGELOG.md`: запись с датой правки, разделы Исправлено / Добавлено /
   Изменено / Ускорено. Последняя запись уходит в описание релиза. `VERSION`
   не менять (0.5.0 до 1.0).
2. **Допуск (все пункты, иначе стоп — не сливать и не объяснять «почти»):**
   - `/verify` раздел 4 пройден полностью (все обязательные этапы, ни один не
     пропущен): `cat build/.verify-full` равен `git rev-parse <ветка>`. Файла
     нет или хеш другой — проверка не пройдена или устарела: запустить
     `/verify`, исправить, повторить, потом вернуться сюда;
   - `git status --porcelain` пуст: после проверки нет правок, требующих нового
     прогона (правка проверяемого кода после штампа — новый полный прогон);
   - нет конфликтов и неразрешённых ошибок (`git diff --name-only --diff-filter=U`
     пуст; ошибки `/verify` исправлены, а не отложены).
3. Резервная ветка — только если пользователь просит:
   `git fetch origin main && git branch -f claude/backup-main-<ГГГГММДД>-<sha> origin/main`,
   пуш этой ветки (не тега — теги дают 403). Резерв не удалять.
4. `git fetch origin main && git checkout main && git merge --no-ff <ветка>`
   — граница правки в истории, откат `git revert -m 1 <слияние>`.
5. `git push origin main` — по разрешению. Затем проверить результат:
   `git fetch origin main`; `git log -1 --merges --format=%H origin/main`
   — слияние на месте; `git merge-base --is-ancestor <ветка> origin/main`;
   `git status -sb` — чисто, без расхождения с `origin/main`. Не сошлось —
   сообщить, не «чинить» вручную.
6. Релизы собирают `linux.yml` (`linux-latest`) и `windows.yml`
   (`windows-latest`), только с `main`. Проверить, что оба зелёные и в
   описании релиза дата и коммит совпадают с запушенным; упало — сообщить и
   предложить исправление. `macos.yml` — ручной запуск, не ждать и не чинить.
   Резервные ветки не собираются (`branches-ignore` в `windows.yml`).
7. Рабочую ветку не удалять.

Жёсткий откат (`reset --hard` на резерв + `push --force-with-lease`) — только
по прямой просьбе.
