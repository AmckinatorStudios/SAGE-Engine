# SAGE AI

Система построения поведения персонажей, противников и NPC.

**Три инструмента, у каждого своё назначение:**

| Инструмент | Файл | Для чего |
|---|---|---|
| SAGE Lua | `.slua` | текстовая игровая логика и задачи ИИ (`ai.task`) |
| Script Graph | `.sgraph` | визуальная игровая логика объектов — см. [visual_scripting.md](visual_scripting.md) |
| AI Graph | `.aigraph` | визуальное поведение ИИ: задачи, условия, контекст, управление поведением |

AI Graph — специализированный инструмент: в нём только узлы ИИ, и он
выполняется как задача со своим жизненным циклом (начало, выполнение между
кадрами, успех / неудача / прерывание). Игровой логике (Branch, циклы,
игровые действия) место в Script Graph.

## Назначение

Движок **не содержит готовых сценариев** — ни патруля, ни преследования, ни
распорядка дня. Он даёт три вещи: запустить задачу, дождаться её и управлять
ею. Что задача делает, решает автор игры. `InvestigateNoise`, `SearchArea`,
`DailyRoutine` в примерах ниже — пользовательские имена, а не встроенные.

Поведение собирается в AI Graph; задачи — узлами AI Graph (Move To Target,
Follow Target, Find Target…), другим AI Graph или на SAGE Lua / C++
(`ai.task`). Правила выполнения у всех одни и живут в ядре
(`engine/src/sage/ai/`), поэтому поведение зовёт задачу по имени и не знает, на
чём та написана.

## Три уровня поведения

| Уровень | Что делает | Чем выражается |
|---|---|---|
| Управление поведением | выбирает задачу, порядок, повтор, прерывание по приоритету | **AI Graph**: Decide, Task Sequence, Selector, If Condition, Repeat |
| Задачи поведения | действие с результатом: идти, следовать, найти, ждать, взаимодействовать | узлы задач AI Graph, другой AI Graph, `ai.task(...)` на SAGE Lua, C++ |
| Условия и контекст | проверить цель, дистанцию, состояние, параметр; память персонажа | узлы «Условия» и «Контекст ИИ» AI Graph |

У AI Graph и Script Graph **раздельные наборы узлов**: в AI Graph нет
Branch, Sequence потока, циклов, переменных и игровых действий Script Graph,
в Script Graph нет задач, условий и управления поведением ИИ. Правило
соблюдается везде — в палитре, при проверке, при загрузке файла и при
выполнении: не тот узел в не том графе — ошибка с названием узла, а не тихий
запуск.

AI Graph — тоже задача мира ИИ (регистрируется задачей с именем графа), поэтому
то же самое можно написать и на SAGE Lua:

```lua
ai.task("Brain", {
    run = function(t)
        while true do
            if t.instance.heard_noise then
                t.run("InvestigateNoise", {where = t.instance.heard_noise})
                t.instance.heard_noise = nil
            else
                t.run("DailyRoutine")
            end
            t.wait()
        end
    end,
})
```

## Задачи на Lua

```lua
ai.task("MoveTo", {
    inputs  = {target = Vec3(0, 0, 0), speed = 3},   -- имя = умолчание (и тип)
    outputs = {distance = 0},
    run = function(t)
        local body = t.self   -- тот, кого передали ai.agent (в скрипте нового вида — self)
        while (body.Transform.Position - t.inputs.target):Length() > 0.2 do
            -- шаг движения своими силами: физика, навигация, анимация
            t.wait()                                   -- до следующего кадра
        end
        t.outputs.distance = 0
        return true                                    -- успех
    end,
    cancel = function(t)                               -- необязательно: прибрать
        -- остановить персонажа
    end,
})
```

- `run(t)` — тело задачи. Это корутина: `t.wait(...)` отдаёт управление, и
  задача продолжается с того же места, когда ожидание кончилось. Долгая задача
  **не начинается заново** каждый кадр.
- Вернуть `true` (или ничего) — успех. `return false, "причина"` или
  `t.fail("причина")` — неудача. Ошибка Lua — тоже неудача, и она уходит в
  журнал как дефект скрипта.
- `inputs` и `outputs` объявляют имена и типы. Неизвестный вход при запуске,
  запись в необъявленный выход, опечатка в поле — **ошибка с этим именем**, а
  не тихое умолчание. Без `inputs` задача принимает любые входы.
- То же имя второй раз — замена описания (горячая перезагрузка): идущие
  выполнения доживают со старым, новые берут новое.

Контекст `t`:

| Поле / метод | Что это |
|---|---|
| `t.inputs`, `t.outputs` | входы и выходы этого выполнения |
| `t.locals` | Local: данные этого выполнения |
| `t.instance` | Instance: память экземпляра ИИ (персонажа) |
| `t.shared` | Shared: общая область экземпляра |
| `t.self`, `t.agent` | хозяин экземпляра (объект сцены) и сам экземпляр |
| `t.wait()` / `t.wait(сек)` | следующий кадр / столько секунд |
| `t.wait_until(fn, таймаут?)` | пока `fn()` не вернёт true; `false` — по таймауту |
| `t.wait_event(имя, таймаут?)` | событие; возвращает `true, данные` или `false` |
| `t.start(имя, входы?, {priority = N}?)` | запустить дочернюю задачу параллельно, вернуть ручку |
| `t.run(имя, входы?, {priority = N}?)` | запустить и дождаться: `ok, ручка` |
| `t.wait_for(h)`, `t.wait_all(h1, h2, …)` | дождаться одной / всех; `true`, если все успешны |
| `t.wait_any(h1, h2, …)` | дождаться первой завершившейся, вернуть её ручку |
| `t.fail(причина)` | завершиться неудачей |
| `t.emit(событие, данные?, кому?)` | разбудить ждущих события |
| `t.call(операция, …)` | вызвать операцию |

## Экземпляр ИИ

```lua
function Start()
    brain = ai.agent(self, {shared = "guards"})   -- хозяин и общая область
    brain.memory.post = Vec3(10, 0, 4)
    main = brain.start("Brain")
end
```

| Поле / метод | Что это |
|---|---|
| `a.start(имя, входы?)` | запустить верхнюю задачу, вернуть ручку |
| `a.memory` | память экземпляра (= `t.instance` его задач) |
| `a.shared` | общая область (= `t.shared`) |
| `a.owner`, `a.id` | хозяин и номер |
| `a.stop()` | отменить все задачи экземпляра |
| `a.destroy()` | отменить всё и удалить экземпляр |
| `a.emit(событие, данные?)` | событие только этому экземпляру |
| `a.running()` | сколько верхних задач идёт |

Хозяин необязателен (`ai.agent()` — «режиссёр» уровня). Объект‑хозяин удалён
из сцены — экземпляр уходит вместе со всеми задачами.

## Состояния и управление выполнением

Ручка выполнения `h` (из `start`):

| Поле | Значение |
|---|---|
| `h.status` | `"running"`, `"succeeded"`, `"failed"`, `"cancelled"` |
| `h.done`, `h.ok` | завершилась; завершилась успешно |
| `h.error` | причина неудачи или `nil` |
| `h.outputs`, `h.inputs`, `h.locals` | данные выполнения (выходы читаются и после конца) |
| `h.cancel()` | отменить |

Правила:

- **Дочерняя задача не переживает родителя.** Родитель завершился (любым
  исходом) или отменён — его живые дети отменяются. Отменил «Бой» — остановились
  и «Стрелять», и «Искать укрытие».
- **Отмена идёт изнутри наружу**: сначала дети, потом сама задача; у каждой
  зовётся `cancel(t)`.
- Задача, дочерняя которой завершилась мгновенно, продолжает **в том же
  кадре**. Бесконечный цикл мгновенных задач упирается в предел
  (`World::kMaxStepsPerFrame` шагов на выполнение за кадр) и продолжается в
  следующем кадре, а не вешает игру.
- Ждущая задача стоит одной проверки за кадр: исполнителя не зовут, пока
  ожидание не кончилось. Это то, что держит сотни NPC одновременно.

## Приоритеты, каналы и прерывание

Задача объявляет, какие **каналы** персонажа она занимает, и можно ли её
прервать:

```lua
ai.task("ChasePlayer", {channels = {"legs"}, run = ...})            -- ноги
ai.task("Shout",       {channels = {"voice"}, run = ...})           -- голос
ai.task("Arrest",      {channels = {"legs", "hands"}, interruptible = false, run = ...})
```

У AI Graph то же самое — слева в редакторе: «Занимаемые
каналы» и «Можно прервать». Каналы — имена автора игры, движок их не знает.

Правила (`World::Start`):

- Задачи на **разных** каналах (или без каналов) идут параллельно: бежать и
  кричать можно одновременно.
- Новая задача на **занятом** канале прерывает старую, только если её
  приоритет **выше** и старая прерываемая. Старая отменяется с причиной
  «прервана задачей 'X' (приоритет a > b) за канал 'legs'».
- Иначе новая **не запускается**: Failed с причиной «канал 'legs' занят задачей
  'Arrest' (приоритет 50, непрерываемая)». Решение видит неудачу и выбирает
  другое.
- Предки не конфликтуют с потомками: «Бой» на ногах может запустить «Бежать к
  укрытию» на ногах.
- Приоритет — у запуска: `t.start(имя, входы, {priority = 20})`, настройка
  Priority у Run Task / Call Task, вход priority у вариантов Decide.

**Отмена всегда с причиной** (`h.error`, «Причина» в отладчике): родитель
кончился, решение AI Graph переключилось, вытеснила задача за канал,
`World::Cancel(run, причина)`. У задачи зовётся `cancel(t)` — прибрать.

**Повтор после неудачи** — решением, а не флагом задачи: вариант Decide с
отдыхом (cooldown) снова участвует в выборе через столько секунд.

## Переменные: Local, Instance, Shared

| Область | Где | Живёт |
|---|---|---|
| Local | `t.locals` | пока идёт выполнение |
| Instance | `t.instance`, `a.memory` | пока жив экземпляр ИИ |
| Shared | `t.shared`, `ai.shared("имя")` | пока жив мир ИИ (до остановки игры) |

Shared разделена на именованные области — пределы задаёт автор: у стражей
`guards`, у торговцев `merchants`; по умолчанию у всех `world`.

Значения — общий тип движка (`sage::vars::Value`): логическое, целое, дробное,
строка, `Vec2`/`Vec3`/`Vec4`, поворот, объект сцены, а также список и структура.
Тот же тип у публичных переменных и событий, поэтому граф и Lua передают друг
другу ровно одно и то же. Таблица Lua становится списком (ключи 1..n) или
структурой (имена полей; имя типа — в `_type`) и возвращается в Lua тем же.
Функцию положить нельзя (ошибка с именем переменной). `nil` удаляет
переменную. Список имён — `ai.names(t.instance)`.

## События

```lua
-- кто-то шумит
ai.emit("noise", self.Transform.Position)          -- всем экземплярам
brain.emit("noise", where)                         -- только этому

-- страж слушает
local heard, where = t.wait_event("noise", 5)      -- не дольше 5 секунд
```

Событие будит тех, кто ждёт его **сейчас**; очереди нет. Шум, прозвучавший,
пока страж был занят другим, он не услышал — «запомнить на потом» выражается
памятью экземпляра.

## Операции

Операция — мгновенное действие без ожидания и состояния; граф покажет её
узлом. Порядок входов важен (зовут по позициям), поэтому объявление — список
пар:

```lua
ai.operation("in_range", function(a, b, r) return (a - b):Length() <= r end, {
    inputs  = {{"a", Vec3()}, {"b", Vec3()}, {"radius", 1.0}},
    outputs = {{"yes", false}},
})
local yes = ai.call("in_range", me, enemy, 5)
```

Объявление необязательно; без него входы передаются как есть. `ai.tasks()` и
`ai.operations()` — списки имён.

## Задачи на C++ и граф

Мир ИИ скриптов открыт C++: `scriptEngine.AI()` (`sage::ai::World`). Задача на
C++ регистрируется в ту же библиотеку и зовётся из Lua по имени — и наоборот:

```cpp
sage::ai::TaskSignature sig;
sig.Inputs = {{"seconds", sage::vars::Value(1.0f)}};
scripts.AI().RegisterTask(sage::ai::MakeTask("Sleep", sig, [](sage::ai::TaskContext& t) {
    if (t.Phase()++ == 0) {                 // шаг 0: назначить ожидание
        t.WaitSeconds(t.Inputs().Get("seconds").AsFloat());
        return sage::ai::TaskStatus::Running;
    }
    return sage::ai::TaskStatus::Succeeded; // шаг 1: ожидание кончилось
}));
```

Своя реализация задачи (так подключится SAGE AI Graph и любой другой язык) —
наследник `TaskDefinition` (описание: имя, подпись, `Create()`) и
`TaskBehavior` (исполнитель одного запуска: `Step`, `Cancel`). Операции —
`World::RegisterOperation`.

## Как это устроено

```
sage/ai (слой «службы»)            sage/scripting
  Blackboard   ─ переменные          ScriptApi_AI.cpp
  Task.h       ─ описание, исполнитель,   ai.task / ai.agent / ai.call …
                 выполнение, ожидания       корутина задачи на своём потоке Lua
  World        ─ библиотека, экземпляры,
                 планировщик, события
```

- Ядро не знает ни Lua, ни сцены: хозяина‑объекта оно спрашивает у движка
  скриптов через `SetOwnerAlive`. Поэтому оно в нижнем слое, и граф, C++ и Lua
  стоят на нём одинаково.
- Кадр: `ScriptEngine::UpdateAll` после скриптов кадра зовёт `World::Tick` —
  задача, запущенная из `OnUpdate`, делает первый шаг в этом же кадре.
- Порядок шагов детерминирован (порядок запуска), очередь пробуждений — в
  пределах одного кадра.
- Отмена из собственного шага (`a.stop()` внутри задачи) откладывается до
  конца шага: исполнитель в этот момент на стеке.
- Мир ИИ объявлен в `ScriptEngine` после состояния Lua и умирает раньше
  него: описания и корутины держат функции Lua.

Проверки: `tests/test_ai.cpp` (ядро), `tests/test_ai_lua.cpp` (Lua и вызовы
между Lua и C++), `tests/test_ai_concept.cpp` (пример охранника целиком:
решения, каналы, прерывание, движение, память, профиль).

## Производительность и профиль

- **Событийно, а не опросом.** Ждущая задача стоит одной проверки за кадр;
  Decide спит до срока перепроверки (Re-check every, по умолчанию 0.25 с),
  события или конца ветки — сотни NPC не пересчитывают решения каждый кадр.
- Частота перепроверки — настройка узла: важному противнику 0.1 с, фоновой
  толпе 1 с.
- **Профиль** (`World::Stats()`, окно «Отладчик ИИ» → «Профиль»): по каждой
  задаче — запуски, шаги, время шагов на процессоре, самый долгий шаг, чем
  кончались. «Какой NPC съел кадр» видно числом. Считается всегда (пара чтений
  часов на шаг), сброс — `ResetStats()`.

## SAGE AI Graph

Визуальное построение поведения ИИ: задачи, условия, контекст и управление
поведением. Только узлы ИИ — игровая логика собирается в Script Graph
([visual_scripting.md](visual_scripting.md)). Недостающее добавляется узлом
на Lua (`ai.node`).

### Файл и библиотека

AI Graph — файл `assets/ai/*.aigraph` (JSON). Вид графа задаёт РАСШИРЕНИЕ:
`.aigraph` — только поведение ИИ, `.sgraph` — только Script Graph. Файл, в
котором вид поправили руками (`"kind": "script"` в `.aigraph`), не
загружается — ошибка называет файл и причину. Новый граф создаётся окном
«Создать…» (тип «AI Graph») сразу с узлом **Task Start**.

Каждый AI Graph регистрируется **задачей** с именем графа: его зовут узлом
Run Task из другого AI Graph, `t.run("Patrol")` из SAGE Lua, `World::Start` из
C++. У графа свои входы, выходы и локальные переменные, каналы и «можно
прервать» (слева в редакторе).

**Библиотека ИИ проекта** — всё из `assets/ai/` и `assets/visual/`
(рекурсивно): сначала `.lua` и `.slua` (задачи, свои узлы, типы, операции),
затем графы (`.aigraph`, `.sgraph`, старые `.vgraph`). Её грузит Play редактора
и собранная игра до скриптов объектов, а редактор графов — для палитры. Из
Lua: `ai.load_library(dir)`, `ai.graph(path)`.

### Компонент AI

«Добавить компонент → Logic → AI»: AI Graph (слотом или перетаскиванием
`.aigraph` на объект в иерархии или во вьюпорте), общая область (`guards`),
«Запускать граф при Play» и **память на старте** — параметры Instance, у
каждого персонажа свои при одном общем графе. Компонент запускает только AI
Graph: Script Graph ставится своим компонентом. Объект удалили — ИИ уходит с
ним. Из скрипта: `ai.agent_of(obj)` (`.memory`, `.emit`, `.stop()`).

### Жизненный цикл задачи

AI Graph — задача поведения, и её цикл записан узлами:

1. Персонаж (компонент AI, Run Task, `t.run`) **выбирает** задачу.
2. Задача **получает контекст**: входы, память персонажа (Instance), общую
   область (Shared), свои локальные данные.
3. Выполнение **начинается** с узла **Task Start** (он в графе ровно один).
4. Долгие узлы (Move To Target, Follow Target, Wait, Run Task) **продолжаются
   между кадрами**: запускаются один раз и ждут своего конца, а не стартуют
   каждый кадр.
5. Задача **возвращает результат**: выполняется, успех (**Succeed**),
   неудача с причиной (**Fail** или неудача задачи, чей выход неудачи ни с
   чем не соединён), прерывание (**Abort Behavior**, отмена извне).
6. По результату выбирается дальнейшее поведение: Task Sequence, Selector,
   Repeat, Decide читают результат своих веток.
7. Изменились условия — **If Condition** снимает свою ветку, **Decide**
   переключается на более важный вариант; снятая ветка отменяет свою задачу
   (движение прекращается, причина пишется в отладчик).

**Результат ветки.** Узел управления запускает варианты дочерними ветками и
решает по их результату: ветка кончается успехом, если дошла до конца или до
Succeed, и неудачей — на Fail или на неудаче задачи без провода. Неудача
поднимается до задачи с причиной: «шаг 1: задача 'Open' не смогла».

### Узлы AI Graph

| Раздел | Узлы |
|---|---|
| Задача | **Task Start**, **Succeed**, **Fail** (причина), **Abort Behavior** (отменить всё поведение) |
| Управление поведением | **Task Sequence** (шаги по порядку, первая неудача — неудача), **Selector** (первый удачный вариант), **If Condition** (ветка, пока условие истинно; ложное — прерывание), **Repeat** (N раз / до неудачи / до успеха; круг — со следующего кадра), **Decide** (приоритеты, перепроверка по времени и событиям, «можно прервать», отдых варианта), Start Task / Wait For Task / Cancel Task |
| Задачи поведения | **Run Task** (задача SAGE Lua, C++ или другой AI Graph, с входами и выходами), **Find Target**, **Select Target**, **Forget Target**, **Move To Target** (к цели или точке, контроллером персонажа), **Follow Target**, **Face Target**, **Interact** (функция скрипта цели), **Wait**, **Wait Until**, **Wait For Event**, **Send AI Event** |
| Условия | **Check Condition** (условие → успех/неудача), **Has Target**, **Can See Target** (дальность, угол обзора, заслонённость), **Target Within Distance**, **In State**, **Compare Parameter**, **Can Run Task** (свободны ли каналы), **All Of**, **Any Of**, **Not** |
| Контекст ИИ | **Self**, **Current Target**, **Get Parameter** / **Set Parameter** (instance, shared, local, input, output), **Set State**, **Last Result** (итог прошлой задачи), **Remember Event** (событие → память), Task Status, Task Output |

Связь с игрой — **явными точками**: перемещение — контроллером персонажа
(физика, ступени, стены), видимость — лучом физики, взаимодействие — функцией
скрипта объекта. Произвольных игровых операций в AI Graph нет.

**Цель** — память персонажа `target`. Её ставят Find Target и Select Target,
читают Current Target и условия, по ней идут Move To Target и Follow Target.
Конец задачи цель не стирает.

**Состояние** — память `state` (Set State / In State): «патруль», «тревога» —
и Decide переключает поведение по нему.

### Свои узлы, типы и правила на Lua

```lua
-- assets/ai/mygame.slua (или .lua) — библиотека ИИ проекта
ai.type("Target", {fields = {{"pos", Vec3()}, {"seen", false}}})

ai.node("mygame.low_health", {           -- своё условие ИИ
    title = "Low Health", category = "Conditions", pure = true,
    inputs  = {{"limit", "float", 25}},
    outputs = {{"result", "bool"}},
    run = function(n) n.outputs.result = (n.instance.hp or 100) < n.inputs.limit end,
})
ai.path_finder(function(from, to) return my_navmesh:path(from, to) end)
```

- `ai.node` — узел AI Graph, `visual.node` — узел Script Graph, `domain =
  "both"` — обоим.
- `n.inputs.x` — вход, `n.outputs.y = …` — выход, `n.settings`, `n.self`,
  `n.instance`. Узел с потоком возвращает имя выхода (`return "yes"`) или
  ничего — по первому.
- Пины: `{имя, тип, умолчание, подпись}`; тип `"exec"` — поток.
- Узел выполняется мгновенно; то, что длится, — задача (`ai.task`), её зовёт
  Run Task.

### Редактор

«Окно → AI Graph» или двойной щелчок / перетаскивание `.aigraph` в окно.
Палитра (правый щелчок, провод в пустоту) показывает **только узлы ИИ** с
поиском по названию и разделам. Слева — имя, описание, входы, выходы,
локальные, каналы и «можно прервать». Проблемы проверки — знаком на узле,
списком внизу с переходом к узлу. Группы, комментарии, Reroute, отмена
(Ctrl+Z/Y), Ctrl+S — как в Script Graph.

### Отладка

Пока идёт Play, отладчик (`sage::ai::GraphDebugger`) пишет:

- **на холсте** (выбрать выполнение над холстом): над узлами-задачами —
  **выполняется / успех / неудача**; узлы, шагавшие недавно, светятся; где
  стоят ветки — жёлтая рамка; пауза — красная; значения пинов при наведении;
- **точки останова** — F9; F5 — дальше, F10 — один узел;
- **окно «Отладчик ИИ»**: дерево задач (граф, Lua, C++) под запустившими их,
  состояние и **причина конца**, живые параметры, **последнее решение**
  («почему выбрана эта ветка»), история с фильтром «Решения» и вкладка
  **«Профиль»**.

### Пример: охранник

Задачи Patrol, ChasePlayer, AnalyzeEvidence — на SAGE Lua (канал `legs`);
InvestigateNoise — AI Graph: Task Start → Move To Target (к точке шума) →
Wait → Succeed. Поведение — AI Graph GuardBrain:

```
Task Start → Decide (interval 0.1)
   option 0: sees_player,  priority 30 → Run Task ChasePlayer
   option 1: heard,        priority 20 → Task Sequence:
                                          step 0 Run Task InvestigateNoise(where = noise_pos)
                                          step 1 Run Task AnalyzeEvidence → Set Parameter evidence
                                          step 2 Set Parameter heard = false
   option 2: true,         priority 10 → Run Task Patrol
Remember Event "noise" → noise_pos, флаг heard
```

Шум — Remember Event пишет его в память, Decide просыпается от события,
Patrol отменяется («решение AI Graph: вариант 1 важнее»), охранник идёт к
шуму контроллером. Увидел игрока — ChasePlayer прерывает расследование.
Целиком пример проверяет `tests/test_ai_concept.cpp`; узлы по их
определениям — `tests/test_ai_behavior.cpp`.

## Старые форматы

- `.vgraph` (Visual Script прежних версий) — **не создаётся**. Script Graph
  объекта из `.vgraph` открывается в редакторе Script Graph и работает в
  компоненте как прежде; граф задачи (`task`) из `.vgraph` загружается
  библиотекой и открывается в Script Graph с пометкой «старый формат». Узлы,
  которые теперь принадлежат только AI Graph (Run Task и управление задачами),
  в нём отмечаются ошибкой проверки с причиной, и такой граф не запускается —
  его задачу переносят в AI Graph или на SAGE Lua.
- `.lua` — **не создаётся** (основной язык — SAGE Lua); существующие скрипты и
  библиотеки на Lua работают.
- Файлы не переименовываются и не удаляются автоматически.

## Чего пока нет

- Встроенного навигационного меша: Find Path идёт по навигации проекта
  (`ai.path_finder`) или по прямой.
- Сохранения состояния задач в сейв: память экземпляра — обычные значения, их
  можно записать самому через `sage.save`.
