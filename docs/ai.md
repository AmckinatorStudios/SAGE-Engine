## Назначение

Движок **не содержит готовых сценариев** — ни патруля, ни преследования, ни
распорядка дня. Он даёт три вещи: запустить задачу, дождаться её и управлять
ею. Что задача делает, решает автор игры. `InvestigateNoise`, `SearchArea`,
`DailyRoutine` в примерах ниже — пользовательские имена, а не встроенные.

Писать поведение можно на Lua, на C++ и (дальше) в визуальном SAGE AI Graph.
Правила выполнения у всех одни и живут в ядре (`engine/src/sage/ai/`), поэтому
задача на Lua зовёт задачу на графе или C++ по имени и не знает, на чём та
написана.

## Три уровня поведения

| Уровень | Что делает | Чем выражается |
|---|---|---|
| Принятие решений | выбирает, что делать сейчас | задача, которая запускает другие задачи |
| Задачи | последовательности действий, ожидания, проверки | `ai.task(...)` |
| Операции | одно мгновенное действие: проверить, вычислить, спросить мир | `ai.operation(...)`, весь API движка |

Отдельного «механизма решений» нет намеренно: решение — тоже задача. Главная
задача персонажа смотрит на память и мир и запускает подходящую:

```lua
ai.task("Brain", {
    run = function(t)
        while true do
            if t.instance.heard_noise then
                t.run("InvestigateNoise", {where = t.instance.heard_noise})
                t.instance.heard_noise = nil
            else
                t.run("DailyRoutine")
            end
            t.wait()
        end
    end,
})
```

## Задачи на Lua

```lua
ai.task("MoveTo", {
    inputs  = {target = Vec3(0, 0, 0), speed = 3},   -- имя = умолчание (и тип)
    outputs = {distance = 0},
    run = function(t)
        local body = t.self   -- тот, кого передали ai.agent (в скрипте нового вида — self)
        while (body.Transform.Position - t.inputs.target):Length() > 0.2 do
            -- шаг движения своими силами: физика, навигация, анимация
            t.wait()                                   -- до следующего кадра
        end
        t.outputs.distance = 0
        return true                                    -- успех
    end,
    cancel = function(t)                               -- необязательно: прибрать
        -- остановить персонажа
    end,
})
```

- `run(t)` — тело задачи. Это корутина: `t.wait(...)` отдаёт управление, и
  задача продолжается с того же места, когда ожидание кончилось. Долгая задача
  **не начинается заново** каждый кадр.
- Вернуть `true` (или ничего) — успех. `return false, "причина"` или
  `t.fail("причина")` — неудача. Ошибка Lua — тоже неудача, и она уходит в
  журнал как дефект скрипта.
- `inputs` и `outputs` объявляют имена и типы. Неизвестный вход при запуске,
  запись в необъявленный выход, опечатка в поле — **ошибка с этим именем**, а
  не тихое умолчание. Без `inputs` задача принимает любые входы.
- То же имя второй раз — замена описания (горячая перезагрузка): идущие
  выполнения доживают со старым, новые берут новое.

Контекст `t`:

| Поле / метод | Что это |
|---|---|
| `t.inputs`, `t.outputs` | входы и выходы этого выполнения |
| `t.locals` | Local: данные этого выполнения |
| `t.instance` | Instance: память экземпляра ИИ (персонажа) |
| `t.shared` | Shared: общая область экземпляра |
| `t.self`, `t.agent` | хозяин экземпляра (объект сцены) и сам экземпляр |
| `t.wait()` / `t.wait(сек)` | следующий кадр / столько секунд |
| `t.wait_until(fn, таймаут?)` | пока `fn()` не вернёт true; `false` — по таймауту |
| `t.wait_event(имя, таймаут?)` | событие; возвращает `true, данные` или `false` |
| `t.start(имя, входы?)` | запустить дочернюю задачу параллельно, вернуть ручку |
| `t.run(имя, входы?)` | запустить и дождаться: `ok, ручка` |
| `t.wait_for(h)`, `t.wait_all(h1, h2, …)` | дождаться одной / всех; `true`, если все успешны |
| `t.wait_any(h1, h2, …)` | дождаться первой завершившейся, вернуть её ручку |
| `t.fail(причина)` | завершиться неудачей |
| `t.emit(событие, данные?, кому?)` | разбудить ждущих события |
| `t.call(операция, …)` | вызвать операцию |

## Экземпляр ИИ

```lua
function Start()
    brain = ai.agent(self, {shared = "guards"})   -- хозяин и общая область
    brain.memory.post = Vec3(10, 0, 4)
    main = brain.start("Brain")
end
```

| Поле / метод | Что это |
|---|---|
| `a.start(имя, входы?)` | запустить верхнюю задачу, вернуть ручку |
| `a.memory` | память экземпляра (= `t.instance` его задач) |
| `a.shared` | общая область (= `t.shared`) |
| `a.owner`, `a.id` | хозяин и номер |
| `a.stop()` | отменить все задачи экземпляра |
| `a.destroy()` | отменить всё и удалить экземпляр |
| `a.emit(событие, данные?)` | событие только этому экземпляру |
| `a.running()` | сколько верхних задач идёт |

Хозяин необязателен (`ai.agent()` — «режиссёр» уровня). Объект‑хозяин удалён
из сцены — экземпляр уходит вместе со всеми задачами.

## Состояния и управление выполнением

Ручка выполнения `h` (из `start`):

| Поле | Значение |
|---|---|
| `h.status` | `"running"`, `"succeeded"`, `"failed"`, `"cancelled"` |
| `h.done`, `h.ok` | завершилась; завершилась успешно |
| `h.error` | причина неудачи или `nil` |
| `h.outputs`, `h.inputs`, `h.locals` | данные выполнения (выходы читаются и после конца) |
| `h.cancel()` | отменить |

Правила:

- **Дочерняя задача не переживает родителя.** Родитель завершился (любым
  исходом) или отменён — его живые дети отменяются. Отменил «Бой» — остановились
  и «Стрелять», и «Искать укрытие».
- **Отмена идёт изнутри наружу**: сначала дети, потом сама задача; у каждой
  зовётся `cancel(t)`.
- Задача, дочерняя которой завершилась мгновенно, продолжает **в том же
  кадре**. Бесконечный цикл мгновенных задач упирается в предел
  (`World::kMaxStepsPerFrame` шагов на выполнение за кадр) и продолжается в
  следующем кадре, а не вешает игру.
- Ждущая задача стоит одной проверки за кадр: исполнителя не зовут, пока
  ожидание не кончилось. Это то, что держит сотни NPC одновременно.

## Переменные: Local, Instance, Shared

| Область | Где | Живёт |
|---|---|---|
| Local | `t.locals` | пока идёт выполнение |
| Instance | `t.instance`, `a.memory` | пока жив экземпляр ИИ |
| Shared | `t.shared`, `ai.shared("имя")` | пока жив мир ИИ (до остановки игры) |

Shared разделена на именованные области — пределы задаёт автор: у стражей
`guards`, у торговцев `merchants`; по умолчанию у всех `world`.

Значения — общий тип движка (`sage::vars::Value`): логическое, целое, дробное,
строка, `Vec2`/`Vec3`/`Vec4`, объект сцены. Тот же тип у публичных переменных и
событий, поэтому граф и Lua передают друг другу ровно одно и то же. Таблицу или
функцию положить нельзя (ошибка с именем переменной): составное состояние —
несколько переменных, а для временного внутри одной задачи хватает обычных
локальных переменных Lua. `nil` удаляет переменную. Список имён —
`ai.names(t.instance)`.

## События

```lua
-- кто-то шумит
ai.emit("noise", self.Transform.Position)          -- всем экземплярам
brain.emit("noise", where)                         -- только этому

-- страж слушает
local heard, where = t.wait_event("noise", 5)      -- не дольше 5 секунд
```

Событие будит тех, кто ждёт его **сейчас**; очереди нет. Шум, прозвучавший,
пока страж был занят другим, он не услышал — «запомнить на потом» выражается
памятью экземпляра.

## Операции

Операция — мгновенное действие без ожидания и состояния; граф покажет её
узлом. Порядок входов важен (зовут по позициям), поэтому объявление — список
пар:

```lua
ai.operation("in_range", function(a, b, r) return (a - b):Length() <= r end, {
    inputs  = {{"a", Vec3()}, {"b", Vec3()}, {"radius", 1.0}},
    outputs = {{"yes", false}},
})
local yes = ai.call("in_range", me, enemy, 5)
```

Объявление необязательно; без него входы передаются как есть. `ai.tasks()` и
`ai.operations()` — списки имён.

## Задачи на C++ и граф

Мир ИИ скриптов открыт C++: `scriptEngine.AI()` (`sage::ai::World`). Задача на
C++ регистрируется в ту же библиотеку и зовётся из Lua по имени — и наоборот:

```cpp
sage::ai::TaskSignature sig;
sig.Inputs = {{"seconds", sage::vars::Value(1.0f)}};
scripts.AI().RegisterTask(sage::ai::MakeTask("Sleep", sig, [](sage::ai::TaskContext& t) {
    if (t.Phase()++ == 0) {                 // шаг 0: назначить ожидание
        t.WaitSeconds(t.Inputs().Get("seconds").AsFloat());
        return sage::ai::TaskStatus::Running;
    }
    return sage::ai::TaskStatus::Succeeded; // шаг 1: ожидание кончилось
}));
```

Своя реализация задачи (так подключится SAGE AI Graph и любой другой язык) —
наследник `TaskDefinition` (описание: имя, подпись, `Create()`) и
`TaskBehavior` (исполнитель одного запуска: `Step`, `Cancel`). Операции —
`World::RegisterOperation`.

## Как это устроено

```
sage/ai (слой «службы»)            sage/scripting
  Blackboard   ─ переменные          ScriptApi_AI.cpp
  Task.h       ─ описание, исполнитель,   ai.task / ai.agent / ai.call …
                 выполнение, ожидания       корутина задачи на своём потоке Lua
  World        ─ библиотека, экземпляры,
                 планировщик, события
```

- Ядро не знает ни Lua, ни сцены: хозяина‑объекта оно спрашивает у движка
  скриптов через `SetOwnerAlive`. Поэтому оно в нижнем слое, и граф, C++ и Lua
  стоят на нём одинаково.
- Кадр: `ScriptEngine::UpdateAll` после скриптов кадра зовёт `World::Tick` —
  задача, запущенная из `OnUpdate`, делает первый шаг в этом же кадре.
- Порядок шагов детерминирован (порядок запуска), очередь пробуждений — в
  пределах одного кадра.
- Отмена из собственного шага (`a.stop()` внутри задачи) откладывается до
  конца шага: исполнитель в этот момент на стеке.
- Мир ИИ объявлен в `ScriptEngine` после состояния Lua и умирает раньше
  него: описания и корутины держат функции Lua.

Проверки: `tests/test_ai.cpp` (ядро), `tests/test_ai_lua.cpp` (Lua и вызовы
между Lua и C++).

## Чего пока нет

- Визуального редактора SAGE AI Graph — следующие части. Точка подключения
  готова: `TaskDefinition`/`TaskBehavior` и библиотека по имени.
- Встроенной навигации и восприятия: задачи пользуются тем, что уже есть в
  движке (физика, лучи, контроллер персонажа).
- Сохранения состояния задач в сейв: память экземпляра — обычные значения, их
  можно записать самому через `sage.save`.
