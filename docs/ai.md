## Назначение

Движок **не содержит готовых сценариев** — ни патруля, ни преследования, ни
распорядка дня. Он даёт три вещи: запустить задачу, дождаться её и управлять
ею. Что задача делает, решает автор игры. `InvestigateNoise`, `SearchArea`,
`DailyRoutine` в примерах ниже — пользовательские имена, а не встроенные.

Решения пишутся в AI Graph (или Lua-задачей-«мозгом»), задачи — в Visual
Scripting (граф вида Task), на Lua или C++. Правила выполнения у всех одни и
живут в ядре (`engine/src/sage/ai/`), поэтому решение зовёт задачу по имени и
не знает, на чём та написана.

## Три уровня поведения

| Уровень | Что делает | Чем выражается |
|---|---|---|
| Принятие решений | выбирает, что делать сейчас, и когда переключиться | **AI Graph** (узел Decide, Run/Cancel Task, события) |
| Задачи | как задача выполняется: действия, ожидания, проверки, движение | граф Task в **Visual Scripting**, `ai.task(...)` на Lua, C++ |
| Операции | одно мгновенное действие: проверить, вычислить, спросить мир | `ai.operation(...)`, весь API движка |

Узлы делятся так же. **Общие** (Branch, Sequence, Parallel, Wait, математика,
переменные, Run Task) есть в обоих редакторах. **Управление задачами** (Decide,
Call/Cancel/Wait For Task, Task Status, события ИИ) — только в AI Graph.
**Действия над миром** (Set Position, Move To, Look At, Set Property, Call
Script) — только в задачах и скриптах Visual Scripting: AI Graph решает, а не
двигает объекты. Не тот узел в не том графе — ошибка проверки графа с
объяснением, а не тихий запуск.

Решение — тоже задача мира ИИ (граф решений регистрируется задачей), поэтому
то же самое можно написать и на Lua:

```lua
ai.task("Brain", {
    run = function(t)
        while true do
            if t.instance.heard_noise then
                t.run("InvestigateNoise", {where = t.instance.heard_noise})
                t.instance.heard_noise = nil
            else
                t.run("DailyRoutine")
            end
            t.wait()
        end
    end,
})
```

## Задачи на Lua

```lua
ai.task("MoveTo", {
    inputs  = {target = Vec3(0, 0, 0), speed = 3},   -- имя = умолчание (и тип)
    outputs = {distance = 0},
    run = function(t)
        local body = t.self   -- тот, кого передали ai.agent (в скрипте нового вида — self)
        while (body.Transform.Position - t.inputs.target):Length() > 0.2 do
            -- шаг движения своими силами: физика, навигация, анимация
            t.wait()                                   -- до следующего кадра
        end
        t.outputs.distance = 0
        return true                                    -- успех
    end,
    cancel = function(t)                               -- необязательно: прибрать
        -- остановить персонажа
    end,
})
```

- `run(t)` — тело задачи. Это корутина: `t.wait(...)` отдаёт управление, и
  задача продолжается с того же места, когда ожидание кончилось. Долгая задача
  **не начинается заново** каждый кадр.
- Вернуть `true` (или ничего) — успех. `return false, "причина"` или
  `t.fail("причина")` — неудача. Ошибка Lua — тоже неудача, и она уходит в
  журнал как дефект скрипта.
- `inputs` и `outputs` объявляют имена и типы. Неизвестный вход при запуске,
  запись в необъявленный выход, опечатка в поле — **ошибка с этим именем**, а
  не тихое умолчание. Без `inputs` задача принимает любые входы.
- То же имя второй раз — замена описания (горячая перезагрузка): идущие
  выполнения доживают со старым, новые берут новое.

Контекст `t`:

| Поле / метод | Что это |
|---|---|
| `t.inputs`, `t.outputs` | входы и выходы этого выполнения |
| `t.locals` | Local: данные этого выполнения |
| `t.instance` | Instance: память экземпляра ИИ (персонажа) |
| `t.shared` | Shared: общая область экземпляра |
| `t.self`, `t.agent` | хозяин экземпляра (объект сцены) и сам экземпляр |
| `t.wait()` / `t.wait(сек)` | следующий кадр / столько секунд |
| `t.wait_until(fn, таймаут?)` | пока `fn()` не вернёт true; `false` — по таймауту |
| `t.wait_event(имя, таймаут?)` | событие; возвращает `true, данные` или `false` |
| `t.start(имя, входы?, {priority = N}?)` | запустить дочернюю задачу параллельно, вернуть ручку |
| `t.run(имя, входы?, {priority = N}?)` | запустить и дождаться: `ok, ручка` |
| `t.wait_for(h)`, `t.wait_all(h1, h2, …)` | дождаться одной / всех; `true`, если все успешны |
| `t.wait_any(h1, h2, …)` | дождаться первой завершившейся, вернуть её ручку |
| `t.fail(причина)` | завершиться неудачей |
| `t.emit(событие, данные?, кому?)` | разбудить ждущих события |
| `t.call(операция, …)` | вызвать операцию |

## Экземпляр ИИ

```lua
function Start()
    brain = ai.agent(self, {shared = "guards"})   -- хозяин и общая область
    brain.memory.post = Vec3(10, 0, 4)
    main = brain.start("Brain")
end
```

| Поле / метод | Что это |
|---|---|
| `a.start(имя, входы?)` | запустить верхнюю задачу, вернуть ручку |
| `a.memory` | память экземпляра (= `t.instance` его задач) |
| `a.shared` | общая область (= `t.shared`) |
| `a.owner`, `a.id` | хозяин и номер |
| `a.stop()` | отменить все задачи экземпляра |
| `a.destroy()` | отменить всё и удалить экземпляр |
| `a.emit(событие, данные?)` | событие только этому экземпляру |
| `a.running()` | сколько верхних задач идёт |

Хозяин необязателен (`ai.agent()` — «режиссёр» уровня). Объект‑хозяин удалён
из сцены — экземпляр уходит вместе со всеми задачами.

## Состояния и управление выполнением

Ручка выполнения `h` (из `start`):

| Поле | Значение |
|---|---|
| `h.status` | `"running"`, `"succeeded"`, `"failed"`, `"cancelled"` |
| `h.done`, `h.ok` | завершилась; завершилась успешно |
| `h.error` | причина неудачи или `nil` |
| `h.outputs`, `h.inputs`, `h.locals` | данные выполнения (выходы читаются и после конца) |
| `h.cancel()` | отменить |

Правила:

- **Дочерняя задача не переживает родителя.** Родитель завершился (любым
  исходом) или отменён — его живые дети отменяются. Отменил «Бой» — остановились
  и «Стрелять», и «Искать укрытие».
- **Отмена идёт изнутри наружу**: сначала дети, потом сама задача; у каждой
  зовётся `cancel(t)`.
- Задача, дочерняя которой завершилась мгновенно, продолжает **в том же
  кадре**. Бесконечный цикл мгновенных задач упирается в предел
  (`World::kMaxStepsPerFrame` шагов на выполнение за кадр) и продолжается в
  следующем кадре, а не вешает игру.
- Ждущая задача стоит одной проверки за кадр: исполнителя не зовут, пока
  ожидание не кончилось. Это то, что держит сотни NPC одновременно.

## Приоритеты, каналы и прерывание

Задача объявляет, какие **каналы** персонажа она занимает, и можно ли её
прервать:

```lua
ai.task("ChasePlayer", {channels = {"legs"}, run = ...})            -- ноги
ai.task("Shout",       {channels = {"voice"}, run = ...})           -- голос
ai.task("Arrest",      {channels = {"legs", "hands"}, interruptible = false, run = ...})
```

У графа задачи Visual Scripting то же самое — слева в редакторе: «Занимаемые
каналы» и «Можно прервать». Каналы — имена автора игры, движок их не знает.

Правила (`World::Start`):

- Задачи на **разных** каналах (или без каналов) идут параллельно: бежать и
  кричать можно одновременно.
- Новая задача на **занятом** канале прерывает старую, только если её
  приоритет **выше** и старая прерываемая. Старая отменяется с причиной
  «прервана задачей 'X' (приоритет a > b) за канал 'legs'».
- Иначе новая **не запускается**: Failed с причиной «канал 'legs' занят задачей
  'Arrest' (приоритет 50, непрерываемая)». Решение видит неудачу и выбирает
  другое.
- Предки не конфликтуют с потомками: «Бой» на ногах может запустить «Бежать к
  укрытию» на ногах.
- Приоритет — у запуска: `t.start(имя, входы, {priority = 20})`, настройка
  Priority у Run Task / Call Task, вход priority у вариантов Decide.

**Отмена всегда с причиной** (`h.error`, «Причина» в отладчике): родитель
кончился, решение AI Graph переключилось, вытеснила задача за канал,
`World::Cancel(run, причина)`. У задачи зовётся `cancel(t)` — прибрать.

**Повтор после неудачи** — решением, а не флагом задачи: вариант Decide с
отдыхом (cooldown) снова участвует в выборе через столько секунд.

## Переменные: Local, Instance, Shared

| Область | Где | Живёт |
|---|---|---|
| Local | `t.locals` | пока идёт выполнение |
| Instance | `t.instance`, `a.memory` | пока жив экземпляр ИИ |
| Shared | `t.shared`, `ai.shared("имя")` | пока жив мир ИИ (до остановки игры) |

Shared разделена на именованные области — пределы задаёт автор: у стражей
`guards`, у торговцев `merchants`; по умолчанию у всех `world`.

Значения — общий тип движка (`sage::vars::Value`): логическое, целое, дробное,
строка, `Vec2`/`Vec3`/`Vec4`, поворот, объект сцены, а также список и структура.
Тот же тип у публичных переменных и событий, поэтому граф и Lua передают друг
другу ровно одно и то же. Таблица Lua становится списком (ключи 1..n) или
структурой (имена полей; имя типа — в `_type`) и возвращается в Lua тем же.
Функцию положить нельзя (ошибка с именем переменной). `nil` удаляет
переменную. Список имён — `ai.names(t.instance)`.

## События

```lua
-- кто-то шумит
ai.emit("noise", self.Transform.Position)          -- всем экземплярам
brain.emit("noise", where)                         -- только этому

-- страж слушает
local heard, where = t.wait_event("noise", 5)      -- не дольше 5 секунд
```

Событие будит тех, кто ждёт его **сейчас**; очереди нет. Шум, прозвучавший,
пока страж был занят другим, он не услышал — «запомнить на потом» выражается
памятью экземпляра.

## Операции

Операция — мгновенное действие без ожидания и состояния; граф покажет её
узлом. Порядок входов важен (зовут по позициям), поэтому объявление — список
пар:

```lua
ai.operation("in_range", function(a, b, r) return (a - b):Length() <= r end, {
    inputs  = {{"a", Vec3()}, {"b", Vec3()}, {"radius", 1.0}},
    outputs = {{"yes", false}},
})
local yes = ai.call("in_range", me, enemy, 5)
```

Объявление необязательно; без него входы передаются как есть. `ai.tasks()` и
`ai.operations()` — списки имён.

## Задачи на C++ и граф

Мир ИИ скриптов открыт C++: `scriptEngine.AI()` (`sage::ai::World`). Задача на
C++ регистрируется в ту же библиотеку и зовётся из Lua по имени — и наоборот:

```cpp
sage::ai::TaskSignature sig;
sig.Inputs = {{"seconds", sage::vars::Value(1.0f)}};
scripts.AI().RegisterTask(sage::ai::MakeTask("Sleep", sig, [](sage::ai::TaskContext& t) {
    if (t.Phase()++ == 0) {                 // шаг 0: назначить ожидание
        t.WaitSeconds(t.Inputs().Get("seconds").AsFloat());
        return sage::ai::TaskStatus::Running;
    }
    return sage::ai::TaskStatus::Succeeded; // шаг 1: ожидание кончилось
}));
```

Своя реализация задачи (так подключится SAGE AI Graph и любой другой язык) —
наследник `TaskDefinition` (описание: имя, подпись, `Create()`) и
`TaskBehavior` (исполнитель одного запуска: `Step`, `Cancel`). Операции —
`World::RegisterOperation`.

## Как это устроено

```
sage/ai (слой «службы»)            sage/scripting
  Blackboard   ─ переменные          ScriptApi_AI.cpp
  Task.h       ─ описание, исполнитель,   ai.task / ai.agent / ai.call …
                 выполнение, ожидания       корутина задачи на своём потоке Lua
  World        ─ библиотека, экземпляры,
                 планировщик, события
```

- Ядро не знает ни Lua, ни сцены: хозяина‑объекта оно спрашивает у движка
  скриптов через `SetOwnerAlive`. Поэтому оно в нижнем слое, и граф, C++ и Lua
  стоят на нём одинаково.
- Кадр: `ScriptEngine::UpdateAll` после скриптов кадра зовёт `World::Tick` —
  задача, запущенная из `OnUpdate`, делает первый шаг в этом же кадре.
- Порядок шагов детерминирован (порядок запуска), очередь пробуждений — в
  пределах одного кадра.
- Отмена из собственного шага (`a.stop()` внутри задачи) откладывается до
  конца шага: исполнитель в этот момент на стеке.
- Мир ИИ объявлен в `ScriptEngine` после состояния Lua и умирает раньше
  него: описания и корутины держат функции Lua.

Проверки: `tests/test_ai.cpp` (ядро), `tests/test_ai_lua.cpp` (Lua и вызовы
между Lua и C++), `tests/test_ai_concept.cpp` (пример охранника целиком:
решения, каналы, прерывание, движение, память, профиль).

## Производительность и профиль

- **Событийно, а не опросом.** Ждущая задача стоит одной проверки за кадр;
  Decide спит до срока перепроверки (Re-check every, по умолчанию 0.25 с),
  события или конца ветки — сотни NPC не пересчитывают решения каждый кадр.
- Частота перепроверки — настройка узла: важному противнику 0.1 с, фоновой
  толпе 1 с.
- **Профиль** (`World::Stats()`, окно «Отладчик ИИ» → «Профиль»): по каждой
  задаче — запуски, шаги, время шагов на процессоре, самый долгий шаг, чем
  кончались. «Какой NPC съел кадр» видно числом. Считается всегда (пара чтений
  часов на шаг), сброс — `ResetStats()`.

## SAGE AI Graph

Визуальное программирование поведения узлами и проводами — без кода, но и без
стены, если нужной возможности нет: её добавляют узлом на Lua.

### Графы и где они лежат

Граф — файл JSON. Виды и редакторы:

| Вид | Редактор, файл | Зачем |
|---|---|---|
| Граф решений (`behavior`) | AI Graph, `assets/ai/*.aigraph` | какую задачу выполнять и когда сменить |
| Граф задачи (`task`) | Visual Script, `assets/visual/*.vgraph` | как задача выполняется: действия, движение, ожидания |
| Скрипт объекта (`script`) | Visual Script | игровая логика объекта (On Start / On Update) |
| Граф-функция (`function`) | оба | переиспользуемый блок только из общих узлов |

Граф чужого вида открывается в своём редакторе сам: задачу из старого
проекта, лежащую в `assets/ai`, правят в Visual Script.

Каждый граф регистрируется **задачей** с именем графа. Поэтому граф зовут
отовсюду одинаково: узлом Run Task из другого графа, `t.run("Patrol")` из Lua,
`World::Start` из C++. У графа свои входы, выходы и локальные переменные.

**Библиотека ИИ проекта** — всё из `assets/ai/` и `assets/visual/`
(рекурсивно): сначала `.lua` (задачи, свои узлы, типы, операции), затем графы. Её грузит Play
редактора и собранная игра (из пакета) до скриптов объектов, а редактор
графов — для палитры. Из Lua: `ai.load_library(dir)`, `ai.graph(path)`.

### Компонент AI

«Добавить компонент → Logic → AI»: граф поведения (слотом, перетащить
`.aigraph`), общая область (`guards`), «Запускать граф при Play» и **память на
старте** — переменные Instance, у каждого объекта свои при одном общем графе.
В Play объект получает экземпляр ИИ и запускает граф; объект удалили — ИИ
уходит с ним. Из скрипта: `ai.agent_of(obj)` — тот же экземпляр (`.memory`,
`.emit`, `.stop()`).

### Как граф выполняется

- Узлы двух родов: **с потоком** (белые треугольные пины — порядок действий) и
  **чистые** (только данные: вычисляются, когда их спросили, каждый раз
  заново — «расстояние до цели» в условии цикла всегда свежее).
- **Ветки выполнения.** Parallel и обработчики событий ведут несколько веток
  сразу. Ветка, дошедшая до ожидания (Wait, Run Task, Wait For Event), стоит и
  не шагает: `Run Task: MoveTo` запускает перемещение один раз и ждёт его.
- **Конец графа** — узел Return (вход `ok`: успех или неудача, `reason` —
  причина) или когда все ветки дошли до конца. Граф с узлом On Event сам не
  кончается — ждёт событий, пока его не отменят.
- **Защита от зависания:** больше 10 000 узлов за кадр без ожидания — граф
  завершается неудачей «похоже на бесконечный цикл», а не вешает игру.
- Неизвестный узел (не загружена библиотека с Lua-узлом) — граф не
  запускается, причина называет узел.

### Узлы

| Раздел | Узлы |
|---|---|
| Поток | Start, Sequence, Branch, Loop While, For Loop, For Each, Break, Parallel (все / первая), Wait, Wait Until, Return, End Branch, Select, Reroute |
| Решения (AI Graph) | **Decide** — варианты с условием, приоритетом и «можно прервать»; перепроверка по времени и событиям, отдых варианта |
| Задачи | Run Task (общий: запустить и дождаться, выходы — пинами, настройка Priority); только AI Graph: Call Task (запустить и идти дальше → ручка), Wait For Task, Cancel Task, Task Status, Task Output |
| События | On Event, Wait For Event (с таймаутом); Emit Event — AI Graph |
| Переменные | Get Variable, Set Variable — области local, instance, shared, input, output |
| Функции | Call Operation (C++, Lua, API), Call Lua Function, Log |
| Математика и логика | арифметика по числам и векторам, Clamp, Lerp, Random, векторы, сравнения, И/Или/Не, преобразования, строки |
| Списки и структуры | Make/Get/Set/Add/Remove/Find/Random Item, Array Length; Make/Break Struct, Get/Set Field |
| Повороты | из углов и в углы, Rotate Vector, Look Rotation, Combine, Blend, Transform Point |
| Мир | Self, Find Object, Object Info (есть ли, имя, позиция, направление), Distance To; действия (задачи и скрипты) — Set Position, Look At, **Move To** (каждый кадр к точке через контроллер персонажа, если он есть; arrived / failed по таймауту) |
| Восприятие | Raycast, Line Of Sight, Can See (дальность + угол обзора + заслонённость), Find Nearby |
| Навигация | Find Path — навигация проекта (`ai.path_finder`) или прямая |
| Объект | Get/Set Property по пути (`Light.Intensity`, `Transform.Position`), Call Script — функция скрипта объекта |
| API движка | узел на **каждую** функцию `sage.<модуль>.<имя>` |

Узлы мира — данные и действия, а не поведение: «видит ли» отвечает Can See,
а что персонаж сделает, увидев, — рисунок автора. Движение идёт системами
движка (контроллер персонажа, физика), а не телепортом.

**Decide.** Варианты сверху вниз; у каждого — `condition i`, `priority i`,
`interruptible i` и выход потока `option i` (обычно Run Task нужной задачи).
Выполняется ветка самого важного варианта с истинным условием. Переключение —
когда истинным стал более важный, а текущий прерываемый, или когда условие
текущего перестало выполняться; ветка старого снимается вместе с задачей,
которую ждёт (причина «решение AI Graph: …»). Непрерываемый вариант доигрывает.
Выходы `active` и `reason`; каждое решение — запись «decision» в отладчике.

**Расширяемость без правки редактора.** Узлы «API движка» строятся из той же
таблицы сигнатур, что подсказка редактора кода (`SageApiTable.inl`): новый
`Bind(...)` в движке — новый узел сам. Get/Set Property и Call Script достают
до любого свойства компонента и любой функции скрипта, в том числе своих
компонентов и скриптов игры.

### Типы данных

Boolean, Integer, Float, String, Vector2, Vector3, Color, Rotation, Transform
(структура: position, rotation, scale), Object Reference, Asset, Array, Struct,
Task (ручка выполнения) и **свои типы** (`ai.type`). Цвет пина — по типу.

Совместимость проверяется **до** того, как провод проведён: тот же тип; Any с
чем угодно; целое ↔ дробное; что угодно → строка; векторы между собой; Vector3 ↔
поворот (углы); одно значение → список. Несовместимый провод не проводится, у
курсора — причина. Свои правила (`ai.connect_rule`, `ai.convert_rule`) стоят
**впереди** встроенных: могут и разрешить своё, и запретить встроенное.

### Свои узлы, типы и правила на Lua

```lua
-- assets/ai/mygame.lua — библиотека ИИ проекта
ai.type("Target", {fields = {{"pos", Vec3()}, {"seen", false}}})

ai.node("mygame.heal", {
    title = "Heal", category = "My game", description = "Restores health",
    inputs  = {{"target", "object"}, {"amount", "float", 10}},
    outputs = {{"healed", "float"}},
    run = function(n)
        n.outputs.healed = heal(n.inputs.target, n.inputs.amount)
    end,
    connect = function(pin, type)          -- своё правило проводов (необязательно)
        if pin == "amount" and type == "string" then return false, "только числа" end
    end,
})

ai.connect_rule(function(from, to) if from == "Target" and to == "vec3" then return true end end)
ai.convert_rule(function(v, to) if to == "vec3" and v._type == "Target" then return v.pos end end)
ai.path_finder(function(from, to) return my_navmesh:path(from, to) end)
```

- `n.inputs.x` — значение входа, `n.outputs.y = …` — выход, `n.settings`,
  `n.self`, `n.instance`. Узел с потоком возвращает имя выхода, по которому
  идти (`return "yes"`), или ничего — по первому.
- Пины: `{имя, тип, умолчание, подпись}`; тип `"exec"` — поток. У узла с
  потоком без явных пинов потока появляются `in` и `then`.
- `settings = {{"mode", "choice", "fast", {"fast", "slow"}}}` — настройки в окне
  свойств.
- Узел выполняется мгновенно; то, что длится, — Lua-задача (`ai.task`), в
  графе её зовёт Run Task.
- `domain`: без указания `ai.node` годится AI Graph и задачам Visual
  Scripting; `"ai"` — только AI Graph, `"task"` — то же, что умолчание,
  `"script"` — Visual Scripting, `"both"` — везде.

### Редактор графов

«Окно → AI Graph» или двойной щелчок по `.aigraph` в Assets. Задачи —
«Окно → Visual Script», тот же редактор с другой палитрой.

- **Слева** — граф: имя (по нему зовут задачу), вид, описание, входы, выходы,
  локальные переменные с типами и умолчаниями.
- **В центре** — холст. Правый щелчок — палитра с поиском (по названию,
  разделу, ключевым словам). Провод из пина, отпущенный в пустоту, открывает
  палитру только с подходящими узлами и сразу подключает выбранный. Alt+щелчок
  по пину — снять провода. Колесо — масштаб, средняя/правая кнопка с
  протягиванием — сдвиг, F — показать всё.
- **Справа** — выбранный узел: описание, настройки (задача, операция, событие,
  переменная — списком), значения несоединённых входов, комментарий над
  узлом, точка останова.
- **Большие графы:** группы (рамка с заголовком тащит узлы внутри, угол —
  размер), комментарии, Reroute, графы-функции; двойной щелчок по Run Task
  открывает граф задачи.
- Del, Ctrl+D, Ctrl+C/V, Ctrl+Z/Y, Ctrl+S — пока окно графа в фокусе, клавиши
  его, а не сцены.

### Отладка

Пока идёт Play, отладчик (`sage::ai::GraphDebugger`) пишет:

- **на холсте** (выбрать выполнение в списке над холстом): узлы, шагавшие
  недавно, светятся и остывают; узлы, где стоят ветки, — в жёлтой рамке; пауза
  — красной; у пина при наведении — последнее значение;
- **точки останова** — F9 или красная метка в заголовке узла; F5 — дальше,
  F10 — один узел;
- **окно «Отладчик ИИ»**: дерево всех задач игры (граф, Lua, C++) под
  запустившими их, состояние и **причина конца** (ошибка, отмена), живые
  переменные (входы, выходы, локальные, память экземпляра, общая область),
  **последнее решение** (почему выбрана эта задача) и история — шаги, решения,
  события, запуски и концы задач, ошибки, Log; вкладка **«Профиль»** —
  стоимость задач.

В собранной игре отладчик выключен и не стоит ничего.

### Пример: охранник

Задачи — Patrol, ChasePlayer (Lua, канал `legs`), InvestigateNoise (граф Task
Visual Scripting: Move To к месту шума, запись в память), SearchArea,
ReturnToRoutine. Решение — граф GuardBrain в AI Graph:

```
Start → Decide (interval 0.25)
          option 0: condition = instance.sees_player,  priority 30 → Run Task ChasePlayer
          option 1: condition = instance.noise_at != nil, priority 20 → Run Task InvestigateNoise → SearchArea
          option 2: condition = true,                   priority 0  → Run Task Patrol
On Event "noise" → Set Variable instance.noise_at
```

Шум → Decide просыпается от события, Patrol отменяется («решение AI Graph:
вариант 1 важнее»), охранник идёт к шуму контроллером персонажа. Увидел игрока
— ChasePlayer прерывает расследование. Потерял — условие ложно, решение
возвращает к патрулю. Всё это — в истории отладчика с причинами. Целиком
пример проверяет `tests/test_ai_concept.cpp`.

Проверки: `tests/test_ai_graph.cpp` (документ, типы, выполнение, отладчик),
`tests/test_ai_graph_lua.cpp` (Lua-узлы и типы, граф ↔ Lua, узлы API, файл,
компонент AI, события), самопроверка редактора `ai-graph` и кадровая
`AI_GRAPH`.

## Visual Scripting

Общее визуальное программирование: графы задач ИИ (как задача выполняется) и

палитра: см. [visual_scripting.md](visual_scripting.md). Графы-функции общие
для обоих.

## Чего пока нет

- Встроенного навигационного меша: Find Path идёт по навигации проекта
  (`ai.path_finder`) или по прямой.
- Сохранения состояния задач в сейв: память экземпляра — обычные значения, их
  можно записать самому через `sage.save`.
