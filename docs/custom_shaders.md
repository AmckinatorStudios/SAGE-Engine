# Свои шейдеры в SAGE Engine

Материал (`.sagemat`) может нести собственную пару `.vert`/`.frag`. Такой
материал рисуется своей программой, но остаётся ПОЛНОЦЕННЫМ объектом сцены:
получает освещение, тени, GI, участвует в отсечении по фрустуму и — главное —
не теряет инстансный батчинг. Тысяча объектов со своим шейдером остаётся одним
draw call'ом; без этого своим шейдером нельзя было бы рисовать воду, траву или
листву, то есть ровно то, ради чего он обычно и нужен.

## Как подключить

```json
// assets/materials/water.sagemat
{
  "albedo": [0.05, 0.28, 0.42],
  "opacity": 0.72,
  "doubleSided": false,
  "vertexShader": "assets/shaders/water.vert",
  "fragmentShader": "assets/shaders/water.frag",
  "params": {
    "uWaveHeight": 0.35,
    "uFoamColor": [0.82, 0.94, 1.0]
  }
}
```

```lua
-- назначить материал сущности из скрипта
SetMaterial(entity, "assets/materials/water.sagemat")
-- правка юниформы МАТЕРИАЛА: видна всем, кто им покрашен, и НЕ ломает батчинг
SetMaterialParam("assets/materials/water.sagemat", "uFocus", Vec3(x, 0, z))
-- переопределить юниформу ДЛЯ ЭТОЙ сущности (материал общий, правка — штучная)
SetShaderParam(entity, "uWaveHeight", 0.6)
SetShaderParam(entity, "uFoamColor", Vec3(1.0, 0.9, 0.7))
ClearShaderParams(entity)
```

Цвет сущности МОДУЛИРУЕТ материал (`EffectiveColor`): `iColor` в шейдере — это
`albedo` материала, домноженный на то, что лежит в `obj.Color`. Белый цвет (по
умолчанию) даёт ровно albedo материала, поэтому «покрасить каждый объект
по-своему» при общем материале — законная операция: материал задаёт, из чего
предмет сделан, а цвет экземпляра — какого именно он оттенка.

Раньше материал цвет ЗАМЕЩАЛ, и это молчало: `obj.Color` из скрипта переставал
что-либо делать в тот момент, когда сущности назначали материал. Уже сделанные
сцены переводит миграция формата (v3→v4) — у сущности с материалом мёртвый цвет
заменяется нейтральным, так что вид не меняется.

Правка `.vert`/`.frag` подхватывается редактором на лету: `ReloadChangedShaders`
сверяет время правки файлов раз в кадр. Шейдер с ошибкой компиляции **не
заменяет** рабочий — в сцене остаётся прежняя версия, ошибка уходит в лог.

## Контракт вершинного шейдера

Локации атрибутов фиксированы движком (см. `render/Mesh.cpp`):

| Локация | Что | Частота |
|---|---|---|
| 0 | `vec3 aPos` | вершина |
| 1 | `vec3 aNormal` | вершина |
| 2 | `vec2 aUV` | вершина |
| 3 | `vec4 aTangent` (w — знак развёртки) | вершина |
| 11 | `vec2 aUV2` (лайтмапа GI) | вершина |
| 4…7 | `mat4` модельная матрица (четыре строки) | инстанс |
| 8 | `vec3 iColor` | инстанс |
| 9 | `float iMetallic` | инстанс |
| 10 | `float iRoughness` | инстанс |
| 12 | `float iAlpha` | инстанс |

Инстансные локации читать **обязательно**: объект приходит в шейдер через них,
а не через `uModel`. Минимальный вершинный шейдер:

```glsl
#version 330 core
layout (location = 0) in vec3 aPos;
layout (location = 1) in vec3 aNormal;
layout (location = 4) in vec4 iM0;
layout (location = 5) in vec4 iM1;
layout (location = 6) in vec4 iM2;
layout (location = 7) in vec4 iM3;
layout (location = 8) in vec3 iColor;
layout (location = 12) in float iAlpha;

uniform mat4 uView;
uniform mat4 uProjection;
uniform float uTime;

out vec3 FragPos; out vec3 Normal; out vec3 vColor; out float vAlpha;

void main() {
    mat4 model = mat4(iM0, iM1, iM2, iM3);
    vec4 world = model * vec4(aPos, 1.0);
    world.y += sin(world.x * 0.4 + uTime) * 0.15;   // своя волна
    FragPos = world.xyz;
    Normal  = transpose(inverse(mat3(model))) * aNormal;
    vColor  = iColor;
    vAlpha  = iAlpha;
    gl_Position = uProjection * uView * world;
}
```

## Стандартные юниформы

Движок заливает их сам перед отрисовкой группы — объявляй только те, что нужны.

| Юниформа | Смысл |
|---|---|
| `mat4 uView`, `mat4 uProjection` | камера кадра |
| `vec3 uViewPos` | позиция камеры (спекуляр, туман) |
| `float uTime` | время сцены в секундах (анимация) |
| `int uShadingMode` | 0 освещённый / 1 плоский / 2 нормали (режимы вьюпорта) |
| `vec3 uAlbedoFactor`, `float uMetallic`, `float uRoughness`, `float uOpacity` | поля материала |
| освещение, тени, GI | тот же блок, что у штатного шейдера — см. `render/PbrShader.h` |

Готовое PBR-освещение подключается одной строкой — вставь в свой `.frag`
содержимое `kPbrSharedGlsl` (движок делает так же) и зови
`ShadePBRgi(N, FragPos, albedo, metallic, roughness, ao, indirect)`.

## Прозрачность

`opacity` материала (или `MeshRenderer.Opacity` сущности) меньше 1 отправляет
объект в полупрозрачный проход: сортировка от дальних к ближним, блендинг
включён, запись глубины выключена. Возвращать альфу из шейдера нужно самому —
обычно `vAlpha` или `uOpacity`.

Свой шейдер прозрачности НЕ отменяет: группа с полупрозрачным материалом
рисуется в том же проходе и там же сортируется — но сортируется ВНУТРИ СЕБЯ,
инстанс за инстансом, и остаётся одним draw call'ом. Такие группы идут перед
остальным прозрачным: обычно это среда (вода, листва), на фоне которой стоит
всё прочее, а у группы, растянутой на всю сцену, нет одной глубины, по которой
её можно было бы вставить в общий порядок.

`doubleSided` (по умолчанию `true`) — рисовать ли задние грани. У листвы и
стекла-«плоскости» их видно, и отсечение превратило бы стакан в половину
стакана. А у ЗАМКНУТОГО тела (плитка воды, стеклянный ящик) двусторонняя
отрисовка означает два слоя смешивания на один объект: цвет темнеет вдвое, а
на стыках проступает сетка. Такому материалу ставят `false`.

Тень полупрозрачный объект отбрасывает, только если его непрозрачность ≥ 0.5:
карта теней бинарна и «половину тени» не умеет.

## Ограничения

* Один материал — одна программа; переключение шейдера на лету означает смену
  материала.
* Персональные юниформы сущности (`SetShaderParam`) ломают батчинг ЕЁ группы:
  группа с такими сущностями рисуется поштучно. Для тысяч объектов держи
  значения в материале.
* Персональные юниформы живут только в рантайме и не сохраняются в сцену —
  их выставляет скрипт. Параметры материала сохраняются.
* Объект со своим шейдером НЕ отбрасывает тень: карта глубины рисуется штатным
  шейдером и о твоей деформации вершин не знает — тень легла бы не там, где
  объект. Нужна тень — оставь геометрию на месте и меняй только цвет.
* Геометрические шейдеры и tessellation не поддерживаются.
