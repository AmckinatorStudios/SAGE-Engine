# Процедурные текстуры

Картинка, посчитанная формулой, вместо файла на диске.

## Зачем

Без текстур поверхность в кадре — ровная заливка. По ней плохо читается
освещение: нет ни масштаба (метр перед тобой или сто — непонятно), ни мелкой
формы, на которой виден блик. Обычный ответ — положить в проект файлы
картинок, но у него есть цена, которая на прототипе перевешивает пользу:
мегабайты в репозитории, лицензии на чужие изображения и невозможность
поменять размер клетки, не открывая редактор изображений.

Формула не стоит ничего на диске, читается как код, правится одним числом и
отдаёт любое разрешение. Это не замена художнику: это то, на чём стоит
прототип и на чём проверяется сам рендер — фильтрация, мипмапы, анизотропия,
нормал-маппинг.

Реализация — `engine/src/sage/render/TextureGen.h`; проверки —
`tests/test_texturegen.cpp`.

## Из Lua

```lua
local id = sage.texture.Generate("floor/albedo", {
    pattern = "checker",
    width = 1024,                      -- height = width, если не задан
    tilesX = 4, tilesY = 4,
    colorA = Vec3(0.82, 0.82, 0.84),
    colorB = Vec3(0.17, 0.18, 0.21),
    grain = 0.05,                      -- лёгкий шум поверх узора
})

local m = sage.render.NewMaterial("floor")
m.TexturePath = id
m.Roughness = 0.55
m.Render.UVScaleX = 26                 -- сколько раз уложить по ширине
m.Render.UVScaleY = 26
sage.render.ResolveMaterialTextures(m)  -- подтянуть карты по путям

sage.render.SetMaterial(obj, "floor")
```

`Generate` возвращает ИМЯ, под которым текстура легла в кэш ресурсов. Дальше
она ничем не отличается от загруженной с диска: её видит материал, она
участвует в мипмапах и фильтрации, её показывает редактор. Повторный вызов с
тем же именем ПЕРЕСЧИТЫВАЕТ картинку — ровно за этим его и зовут второй раз.

## Узоры

| `pattern`  | что рисует | чем задаётся |
|------------|------------|--------------|
| `solid`    | заливка `colorA` | — |
| `checker`  | шахматка | `tilesX`, `tilesY` |
| `grid`     | линии `colorB` по фону `colorA` | `tilesX/Y`, `lineWidth` |
| `bricks`   | кладка со смещением рядов | `tilesX/Y`, `lineWidth`, `offset` |
| `dots`     | точки/заклёпки по сетке | `tilesX/Y`, `lineWidth` (радиус) |
| `gradient` | переход A→B | `angle`, `radial` |
| `noise`    | фрактальный шум | `frequency`, `octaves`, `persistence`, `seed` |

Общие поля: `width`, `height`, `colorA`, `colorB`, `grain`, `seed`.

## Карта нормалей из того же описания

```lua
local n = sage.texture.Generate("floor/normal", {
    pattern = "grid", width = 1024, tilesX = 4, tilesY = 4,
    lineWidth = 0.035, normal = true, strength = 1.6,
})
m.NormalMapPath = n
```

`normal = true` считает узор ВЫСОТОЙ и отдаёт тангенциальную карту нормалей.
Смысл в том, что цвет и рельеф выходят из одного описания: шов на рельефе
всегда там же, где шов на картинке. Пара «цвет + нормаль», нарисованная
руками, расходится на первой же правке.

## Бесшовность

Все узоры сходятся по краям — иначе текстура, повторённая на полу пятьдесят
раз, дала бы сетку швов поверх рисунка. Ради этого:

* число клеток округляется до целого (половина клетки на краю — это и есть шов);
* у шахматки — до ЧЁТНОГО: соседние клетки обязаны отличаться, а при нечётном
  счёте последняя клетка ряда и первая клетка следующей укладки совпали бы по
  цвету;
* шум считается на периодической решётке, и период удваивается вместе с
  частотой октавы — иначе бесшовной осталась бы только первая октава.

## Повтор текстуры (`UVScale`)

Развёртка примитивов движка — 0..1 на грань, поэтому картинка на большом
объекте растягивается: пол в сто метров получил бы одну плитку. Повтор задаётся
материалом:

```lua
m.Render.UVScaleX = размерПолаВМетрах / размерКлеткиВМетрах / клетокВТекстуре
m.Render.UVScaleY = m.Render.UVScaleX
```

Два числа, а не одно: у стены 4 × 2.5 метра равный повтор по осям растянул бы
кладку. Поля сериализуются в `.sagemat` (`uvScaleX`, `uvScaleY`) и правятся в
инспекторе материала — в подразделе «Тайлинг» среди карт.

### Режим повтора (`tilingMode`)

| режим | ключ в файле | что значат числа |
|-------|--------------|------------------|
| Общий | `uniform` | одно число (`uvScaleX`) на обе оси |
| По осям | `separate` | ширина и высота отдельно (по умолчанию) |
| По размеру объекта | `worldSize` | **повторов на метр** двух больших сторон объекта |

**Зачем «по размеру объекта».** При постоянном повторе растяжение САМОГО
объекта растягивает и рисунок: тот же пол, растянутый с 5 до 50 метров, снова
показывает одну плитку на всю длину, и повтор приходится подбирать заново после
каждого изменения размера. В этом режиме повтор умножается на размеры объекта в
мире, и плитка остаётся одного физического размера, как бы объект ни
масштабировали. Берутся ДВА БОЛЬШИХ измерения: поверхность тянется вдоль них, а
третье — толщина пола или стены, к развёртке отношения не имеющая (у пола
`10 × 0.2 × 10` это X и Z, у стены `10 × 5 × 0.2` — X и Y; различать «пол» и
«стену» не приходится).

Считает это одна функция на весь движок — `TilingFactor`
(`sage/render/Material.h`): повтор подставляют три разных прохода отрисовки, и
разойтись им нельзя, иначе одна и та же стена показывала бы разный размер
плитки в зависимости от того, каким путём её нарисовали.

### Сдвиг развёртки (`uvOffsetX`, `uvOffsetY`)

Сдвиг **в плитках**, а не в долях грани: «на треть плитки правее» не должно
менять смысл при каждой смене повтора. Нужен затем же, зачем повтор: шов плитки
попадает ровно в середину стены, и подвинуть рисунок дешевле, чем переделывать
геометрию.

```lua
m.Render.TilingMode = "worldSize"   -- "uniform" | "separate" | "worldSize"
m.Render.UVScaleX = 0.5             -- пол-плитки на метр
m.Render.UVScaleY = 0.5
m.Render.UVOffsetX = 0.25
```

## Из C++

```cpp
#include "sage/render/TextureGen.h"

sage::render::TextureRecipe r;
r.Kind = sage::render::TextureRecipe::Pattern::Checker;
r.Width = r.Height = 1024;
r.TilesX = r.TilesY = 4.0f;
auto tex = sage::render::GenerateTexture(r);            // GPU-текстура
ResourceManager::Instance().RegisterTexture("floor", tex);
```

`GenerateTexturePixels(recipe)` отдаёт RGBA8 без графического контекста —
этим и проверяется генератор в тестах.

## Чего он не делает

* Не заменяет фотограмметрию и рисованные ассеты: узоров семь, и все они
  геометрические.
* Не считается на GPU: картинка строится на процессоре один раз при запуске.
  1024×1024 — это единицы миллисекунд; пересчитывать её каждый кадр нельзя.
* Не хранится на диске: сгенерированная текстура живёт в кэше ресурсов до
  конца работы и не участвует ни в вытеснении по бюджету VRAM, ни в сборке
  мусора — перечитать её было бы неоткуда.
