# Ошибки и проблемы

Как SAGE сообщает о том, что пошло не так, и как этим пользоваться.

## Коротко

- Каждое предупреждение и каждая ошибка движка — **проблема**: запись с
  уровнем серьёзности, местом (файл, строка, столбец, объект), объяснением,
  шагами исправления и, где возможно, **исправленным примером**.
- Одинаковые проблемы — одна запись со счётчиком «×N».
- Связанные — **одна группа**: сверху **первопричина**, под ней последствия.
  Чинить начинают с первопричины — последствия обычно уходят вместе с ней.
- Скрипт с ошибкой сборки **не запускается**. Скрипт, падающий раз за разом
  или зависший, останавливается **только на своём объекте** — остальные
  работают.
- Всё видно в редакторе: **Консоль → вкладка «Проблемы»**. Там же —
  **диагностический отчёт** одной кнопкой.

## Уровни

| уровень | что значит |
|---------|------------|
| Сведения | работает, но стоит знать |
| Предупреждение | работает не так, как задумано: взят запасной вариант |
| Ошибка | часть не работает: скрипт не запущен, ассет не загружен |
| Авария | движок не может продолжать: не создалось окно, падение |

## Вкладка «Проблемы»

Консоль редактора — две вкладки. **Журнал** — что происходило, строка за
строкой. **Проблемы** — что сломано и как починить. Число у вкладки — открытые
ошибки; щелчок по счётчику ошибок в статусной строке открывает её.

Над списком — уровни (значок и число, щелчок прячет или показывает), поиск (по
заголовку, файлу, объекту, без учёта регистра), **копировать отчёт** и меню
**⋯** (сохранить отчёт в файл, очистить список).

В списке у первопричины — метка **«первопричина · ещё N»**; стрелка слева
раскрывает последствия. Выбранная проблема показана ниже:

- **Где** — файл и строка (кнопка **Открыть** открывает файл на этой строке в
  выбранном редакторе кода), объект;
- **строки кода** вокруг ошибки, с отметкой строки и столбца;
- **Что случилось** — понятным языком;
- **Как исправить** — по шагу; «Возможно, имелось в виду…» при опечатке в
  имени;
- **Исправленный пример** — по возможности ВАША строка, исправленная, с
  кнопкой «Скопировать пример»;
- **Последствия** — что ещё сломалось из-за этой проблемы;
- **Технические подробности** — сырое сообщение и стек вызовов.

**Скопировать проблему** — всё это одним текстом, для чата или обращения.

## Пример: ошибка в `.slua`

```
local speed: number = "fast"
```

```
[Ошибка] Ошибка типа: Ожидалось значение number. Получено значение string. Переменная: speed …
Где: assets/scripts/door.slua:1:23
> 1 | local speed: number = "fast"
    |                       ^
Почему: Нужно число, а дана строка.
Как исправить:
  • Переведите строку в число: tonumber(text).
  • Или исправьте тип в объявлении.
  • Пока ошибка не исправлена, скрипт не запускается — объект работает без него…
Пример:
local speed: number = tonumber(text) or 0
```

Под ней — последствия: «Объект «Door» остался без скрипта», по одному на
каждый объект с этим файлом. Как только файл собрался (сохранили исправление —
горячая перезагрузка), ошибка сборки и её последствия **снимаются сами**.
Ошибки выполнения остаются в списке: они случились, и код мог их не исправить.

## Что объясняется

Ошибки Lua и SAGE Lua разбираются на части и переводятся:

- нет `then`/`do`/`end`, лишний `end`, незакрытая строка, `!=` вместо `~=`;
- вызов несуществующей функции или метода — с «возможно, имелось в виду»
  (ищется среди имён самого файла и хуков движка) и исправленной строкой;
- обращение к пустому значению (`nil`) — с примером проверки `if x then`;
- арифметика и склейка строк с `nil`, сравнение разных типов, неверный тип
  аргумента, бесконечная рекурсия;
- ошибки типов, аннотаций, импорта и вызова SAGE Lua.

Ошибки других подсистем (ассет не найден, материал или модель не загрузились,
шейдер не собрался) получают подсказку по известным случаям. Незнакомая ошибка
всё равно становится проблемой — просто без подсказки: **ничего не прячется**.

## Зависший скрипт

Бесконечный цикл в `Update` больше не вешает редактор. Вызов скрипта, который
длится дольше 8 секунд, прерывается ошибкой «вызов скрипта длится дольше…» —
с файлом и строкой цикла, — и скрипт этого объекта останавливается. Цена
проверки — одно сравнение времени на 20 000 инструкций Lua.

## Диагностический отчёт

Кнопка копирования на вкладке «Проблемы» кладёт в буфер отчёт в Markdown:
версия, система, проект, сцена и режим, все проблемы группами с подробностями,
последние строки журнала. Меню **⋯ → Сохранить** пишет его файлом
`sage-report-<дата>.md` в папку проекта.

**Личное вычищается**: домашняя папка заменяется на `~`, имя пользователя в
путях — на `<user>`. Отчёт уходит в чужие руки, а путь `C:\Users\Иван\…` — это
имя.

## Журналы

- **Консоль** — одна строка на проблему (`файл:строка: что случилось`).
- **Файл журнала** (`sage_editor.log`, `sage_player.log`) — та же строка и,
  один раз на проблему, полный разбор с отступом: причина, шаги, пример,
  стек. Журнал, который пришлют, объясняет сам.
- **Отчёт о падении** (`sage-crash-*.txt`) — дополнительно последние
  первопричины до падения.

## Для своего кода

```cpp
#include "sage/core/Problems.h"

sage::Problem p;
p.Level = sage::Severity::Error;
p.Category = "MyGame";
p.Code = "mygame.level";            // устойчивый вид проблемы
p.Title = "Уровень не загрузился";
p.File = "assets/levels/forest.json";
p.Detail = "В файле нет списка комнат.";
p.Hints = {"Добавьте массив \"rooms\" в корень файла."};
p.Example = "{ \"rooms\": [] }";
sage::Problems::Report(p);

// Исправили — снять:
sage::Problems::Resolve("assets/levels/forest.json", "mygame.");
```

Группировка — по полю `Resource` (по умолчанию — `File`): первая ошибка о
ресурсе — первопричина, следующие о нём же — её последствия. Последствие в
другом ресурсе называет причину в `CausedBy`; пришедшая позже причина
подбирает свои последствия. Обычный `LOG_WARN`/`LOG_ERROR` тоже становится
проблемой, а путь ассета из текста сообщения — её ресурсом.
