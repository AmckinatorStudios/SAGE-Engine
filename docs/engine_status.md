# Состояние движка: что серьёзно и что исправлять

Честный срез на 2026-10-25 (версия 0.5.0, путь к 1.0). Что уже закрыто —
в `CHANGELOG.md`; здесь то, что остаётся, по убыванию важности. У каждого
пункта — почему это проблема и что делать.

## Критично для игры

Три пункта прошлого среза закрыты (см. `CHANGELOG.md`, 2026-10-25, «захват
курсора в окнах панелей, запасной захват, повороты в анимациях»):
захват курсора получил программный запасной режим (`window.cursorLock`, Auto
переходит на него сам), панель Game отдельным окном получает ввод и захват,
повороты клипов свойств и твинов переводятся миграцией.

1. **Захват на настоящих Windows и macOS всё ещё не проверен руками** —
   пробы гоняются под xvfb. Если курсор гуляет и Auto не сработал (система не
   сбрасывает режим, а просто не держит курсор) — в Game Settings выбрать
   «Захват курсора: Программный». Что сделать: прогнать `01_fps_controller.lua`
   и облёт камеры в релизах `windows-latest` и `macos-latest`.
2. **Скрипты, складывающие углы по нескольким осям руками,** после смены
   соглашения об углах ведут себя иначе — их миграция не переводит (это код).
   Описано в `scripting.md`.

## Графика

Пункты прошлого среза закрыты (`CHANGELOG.md`, 2026-10-25, «графика из
статуса, нагрузка»): тонкий G-буфер и честный экранный GI, кластерный свет
(до 1024 ламп кадра) и площадные источники, glTF-модели заслоняют свет при
запекании, скелетные модели берут свет из проб, объёмный свет стабилен и
вернулся в Game Settings, кадровые проверки умеют режим свойств для прогона на
видеокарте.

4. **Кадровые проверки на видеокарте ждут раннера.** Работа
   `.github/workflows/render-gpu.yml` готова (каждую ночь, режим свойств), но у
   бесплатных раннеров GitHub видеокарты нет. **Сделать:** зарегистрировать
   свой компьютер с видеокартой как self-hosted runner (или взять GPU-раннер
   GitHub) и записать его метку в переменную репозитория `SAGE_GPU_RUNNER`.
5. **Площадной источник не отбрасывает тени** и не участвует в запекании GI.
   Рассеянный свет считается точно (форм-фактор), блик — приближением
   «представительной точкой». **Сделать (после 1.0):** тень площадного —
   несколько выборок карты прожектора по панели.
6. **SSR и деферред-свет** — G-буфер для них уже есть (альбедо, нормаль), но
   самих проходов нет: отражения — кубы зондов и плоское зеркало.

## Платформы

7. **Vulkan не закончен, DirectX нет** — игра идёт на OpenGL 3.3. RHI к второму
   бэкенду готов, но ни один не реализован полностью.
8. **macOS собирается только в CI** — локально её не проверить, а у раннера
   macOS GitHub нет OpenGL, так что самопроверка с окном там не идёт.
   **Сделать:** тот же self-hosted раннер (Mac с видеокартой) для
   `render-gpu.yml`.

## Устройство кода

9. **Нарушения слоёв в базе: `assets → render` (7 включений) и
    `assets → anim` (1).** Импорт ресурсов знает о рендере. **Сделать:** перенести
    в `assets` интерфейсы, которые ему нужны, реализацию — в `render`
    (см. «Слои движка» в `architecture.md`).
10. **Крупные файлы движка:** `PostFX.cpp` (~2500 строк, все звенья пост-обработки
    в одном файле), `SageCheck.cpp` (~2250), `SceneSerializer.cpp` (~1700),
    `UIParts.cpp` (~1650), `SkinnedModel.cpp` (~1600). Лимит 1000 строк сейчас
    действует только для редактора; в базе редактора один файл —
    `ViewportPanel.cpp`. **Сделать:** разнести звенья PostFX по файлам по их
    этапу, сериализатор — по системам (как уже сделан реестр компонентов).
11. **Кастомные компоненты игр без реестра не сохраняются в `.sage`.** Реестр
    компонентов есть, но старые игры (`games/testgame`) сериализуют своё сами.

## Что уже держится (чтобы не чинить заново)

Соглашения, которые проверяются автоматически и не должны откатываться:
базовый вывод кадра камеры без обработки (`FramePostChain`), гамма при любом
выводе, наклон Эйлера вокруг своей оси, вертикальное тело персонажа, возврат
захвата курсора (и в окне панели), программный захват, раскладка данных моделей по общим папкам, развёртка лайтмап,
G-буфер для экранного GI, кластерный свет (все лампы горят), форм-фактор
площадного источника, glTF в запекании, пробы на скелетных моделях, история
объёма на каждое окно, лимит кадров в фоне и в простое.
Список проверок — в разделах `rendering.md`, `scripting.md`, `assets.md`.
