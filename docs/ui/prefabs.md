# Префабы

## Зачем

Слот инвентаря, карточка, строка списка, всплывающая подсказка повторяются
десятками. Копия каждого — гарантия, что через неделю они перестанут быть
одинаковыми.

## Как устроено

Экземпляр помнит источник (файл `.uiprefab`) и **список своих отличий**:

```cpp
UINodeId inst = UIInstantiatePrefab(doc, parent, "assets/ui/Card.uiprefab");
// …правим экземпляр…
UICapturePrefabOverrides(doc, inst);        // запомнить отличия
UIRefreshPrefabInstances(doc, path);        // обновить из источника
```

Обновление источника переносится во все экземпляры, а отличия остаются. Без
списка отличий обновление префаба стирало бы ручную работу — и им перестают
пользоваться.

## Почему отличия считаются сравнением

`UICapturePrefabOverrides` сравнивает экземпляр с исходником, а не запоминает
правки по ходу дела. Запоминание правок промахивается на любом действии мимо
редактора (отмена, скрипт, миграция), а сравнение всегда честно.

## Вложенность

Экземпляр префаба внутри другого префаба — обычный случай (кнопка со значком
внутри карточки). Ничего особенного для этого не нужно: отличия адресуются
путём внутри экземпляра (`"Title.text.Text"`), то есть относительно, а не
абсолютно. Поэтому они переживают переименование самого экземпляра.

## Пропавший источник

Экземпляр не исчезает и не молчит: остаётся узел-заглушка с сохранённой ссылкой
и предупреждением в логе. Иначе поправить путь потом просто не по чему.

## Разрыв связи

`UIUnpackPrefab` превращает экземпляр в обычное поддерево.
