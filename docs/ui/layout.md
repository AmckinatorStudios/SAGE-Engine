# Раскладка

## Два прохода

Раскладку считает `UILayoutSolver`, и делает это в два прохода:

1. **измерение** снизу вверх — сколько места нужно тексту, картинке,
   содержимому контейнера;
2. **расстановка** сверху вниз — где стоит каждый узел.

Иначе «панель по размеру содержимого внутри строки, которая сама по размеру
содержимого» не считается вовсе.

Результат — плоский массив `UIResolvedNode` в **экранных пикселях**. На него
смотрят все: рисование, ввод, редактор, отладка, тесты.

## Якоря

Два якоря — `AnchorMin` и `AnchorMax` — задают в долях родителя область, к
которой узел привязан.

* якоря **совпали** — это точка: узел стоит рядом с ней со смещением `Offset` и
  не тянется;
* якоря **разошлись** — это область: узел растягивается по ней с полями
  `Margin`.

Девять «стандартных» якорей — частные случаи, а не отдельный механизм:

| Якорь | AnchorMin = AnchorMax |
|---|---|
| TopLeft | (0, 0) |
| TopCenter | (0.5, 0) |
| BottomRight | (1, 1) |
| произвольный | (0.25, 0.75) — тоже законен |

Прежний `UIAnchor` умел ровно девять точек, и «панель, приклеенная к правой
трети экрана» не выражалась никак.

`SetAnchorPoint(UIAnchor::BottomRight)` — сахар поверх долей; заодно двигает
`Pivot`, иначе «прижать к правому краю» означало бы «поставить левый край узла
на правый край родителя», то есть выкинуть узел за экран.

## Pivot

`Pivot` — точка САМОГО УЗЛА, которая попадает на якорь и вокруг которой идут
поворот и масштаб. `(0,0)` — левый верхний угол, `(0.5,0.5)` — центр.

Именно так, а не «сдвиг на долю размера»: подпись, растущая от середины, при
`Pivot = 0.5` остаётся на месте, а не уезжает.

## Размеры

`WidthMode` и `HeightMode` — независимо по осям:

| Режим | Что значит |
|---|---|
| `Fixed` | ровно `Size` |
| `Percent` | доля стороны родителя (`Percent`, в процентах) |
| `Content` | столько, сколько занимает содержимое |
| `Stretch` | от `AnchorMin` до `AnchorMax` минус `Margin` |

Плюс ограничения, применяемые в фиксированном порядке:

```
режим → Min/Max → соотношение сторон → Min/Max ещё раз
```

Порядок именно такой и записан один раз в `UIResolveTransform`: иначе
«ширина 50% и соотношение 16:9» дают разный ответ в зависимости от того, кто
считает.

`MinSize`/`MaxSize`: ноль означает «не ограничено». Отдельного флага не нужно, а
«максимальная ширина ноль» не значит ничего осмысленного.

## Контейнеры

Узел с компонентом `UILayout` сам расставляет своих детей.

| Режим | Что делает |
|---|---|
| `None` | дети по своим якорям |
| `Horizontal` / `Vertical` | ряд и столбец |
| `Grid` | сетка с фиксированным числом столбцов |
| `Wrap` | ряд с переносом |
| `Overlay` | все дети занимают весь контейнер |
| `Center` | все дети по центру, размеры свои |
| `Stack` | со сдвигом каждого следующего |
| `Aspect` | вписать по соотношению сторон |

Плюс `Padding`, `Gap`, выравнивание вдоль основной и поперечной осей
(`Start`, `Center`, `End`, `Stretch`, `SpaceBetween`, `SpaceAround`,
`SpaceEvenly`), `Columns`, `CellSize`, `Reverse`.

Дети, у которых по основной оси стоит `Stretch`, делят между собой **остаток**
места, а не весь контейнер: иначе фиксированные соседи выдавливаются за край.

`FitWidth` / `FitHeight` — контейнер подгоняет собственный размер под
содержимое. Работает вместе с `UISizeMode::Content` у соответствующей оси
`UITransform`: флаг здесь означает «контейнер умеет посчитать своё содержимое»,
режим там — «этой осью пользуйся».

Ребёнок с `UITransform::IgnoreLayout` не участвует в раскладке родителя и стоит
по своим якорям — значок поверх строки списка не должен ломать её расстановку.

## Опорное разрешение

Вёрстка идёт в **логических единицах**, наружу отдаются **пиксели**.

```cpp
canvas.Scale = UICanvasSettings::ScaleMode::ScaleWithSize;
canvas.Reference = {1920.0f, 1080.0f};
canvas.MatchWidthOrHeight = 0.5f;   // 0 — за шириной, 1 — за высотой
```

Множитель считает `UIDocument::ScaleFor`. При `Expand` берётся геометрическое
среднее двух множителей, а не арифметическое: масштабы перемножаются, и среднее
между «вдвое шире» и «вдвое уже» обязано давать единицу.

`AspectMode`: `Expand` (смешать), `Fit` (вписать целиком, меньший множитель),
`Crop` (заполнить, больший).

`SafeArea` — вырезы и системные панели; задаётся в пикселях экрана (их сообщает
система), переводится в логические единицы один раз, в `ViewportFor`.

`UserScale` — множитель «размер интерфейса» из настроек игры: точка входа для
доступности.

## Обратная задача

Редактор тянет прямоугольник мышью, а записать обязан `Offset`:

```cpp
t.Offset = UIOffsetForTopLeft(t, wantTopLeft, size, parentRect);
```

Это точный обратный ход к `UIResolveTransform`. Складывать дельту с `Offset`
напрямую нельзя: у якорей справа и снизу область якорей смещена, и «подвинуть на
десять пикселей» перестаёт быть «прибавить десять».
