# Рисование

## Граница

Бэкенд не видит ни узлов, ни компонентов, ни дерева. Он получает плоский список
команд.

```
UIDocument → UILayoutSolver → UIDrawBuilder → UIRenderList → IUIDrawBackend → GPU
```

Из этого следуют три вещи, ради которых всё и затевалось:

* интерфейс можно нарисовать другим бэкендом (другой API, снимок в файл,
  отладочный вывод), не трогая ни строки логики интерфейса;
* команды можно сортировать и объединять, ничего не зная о том, откуда они
  взялись;
* отрисовку можно проверить тестом, сравнивая СПИСОК КОМАНД, а не картинку.

## Команда

`UIRenderCommand` описывает **фигуру**, а не «элемент». Кнопка не превращается в
«команду кнопки»: она превращается в скруглённый прямоугольник, текст и, если
надо, тень — то же самое, во что превращается любая другая композиция с тем же
оформлением.

Виды: `Rect`, `Border`, `Image`, `NineSlice`, `Glyphs`, `Polygon`, `Ring`,
`Line`, `Custom`.

Каждая команда несёт своё состояние: прямоугольник, преобразование, радиусы,
цвет, градиент, текстуру, UV, мягкость края, режим наложения, состояние маски,
материал и ключ сортировки.

## Батчи

`UIRenderList::Build` склеивает подряд идущие команды с одинаковым состоянием.
Команды при этом **не переставляются**: порядок задан ключом сортировки, а
перестановка ради батчинга ломала бы прозрачность.

Батч рвут ровно те вещи, которые меняют состояние GPU:

* другая текстура изображения;
* другой режим наложения;
* другое состояние маски или другие ножницы;
* другой материал;
* смена цели рисования.

Текст и сплошные фигуры батч **не рвут**: и глифы, и заливки идут через один и
тот же шейдер интерфейса (глиф берёт покрытие из атласа шрифта, заливка не
сэмплирует ничего). Разрыв здесь означал бы отдельный вызов рисования на каждую
подпись — а подпись есть почти у каждого элемента, и именно из них и набегала бы
«сотня draw call на сотню элементов».

Для витрины из 87 видимых узлов это 104 команды и 19 батчей.

## Бэкенды

`UIClassicBackend` — поверх штатного `UIRenderer` движка. Там, где его
возможности уступают модели команд (разные радиусы у четырёх углов, мягкий край
произвольной ширины), это явно отмечено в коде: система не делает вид, что
нарисовала то, чего нарисовать не смогла. Данные при этом не теряются — они в
команде, и бэкенд со своим шейдером нарисует всё.

Свой бэкенд — это один класс:

```cpp
class MyBackend : public sage::ui::IUIDrawBackend {
    void Begin(glm::vec2 screenPixels) override;
    void Submit(const UIRenderList& list) override;
    void End() override;
};
```

## Промежуточные цели

Узел, которому нужен эффект уровня `Offscreen` (размытие), обрамляется в списке
команд операциями `BeginOffscreen` / `EndOffscreen`. Бэкенд, который их не
поддерживает, честно рисует поддерево без эффекта: интерфейс остаётся рабочим.

Число целей и проходов эффектов видно в `UIRenderStats` — см.
[performance.md](performance.md).

## Свои материалы

`UIMaterialRef` — имя шейдера, до четырёх текстур и до четырёх векторов
параметров. Ядро интерфейса не знает, что внутри шейдера, и не должно: его дело
донести имя и параметры до бэкенда.
