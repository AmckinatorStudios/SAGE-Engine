# Стоимость и производительность

## Нулевая стоимость неиспользуемого

Простой узел не платит за то, чего у него нет:

| Нет компонента | Не платится |
|---|---|
| `UIMask` | ни ножниц, ни записи в стеке масок, ни ветки в шейдере |
| `UIEffects` | ни прохода, ни промежуточной цели |
| `UILayout` | дети позиционируются якорями за один проход |
| `UIInteraction` | узел не участвует в поиске попадания вовсе |
| `UIText` | нет прохода раскладки текста |

Это проверяется тестом: узел с одной заливкой даёт ровно одну команду
рисования, ноль целей и ноль проходов эффектов.

## Явная стоимость сложного

Включил размытие — система честно делает промежуточную цель и проход, и это
видно в профайлере. Включил маску по картинке — она уходит в шейдер. Ничего не
включил — ничего и не происходит.

## Отсечение

Из подготовки выпадают:

* выключенные узлы (вместе с поддеревом);
* невидимые;
* полностью прозрачные;
* целиком за краем экрана;
* целиком за областью маски.

## Грязные флаги

Документ помечает, что именно изменилось. Смена цвета текста не поднимает флаг
раскладки. См. [nodes.md](nodes.md).

## Профайлер

```cpp
const UIProfile& p = ui.Profile();
p.Layout.Nodes / Visible / Culled / MeasurePasses / LayoutMs
p.Render.Commands / Batches / Quads / Glyphs
p.Render.MaskPasses / EffectPasses / RenderTargets / PrepareMs
p.InputMs / p.TotalMs
p.Summary();       // одной строкой
```

Разработчик, включивший размытие на десяти панелях, обязан **увидеть** десять
проходов, а не гадать, почему стало медленно.

## Отладочные слои

```cpp
ctx.Debug = UIDebug_Bounds | UIDebug_Anchors | UIDebug_Masks | UIDebug_Batches;
```

Границы, якоря, опорные точки, маски, области обрезки, области попадания,
слои, границы батчей. Дорисовываются в тот же список команд — то есть тем же
конвейером, а не «поверх, как получится».

## Четыре вопроса

Система обязана отвечать на них конкретной цепочкой, а не «ну как-то так»:

```cpp
UIExplainPosition(doc, layout, id);    // откуда взялось положение
UIExplainVisibility(doc, layout, id);  // почему его не видно
UIExplainOrder(doc, layout, id);       // почему он выше другого
UIExplainEffects(doc, id);             // откуда взялась тень
UIDumpTree(doc, &layout);              // дерево текстом
```

Ответы текстом, потому что читает их человек. В редакторе они лежат в разделе
«Почему так?» инспектора.

## Проверки целостности

`UIValidate(doc)` ловит то, что реально ломается: цикл в иерархии, ссылку на
несуществующего родителя, узел без прямоугольника, повторяющийся guid, маску по
картинке без картинки, экземпляр префаба без источника.

## Основа для многопоточности

Раскладка, измерение текста и подготовка команд не трогают GPU и работают с
данными документа. Разделение сделано так, чтобы их можно было унести с
основного потока, не переписывая модель. Сейчас всё считается синхронно —
архитектура этого не запрещает, но и не делает вид, что уже умеет.

## Основа для виртуализации

`UIScrollView` знает размер содержимого, окно и смещение, и считает, какие
элементы попадают в окно (`FirstVisible`, `VisibleCount`). Сам виртуальный
список — задача поверх, но окно ему считает прокрутка, и десять тысяч элементов
не обязаны становиться десятью тысячами узлов.
