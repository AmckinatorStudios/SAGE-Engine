# Текст

## Почему это подсистема, а не `DrawText()`

Раньше текст был строкой и масштабом: рисующий сам решал, где её начать. Не было
ни переноса по словам, ни многоточия, ни ограничения на число строк, ни
автоподбора кегля, ни выравнивания по базовой линии, ни запасного шрифта, ни
оформленных кусков внутри строки.

Каждая из этих вещей — не украшение. Без переноса длинная реплика уезжает за
край панели. Без многоточия имя предмета налезает на цену. Без запасного шрифта
пользователь видит ряды прямоугольников.

## Проход раскладки

`UILayoutText` — чистая функция: строка + настройки + метрики шрифта → готовые
строки с позициями глифов. Без GPU и без дерева, поэтому проверяется
модульными тестами целиком.

```cpp
UITextLayoutResult r = UILayoutText(ctx, text, maxWidth, maxHeight);
r.Glyphs;      // позиции глифов, шрифт каждого, смещение в байтах
r.Lines;       // строки: диапазон глифов, ширина, базовая линия
r.Size;        // сколько места занял текст
r.FontSize;    // фактический кегль (мог быть подобран)
r.Truncated;   // что-то не поместилось
```

Одна и та же раскладка отвечает и на «сколько места займёт текст» (для подгонки
по содержимому), и на «куда поставить каретку» (для поля ввода), и на «что
нарисовать».

## Настройки

```cpp
UIText& t = node.Ensure<UIText>();
t.Text = "Привет";
t.Key = "menu.play";                 // ключ перевода; Text остаётся запасным
t.Font = "assets/fonts/game.ttf";
t.Size = 18.0f;
t.Align = UITextAlign::Center;       // Left | Center | Right | Justify
t.VAlign = UITextVAlign::Center;     // Top | Center | Bottom | Baseline
t.Wrap = UITextWrap::Word;           // None | Word | Character
t.Overflow = UITextOverflow::Ellipsis;
t.MaxLines = 2;
t.LetterSpacing = 0.0f;
t.LineSpacing = 1.2f;
t.AutoSize = true; t.MinSize = 10.0f; t.MaxSize = 40.0f;
t.OutlineWidth = 2.0f;
t.ShadowOffset = {0.0f, 2.0f};
```

## Как это себя ведёт

**Перенос по словам.** Слово, которое не влезает целиком, режется по символам —
иначе одно длинное слово уезжает за край, то есть ровно то, от чего перенос и
спасает. Ведущие пробелы новой строки не считаются, иначе абзац «дышит» слева на
случайную величину.

**Многоточие.** Место под него освобождается справа, откусывая уже выложенные
глифы: иначе многоточие само не влезает.

**Предел строк** считается и по `MaxLines`, и по доступной высоте.

**Автоподбор кегля** — двоичным поиском, а не шагом по единице: шаг по единице
на кегле 96 — это девяносто раскладок на кадр. Мерится при этом ПОЛНЫЙ текст, а
не обрезанный: при `Clip`/`Ellipsis` раскладка выбрасывает то, что не влезло,
ширина всегда «помещается», и подбор сходится к максимуму, ничего не подобрав.

**Выравнивание по ширине** (`Justify`) не растягивает последнюю строку абзаца.

**Запасной шрифт.** Символ, которого нет в основном шрифте, берётся из
запасного. Один отсутствующий символ не должен превращать строку в ряд
прямоугольников.

**Локализация.** Если задан `Key`, он разрешается через `UIContext::Localize`.
Нет словаря — остаётся `Text`, а не сырой ключ на экране: в редакторе и на
раннем этапе интерфейс обязан оставаться читаемым.

## UTF-8

`UIUtf8Next`, `UIUtf8Prev`, `UIUtf8Length`, `UIUtf8Append` — свой разбор, а не
`std::codecvt` (устарел, тянет локали, ведёт себя по-разному на платформах).
Каретка поля ввода двигается по СИМВОЛАМ, предел длины считается в символах:
иначе русское имя обрезается вдвое раньше английского, а Backspace рвёт букву
пополам.
