# Архитектура

## Что было не так с прежней системой

Прежний игровой интерфейс был **immediate-mode**: каждый кадр игра заново
описывала его вызовами рисования.

```cpp
ui.Begin();
ui.Rect(...);
ui.Text(...);
ui.End();
```

«Элемент» в такой системе существует ровно столько, сколько длится вызов. Из
этого следует всё остальное, и следует неизбежно:

* нельзя спросить «где сейчас эта кнопка» — она нигде, пока её не нарисуют;
* нельзя поймать по ней мышь, не повторив всю раскладку второй раз;
* нельзя проверить вёрстку тестом: тест увидит только последовательность
  вызовов рисования;
* нельзя отредактировать интерфейс иначе как правкой кода;
* редактор вынужден считать прямоугольники своей копией формул — и она
  неизбежно расходится с настоящей.

## Что здесь

**Retained-mode документ**: дерево узлов, которое живёт само по себе, и четыре
независимых прохода над ним.

```
UIDocument            дерево узлов и компонентов — ДАННЫЕ
    │
UILayoutSolver        где всё стоит                — считает, не рисует
    │
UIDrawBuilder         во что это превращается      — команды, не GPU
    │
IUIDrawBackend        кто это рисует               — GPU, не знает про узлы

UIInputRouter         ввод → события интерфейса    — не игровые действия
UITheme / UIStyle     оформление отдельно от структуры
UISerializer          документ ↔ файл
```

Уровни не смешаны, и это главное свойство системы:

* **раскладка отделена от рисования.** Один проход превращает документ в
  плоский массив посчитанных узлов (`UIResolvedNode`). Дальше на него смотрят
  ВСЕ: рисование, попадание курсором, редактор, отладка, тесты. Разойтись им
  негде;
* **рисование отделено от GPU.** Проход подготовки выдаёт список команд
  (`UIRenderCommand`). Бэкенд получает список и не видит ни узлов, ни дерева.
  Заменить бэкенд — значит написать один класс, не трогая ничего больше;
* **ввод отделён от игровой логики.** Мышь превращается в события интерфейса, и
  на этом всё;
* **редактор отделён от рантайма — но правит тот же документ.**

## Почему компоненты, а не типы элементов

Узел не бывает «кнопкой» или «картинкой». Узел бывает узлом, к которому
приложены компоненты:

```
картинка = Transform + Image
надпись  = Transform + Text
кнопка   = Transform + Fill + Interaction + (узел с Text внутри)
панель   = Transform + Fill + Layout + Mask
```

Альтернатива — перечисление видов элементов и один большой компонент со всеми
возможными полями — плоха ровно двумя вещами. Во-первых, у надписи всё равно
оказываются скругление, рамка и девятина: поля лежат в памяти, показываются в
инспекторе и сохраняются в файл, ничего при этом не значая. Во-вторых, каждый
новый вид элемента — это новое значение в перечислении, новая ветка в
отрисовке, новые строки в сериализаторе и новый пункт в инспекторе, то есть
правка четырёх мест сразу.

Здесь свой компонент — это одна структура, одна таблица свойств и одна
регистрация. Всё остальное (сохранение, чтение, инспектор, копирование,
анимация свойств) он получает даром. Подробности — в [extending.md](extending.md).

## Почему таблицы свойств

О полях компонента должны знать четверо: запись в файл, чтение из файла,
инспектор редактора и адресация свойств для анимации. Написанные руками, эти
четыре списка расходятся — вопрос только в том, когда. Свойство, добавленное в
структуру и забытое в сериализаторе, молча теряется при сохранении; забытое в
инспекторе — не существует для человека вовсе.

Поэтому список ровно один — `UIComponentType::Props`, и все четверо читают его.
Забыть свойство нельзя: оно либо есть в таблице (и тогда есть везде), либо его
нет нигде.

## Порядок кадра

```cpp
ui.Update(dt);            // 1. поведение виджетов → стили → раскладка
ui.HandleInput(frame);    // 2. ввод → события → состояния → стили состояний
ui.Render(backend);       // 3. команды → батчи → GPU
```

Порядок фиксирован и объясним. Поведение виджетов может изменить размеры (текст
в поле ввода), стиль может изменить оформление, и только после этого имеет смысл
считать раскладку. Ввод идёт по уже посчитанной раскладке — иначе «кликается не
то, что видно». Рисование идёт последним и ничего не меняет.
