# Маски

## Почему прямоугольного clip недостаточно

Прямоугольные ножницы умеют ровно одно: отрезать по осям. Ими нельзя сделать ни
круглый аватар, ни список со скруглёнными углами, ни виньетку, ни мягкое
затухание списка у края, ни фигурную рамку.

Всё это приходилось изображать картинками, положенными **поверх** содержимого,
то есть врать: под «дыркой» продолжало лежать содержимое, и оно ловило мышь.

## Маска — это значение

Ответ маски в точке — число `0..1`, а не «видно/не видно». Отсюда мягкие края,
растворение и градиентные маски получаются бесплатно, одним и тем же кодом.

```cpp
UIMask& m = node.Ensure<UIMask>();
m.Form = UIMask::Shape::RoundedRect;  // Rect | RoundedRect | Ellipse | Texture | Gradient
m.Radius = UICorners(12.0f);
m.Softness = 8.0f;                    // ширина мягкого края в пикселях
m.Invert = false;
m.Padding = UIEdges::Uniform(4.0f);   // сжать окно маски
```

Маска действует на **всё поддерево**, а не на сам узел: панель с маской рисует
свою подложку целиком и режет содержимое.

## Композиция

Маска складывается с масками предков по заданному режиму:

| Режим | Результат |
|---|---|
| `Intersect` | общее (по умолчанию и чаще всего) |
| `Replace` | забыть маску предков — всплывающее окно внутри списка |
| `Subtract` | вычесть — «дырка» в маске предков |
| `Add` | объединить |
| `Multiply` | перемножить значения — мягкое затемнение |

Композиция — тоже данные, а не зашитое «И».

## Как это устроено внутри

Цепочка масок над узлом превращается в запись в `UIMaskStack`, а узел ссылается
на неё номером. Так вложенные маски не заставляют рисующего подниматься по
дереву, а одинаковые состояния маски естественно попадают в один батч.

Дальше маска идёт одним из двух путей:

* **ножницы** — прямоугольная маска без мягкости и без инверсии. Один вызов GPU,
  ничего больше;
* **шейдер** — всё остальное: скругления, эллипс, мягкий край, инверсия, альфа
  картинки, градиентное затухание. Маска здесь — СОСТОЯНИЕ сегмента, а не
  свойство вершины: она уходит парой uniform'ов и не меняет формат вершины.
  Поэтому узел без маски не платит за неё ничем — в шейдер уходит ноль, и ветка
  не исполняется. Область при этом всё равно сужается ножницами по охватывающему
  прямоугольнику: шейдеру достаётся меньше пикселей.

Одинаковая маска у ста строк списка — один объект, поэтому она не рвёт батч на
каждой строке.

**Ограничение, о котором честно.** В шейдер уходит ОДНА фигурная маска — самая
внутренняя из тех, что не выражаются ножницами. Несколько наложенных
непрямоугольных масок требуют либо нескольких проходов, либо промежуточной цели;
здесь берётся та, что ближе к содержимому, — та, которую человек и имел в виду,
ставя её. Прямоугольные вклады при этом складываются все: они в ножницах.

## Маска и попадание курсором

`UIMaskStack::Sample` — общий ответ и для рисования, и для попадания. Одна
функция на двоих ровно затем, чтобы «видно» и «кликается» не могли разойтись.
Клик по невидимому куску списка — самая частая жалоба на маски, которых нет.

`UIMask::AffectsHitTest` позволяет отключить это поведение точечно.

## Альфа картинки и попадание курсором

Значение альфы текстурной маски известно только на GPU. На стороне процессора
(попадание курсором, тесты) маска по картинке считается своим прямоугольником:
врать «здесь дырка» без пикселей нельзя, а отказываться от попадания вовсе —
значит сломать клики по фигурным кнопкам. Скруглённые, эллиптические,
градиентные и мягкие маски считаются точно — той же формулой, что в шейдере.
