# Узлы, компоненты, документ

## Узел

`UINode` — место в дереве со своими свойствами плюс набор компонентов.

```cpp
UINodeId Id;          // номер внутри документа: быстрый, живёт до удаления
std::string Guid;     // строка: переживает сохранение, копирование, слияние
std::string Name;

bool Enabled;         // выключенный не участвует ни в чём, вместе с детьми
bool Visible;         // невидимый не рисуется
float Opacity;        // умножается на прозрачность предков
UIBlendMode Blend;

int Layer, Order;     // порядок отрисовки, см. layers.md
bool Locked, EditorHidden;   // пометки редактора — свойства содержимого

UINodeId Parent;
std::vector<UINodeId> Children;
std::vector<std::unique_ptr<UIComponent>> Components;
```

Собственные свойства узла — именно эти и только эти, потому что каждое из них
**наследуется поддеревом или управляет им**. Всё остальное принадлежит
компоненту: цвет — заливке, шрифт — тексту, радиус — форме.

Два идентификатора нужны оба. `Id` — рантайм: быстрый поиск, ссылки внутри
кадра. `Guid` — то, по чему на узел ссылаются префабы, анимации и внешние
привязки; он переживает пересохранение файла.

## Компоненты

```cpp
UINode& n = *doc.Create("Panel");
n.Ensure<UIFill>().Color = UIColorFromHex("#1A1D25");
n.Ensure<UILayout>().Kind = UILayout::Mode::Vertical;

if (UIText* t = n.Get<UIText>()) t->Size = 20.0f;
n.Remove<UIBorder>();
```

`Ensure<T>()` — основной способ собирать интерфейс кодом: добавляет компонент,
если его нет, и возвращает ссылку.

Компонент нельзя снять, если он помечен `Essential` — таков `UITransform`: узел
без прямоугольника негде рисовать, и это правило самой модели, а не «редактор
такой не показывает».

Компоненты внутри узла рисуются по `UIComponentType::Order`: тень 0, подложка
10, картинка 20, форма 25, шкала 30, значок 50, текст 60, рамка 80. Шаг в
десять — чтобы чужой компонент мог встать между своими, не переписывая чужие
числа.

**Компоненты не знают друг о друге.** Каждый описывает себя в прямоугольнике
своего узла и не двигает соседей. Отсюда правило композиции: нужен значок слева
от текста — это не «поле значка внутри текста», а два УЗЛА в контейнере с
раскладкой.

## Документ

`UIDocument` владеет узлами и иерархией. Наружу отдаются указатели и номера:
указатель живёт до удаления узла, номер — всегда (по нему всегда можно
спросить, существует ли узел).

```cpp
UINode* Create(name, parent);        // новый узел (сразу с UITransform)
UINodeId CreateWidget("button", p);  // готовый виджет из реестра
UINode* Find(id) / FindByGuid / FindByName / FindByPath("Root/Panel/Title");
void Destroy(id);                    // вместе с поддеревом
UINodeId Duplicate(id, newParent);   // глубокая копия, включая чужие компоненты
bool Reparent(id, newParent, index); // false, если получился бы цикл
bool Move(id, index);                // сменить место среди соседей
```

`Reparent` **отказывается** перенести узел внутрь собственного поддерева. Это не
придирка: цикл в иерархии — бесконечный обход при первой же отрисовке. Отказ, а
не молчаливое исправление, потому что иначе перетаскивание в редакторе делает
не то, что просили, и человек не понимает, почему.

`Duplicate` копирует все компоненты через `Clone()`, включая те, о которых движок
ничего не знает. Списка «что копировать» здесь нет по устройству — значит, он не
может устареть.

## Грязные флаги

Документ помечает, что именно изменилось, а не «изменилось хоть что-то»:

```
UIDirty_Layout | UIDirty_Transform | UIDirty_Visual | UIDirty_Text
UIDirty_Mask   | UIDirty_Effect    | UIDirty_Hierarchy | UIDirty_Style
```

Смена цвета текста не обязана пересчитывать раскладку всей сцены. Помечает сам
документ, а не тот, кто правит: иначе про пометку рано или поздно забудут.
