# Оформление

Визуальные компоненты не знают, что они «подложка кнопки» или «фон панели». Они
закрашивают прямоугольник своего узла тем, что в них задано, и складываются
слоями по `Order`.

## UIFill — заливка

```cpp
UIFill& f = node.Ensure<UIFill>();
f.Type = UIFill::Kind::Gradient;      // Solid | Gradient | Texture
f.Color = UIColorFromHex("#1A1D25E6");
f.Radius = UICorners(12, 4, 20, 0);   // TL, TR, BR, BL — независимо
f.Softness = 0.0f;                    // мягкий край, если нужен
```

Скругления живут здесь, а не у узла: у одного узла может быть заливка со
скруглением и картинка без него.

**Четыре независимых радиуса**, а не один. Карточка со скруглённым верхом,
вкладка, подсказка с «хвостиком» одним числом не описываются вовсе.
`UICorners::Clamped` не даёт радиусам съесть друг друга — ограничение сделано в
одном месте, а не каждым рисующим по-своему.

## UIBorder — рамка

Отдельный компонент, а не два поля внутри заливки. Раньше из этого следовало:
рамка без заливки невозможна, рамка своего цвета поверх картинки невозможна,
рамка с собственным скруглением невозможна.

```cpp
UIBorder& b = node.Ensure<UIBorder>();
b.Thickness = UIEdges::Uniform(1.0f);   // или по сторонам независимо
b.Color = UIColorFromHex("#333A47");
b.Radius = UICorners(-1.0f);            // отрицательное — взять у заливки
b.Inset = 0.0f;                         // наружу от края узла
```

## UIShape — процедурные формы

Круг, эллипс, кольцо, дуга, линия, треугольник, многоугольник, скруглённый
прямоугольник. Один компонент с полем «какая», а не десять компонентов: набор
свойств у них общий, различается только геометрия.

```cpp
UIShape& s = node.Ensure<UIShape>();
s.Type = UIShape::Kind::Ring;
s.Thickness = 4.0f;         // 0 — заливка, больше — обводка
s.StartAngle = 0.0f;  s.SweepAngle = 270.0f;   // дуга
s.Sides = 6;                                    // многоугольник
s.Points = {{0,0}, {1,0.5f}, {0,1}};            // свои точки, В ДОЛЯХ узла
```

Точки задаются в долях прямоугольника узла, а не в пикселях: форма обязана
переживать смену размера, иначе её нельзя ни растянуть, ни положить в раскладку.

## UIImage — изображение

```cpp
UIImage& img = node.Ensure<UIImage>();
img.Path = "assets/ui/panel.png";
img.SourceRect = {52, 0, 26, 26};      // кусок листа В ПИКСЕЛЯХ исходника
img.Fit = UIImageFit::Contain;         // Stretch | Contain | Cover | None | Tile
img.Slice = UIEdges::Uniform(8.0f);    // девятина
img.SliceScale = 2.0f;                 // 0 — растянуть
img.FlipX = true;
img.Radius = UICorners(8.0f);
img.PixelArt = true;
```

Спрайт задаётся **в пикселях исходника**: в наборе интерфейса он описан как
«26×26 начиная с (52,0)», и переводить это в доли текстуры должен движок, а не
человек с калькулятором.

**Девятина** обязательна для наборов интерфейса: панель, нарисованная как 48×48,
обычным квадом на 300×120 не растягивается — углы размажутся вместе с серединой.
`SliceShrink` ужимает углы пропорционально, если узел меньше их суммы: иначе
углы рисуются внахлёст.

Отсутствующая картинка рисуется заметной заглушкой, а не пустым местом: «забыл
назначить» и «путь неверный» не должны выглядеть как «так задумано».

## UIGradient — градиент

Самостоятельный объект, а не «второй цвет заливки»:

```cpp
UIGradient g;
g.Type = UIGradient::Kind::Linear;   // None | Linear | Radial | Angular
g.Angle = 120.0f;
g.Stops = {{0.0f, a}, {0.5f, b}, {1.0f, c}};
```

Произвольное число остановок. Из двух цветов не собирается ни одна настоящая
тема: стеклянная панель — три-четыре остановки, металл — пять, подсветка
кнопки — резкая остановка в середине.

За краями градиент отдаёт крайние цвета, а не прозрачность: «затухание на
границе» почти всегда ошибка ввода, а не замысел.

## UIIcon — векторный значок движка

Значки движка (`sage/ui/UIIcons.h`) не загружаются, а рисуются: десяток кругов,
четырёхугольников и колец на каждый. Ни картинкой, ни процедурной формой они не
выражаются.

```cpp
UIIcon& icon = node.Ensure<UIIcon>();
icon.Name = "heart";
icon.Color = UIColorFromHex("#E05C5C");
icon.Size = 0.0f;      // 0 — вписать в меньшую сторону узла
```

На экран он попадает через **пользовательский материал**: ядро не знает, что
такое значок, и доносит до бэкенда имя. Значок всегда вписан в квадрат, поэтому
вёрстка не зависит от того, какой именно назначили.

## UIMaterial — свой шейдер

```cpp
UIMaterial& m = node.Ensure<UIMaterial>();
m.Shader = "game/noise";
m.Name = "storm";
m.Texture0 = "assets/ui/noise.png";
m.Param0 = {1.0f, 0.5f, 0.0f, 0.0f};
m.Blend = UIBlendMode::Add;
```

Компонент, а не поле у заливки: свой материал бывает нужен и вместо заливки, и
вместо картинки, и сам по себе (шум, помехи, индикатор, процедурный фон). Поле у
одного из них означало бы, что все остальные случаи выразить нечем.

Что шейдер получает от системы: прямоугольник узла, локальную и нормализованную
позицию, UV, размер, цвет, итоговую прозрачность, состояние маски и время. Всё
это уже есть в команде отрисовки — материалу остаётся добавить свои текстуры и
числа.
