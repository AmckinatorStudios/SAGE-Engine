# Интерфейс

Интерфейс игры: экраны, кнопки, надписи, картинки, поля, ползунки. Из скрипта
его собирают **одним набором** `ui.*` (ниже), в редакторе — панелью
«Интерфейс». Всё остальное в этом файле — устройство движка для тех, кто его
правит.

## Интерфейс из скрипта: ui.*

**Один путь.** Раньше одно и то же делалось четырьмя способами (прокси
`obj:AddUI()` с полями `Type`/`TextColor`, глобальные `SetUI*`, таблица
`UI.find`, свойства объекта), и ни один не умел всего: например, вид кнопки
при наведении из скрипта не задавался вовсе, и игры каждый кадр сами меняли
ей картинку. Теперь — строитель на каждый вид элемента, свойства
присваиванием, нажатие — функцией. Источник: `ScriptApi_UIKit.cpp`.

### Быстрый старт

```lua
local menu = ui.screen{order = 10}                       -- экран во весь кадр
ui.image{parent = menu, image = "assets/ui/bg.png", fit = "tile", stretch = "both"}
local title = ui.text{parent = menu, anchor = "top", y = 40, w = 400, h = 40,
                      text = "My Game", size = 32, align = "center"}
local play = ui.button{parent = menu, anchor = "center", w = 200, h = 40, text = "Play",
                       on_click = function(btn) start_game() end}

play.text = "Continue"        -- свойства — присваиванием
play.enabled = false          -- недоступна: свой вид, мышь не ловит
menu.visible = false          -- спрятать экран со всеми детьми
```

### Строители

| Строитель | Что это | Свои ключи |
|---|---|---|
| `ui.screen{}` | экран: корень во весь кадр | `order` (кто поверх), `input = false` (виден, но не нажимается), `scale = "pixel"` / `"fit"` + `reference = {w, h}`, `max` |
| `ui.panel{}` | контейнер с фоном цветом или картинкой | ключи [вида](#вид-цвет-или-картинка) и ключи содержимого |
| `ui.image{}` | картинка или кусок листа | ключи вида (`image`, `sprite`, `fit`…) |
| `ui.text{}` | надпись | `text`, `font`, `size`, `text_color`, `align`, `valign`, `pad`, `wrap`, `bold`, `italic`, `shadow_offset`, `shadow_color` |
| `ui.button{}` | кнопка с надписью | вид + надпись + `hover`, `pressed`, `disabled` (таблицы вида), `hover_text_color`, `pressed_text_color`, `disabled_text_color`, `text_margin`, `offset` |
| `ui.field{}` | поле ввода | вид + надпись + `max`, `placeholder`, `password`, `focused` (вид в фокусе) |
| `ui.slider{}` | ползунок | `value`, `min`, `max`, `step`, `track`, `filled`, `knob` (таблицы вида) |
| `ui.bar{}` | полоса (здоровье, загрузка) | вид фона + `value` (0..1), `fill` (вид заполнения) |
| `ui.container{}` | невидимый контейнер | ключи содержимого (ниже) |

**Ключи содержимого** (`ui.container`, `ui.panel`): `arrange` = `manual` /
`horizontal` / `vertical` / `grid` / `wrap`, `spacing`, `padding` (число или
`{л, в, п, н}`), `align` = `start` / `center` / `end` (поперёк), `distribute`
= `start` / `center` / `end` / `between` / `around` / `evenly` (вдоль),
`child_width` / `child_height` = `fixed` / `fit` / `fill`, `columns`, `rows`,
`wrap_columns`, `fit_content`, `clip = true`, `scroll` = `horizontal` /
`vertical` / `both`.

Помощники: `ui.cursor()` — курсор (Vec2), `ui.size()` — размер кадра (Vec2),
`ui.mouse_down()` — зажата ли левая кнопка.

### Ключи и свойства

**Общие ключи строителя** (у всех): `parent`, `name`, `x`, `y`, `w`, `h`,
`anchor`, `stretch`, `margin`, `visible`, `alpha`, `order`, `layer`, `mask`,
`rotation`, `blend`, `on_click`, `on_change`. Неизвестный ключ — ошибка с его
именем.

**Где стоит.** `anchor` — точка родителя: `top_left` (по умолчанию), `top`,
`top_right`, `left`, `center`, `right`, `bottom_left`, `bottom`,
`bottom_right`. `x`, `y` — сдвиг от неё **внутрь** родителя: у `bottom_right`
положительный `x` — влево, `y` — вверх; у `center` это сдвиг центра.
`stretch = "both"` (`"x"`, `"y"`) — растянуть по родителю, `margin` — поля
`{л, в, п, н}` или число: у растянутого — от краёв родителя, у ребёнка
`ui.container{arrange = ...}` — место вокруг него в ряду, столбце или сетке.

**Свойства элемента** (присваиванием; опечатка — ошибка):

| Свойство | Что |
|---|---|
| `x`, `y`, `w`, `h`, `anchor`, `stretch`, `margin` | место и размер |
| `visible` | спрятать вместе с детьми (не рисуется, не ловит мышь, не занимает места) |
| `alpha`, `order`, `rotation`, `blend` | прозрачность поддерева, порядок среди соседей, поворот, смешивание (`normal`, `add`, `multiply`, `screen`, `invert`) |
| `layer` | слой поверх всего интерфейса (0 — как у родителя): подсказка из глубины окна выше соседних окон |
| `mask` | маска детей (см. [Маски и слои](#маски-и-слои)); `false` — снять |
| `color` | цвет плашки; у картинки — её оттенок |
| `image`, `sprite` | картинка и кусок листа (имя или `{x, y, w, h}`) |
| `text`, `text_color`, `size`, `align`, `valign`, `pad`, `shadow_color` | надпись (у кнопки — её надпись) |
| `value` | ползунок — в единицах `min..max`, полоса — 0..1 |
| `enabled`, `focused`, `placeholder` | кнопка и поле |
| `hovered`, `pressed`, `clicked`, `changed`, `real_size` | только чтение: состояние мыши за кадр, настоящий размер |
| `on_click`, `on_change` | функция `(элемент)` / `(элемент, значение)`; `nil` — снять |

**Методы** (через точку): `el.place(x, y, w, h)` — поставить разом,
`el.show()`, `el.hide()`, `el.remove()`, `el.look(часть, вид)` — вид части.
Объект сцены — `el.obj`.

### Вид: цвет или картинка

Одна таблица на любую поверхность — подложку, состояние кнопки, дорожку и
ручку ползунка, заполнение полосы:

| Ключ | Что |
|---|---|
| `color` | цвет (`Vec4` или `{r, g, b, a}`); с картинкой — оттенок, по умолчанию белый |
| `image` | путь картинки (`"rt:имя"` — съёмка движка) |
| `sprite` | кусок листа: имя из `.sagesheet` рядом с картинкой или `{x, y, w, h}` в пикселях файла |
| `slice` | девятина `{л, в, п, н}` в пикселях файла (кусок листа с девятиной ложится ею сам) |
| `fit` | `stretch`, `nineslice`, `tile`, `fit`, `cover` |
| `pixel` | экранных пикселей на пиксель картинки (у девятины и плитки) |
| `sharp` | ближайший сосед (по умолчанию да — наборы интерфейса пиксельные); `false` — для фото |
| `tile_edges`, `center` | девятина: повторять края вместо растяжения; рисовать ли середину |
| `rounding`, `border`, `border_color`, `gradient`, `shadow` | у плашки цветом |

Состояния кнопки начинаются с обычного вида — достаточно указать, что
меняется:

```lua
ui.button{image = "assets/ui/widgets.png", sprite = "button", pixel = 1,
          hover = {sprite = "button_hover"}, disabled = {sprite = "button_disabled"},
          text = "Options", hover_text_color = {1, 1, 0.6, 1}}
```

Части элемента по имени — `el.look("fill" | "hover" | "pressed" | "disabled" |
"focused" | "track" | "filled" | "knob" | "check" | "bar", {...})`.

### Маски и слои

**Маска** режет детей элемента. Прямоугольник (`mask = "rect"`, или
`clip = true` у группы) режут ножницы; остальное — шейдер по пикселям:

```lua
ui.container{mask = "rounded"}                                  -- скругление подложки
ui.container{mask = {rounding = 12, feather = 4}}               -- своё скругление, мягкий край
ui.container{mask = {image = "assets/ui/circle.png"}}           -- видно там, где картинка непрозрачна
ui.panel{stretch = "both", color = {0, 0, 0, 0.7},          -- затемнение с окном-дыркой
         mask = {invert = true, padding = {100, 80, 100, 80}}}
```

Ключи: `shape` (`rect`, `rounded`, `image`), `rounding`, `image`, `sprite`,
`feather` (мягкий край, пикселей), `invert` (видно всё, кроме окна),
`padding` (сжать окно), `sharp`. Вложенная маска заменяет внешнюю форму;
прямоугольные обрезки при этом пересекаются.

**Слой** (`layer`) — порядок поверх ВСЕГО интерфейса, а не только соседей
(`order`): элемент со слоем 5 рисуется над всеми со слоем меньше и раньше них
ловит мышь. Дети наследуют слой родителя.

**Альфа** складывается верно везде: прозрачность групп, текста и теней
перемножается, смешивание — с домноженной альфой, поэтому интерфейс, снятый в
прозрачную текстуру, сохраняет свою прозрачность. Гладкие картинки с
прозрачностью грузятся с цветом под прозрачными пикселями от соседей — без
тёмной или светлой каймы по краю.

### Пиксельная точность

Движок держит интерфейс на пиксельной сетке сам — ничего включать не нужно:

- **Края — по целым пикселям.** Каждый прямоугольник (панель, картинка, кусок
  девятины, плитка) привязывается к сетке по краям, поэтому элемент по центру
  окна нечётной ширины не стоит на полупикселе: у картинки нет «лишнего»
  столбца, у рамки — разной толщины, между кусками девятины нет щелей.
- **Прямой край — без сглаживания.** Прямоугольник без скругления и рамки
  режет растеризатор, а не SDF: крайний ряд пикселей сплошной, на стыке
  панелей нет полосы.
- **Шрифт-картинка — кратно своему пикселю.** Масштаб такого шрифта
  округляется до целого числа экранных пикселей на пиксель буквы: «строка 16»
  у шрифта 8×8 становится 18 (2 пикселя на пиксель буквы). Дробный масштаб
  выбрасывал из букв разные строки — штрихи выходили то в один, то в два
  пикселя. Начало строки — тоже на целом пикселе.
- **Градиент из прозрачного** (тень под шапкой, затемнение к низу) рисуется:
  прозрачность верхнего и нижнего цвета у него своя.

- **Пиксельная картинка — целым шагом.** Картинка с резкой фильтрацией
  (ближайший сосед — по умолчанию у `ui.*`) на холсте «подгонять под
  разрешение» рисуется целым числом экранных пикселей на её пиксель (или 1/n)
  и встаёт по центру своего прямоугольника — на любом разрешении линии рисунка
  одной толщины. То же у девятины и плитки. Чтобы целым был весь экран сразу,
  — `ui.screen{scale = "pixel", reference = {320, 180}}`.
- **Атлас без каймы соседа.** Кусок листа выбирается с отступом внутрь: у
  гладкой фильтрации в полпикселя (фильтр не дотягивается до соседнего
  спрайта), у резкой — в тысячную (защита от округления на границе).
- **Текст по центру — по центру.** Ширина для выравнивания — по чернилам букв
  (без промежутка после последней), высота для центрирования у
  шрифта-картинки — тело букв (от верха до базовой линии), а не вся строка.
- **Без сжатия с потерями.** «Конвертировать в форматы движка» не жмёт
  блоками BC1/BC3 картинки интерфейса: у которых рядом лист спрайтов или
  девятина, которые лежат в папках `ui`, `gui`, `hud`, `fonts`, `icons`,
  `sprites`, и всё до 256 пикселей — они остаются RGBA без потерь и без
  мипмапов.

Повёрнутый элемент к сетке не привязывается: у косого края нет «пикселя».

## Три понятия, и больше никаких

| Понятие | Что это |
|---|---|
| **Interface** | ЭКРАН: файл `.sageui` с одним главным контейнером |
| **Контейнер** | держит детей и расставляет их: **Container** (невидимый) и **Panel** (с оформлением) |
| **Элемент** | то, что ВИДНО: текст, картинка, значок, кнопка, галка, ползунок, полоса, поле ввода |

**Детей держат только контейнеры** — главный, Container и Panel
(`sage::ui::HoldsChildren`, `CanReparent`). Как дети расставлены — режим
**Arrangement** самого контейнера, а не отдельный тип: «ряд», «столбец»,
«сетка», «прокрутка», «обрезка» и «распорка» как типы убраны. Обрезка детей
(Clip Children) и прокрутка (Scroll) — настройки контейнера в разделе
«Content» инспектора; ни области обрезки, ни вьюпорта в дереве не появляется.

### Arrangement

`sage::ui::Arrangement` (`components/Layout.h`) — одна система у главного
контейнера, Container и Panel. Родитель управляет только непосредственными
детьми; вложенный контейнер раскладывает своих сам.

| Режим | Что делает |
|---|---|
| Manual | дети стоят по своим якорям |
| Horizontal | ряд слева направо |
| Vertical | столбец сверху вниз |
| Grid | равные ячейки: столбцы и строки (0 — сколько нужно), размер ячейки |
| Wrap | ряд, продолжающийся на следующей строке (или столбцами — `WrapVertical`) |

Общие настройки: **Padding**, **Spacing**, **Alignment** (поперёк: начало,
центр, конец), **Distribution** (свободное место вдоль: начало, центр, конец,
между, вокруг, поровну). **Размер детей** по каждой оси: Fixed — свой, Fit
Content — по тексту (у вложенного контейнера — по его содержимому), Fill —
всё доступное место (вдоль оси — поровну, с учётом `Grow` ребёнка; поперёк —
целиком). В режиме Manual остальные поля не показываются; значения других
режимов сохраняются при переключении. Ребёнок с «стоять по своему якорю»
(`IgnoreLayout`) в раскладке не участвует.

**У каждого типа — своё устройство.** Тип (`Element::Type`, заготовка
`sage::ui::Preset`) задаёт, из каких частей элемент состоит и какие настройки у
него есть. Инспектор показывает только их: у текста — текст, у ползунка —
дорожку, заполнение и ручку, у кнопки — вид в каждом состоянии, у контейнера —
раскладку. Поле, которое в нынешнем режиме ничего не делает, не показывается
(поля девятины — только в режиме девятины, режим — только когда выбрана
картинка).

## Что есть у элемента всегда

`sage/ui/Element.h`. Раскладка — **часть элемента, а не компонент**: элемент без
прямоугольника бессмыслен, его негде рисовать, нечем попасть мышью и некуда
класть детей. Сделать её компонентом — значит разрешить состояние «элемент
есть, а места у него нет», которое каждая система обязана проверять и ни одна не
умеет починить.

| Поле | Зачем |
|---|---|
| `Anchor`, `Mode`, `Position`, `Size`, `Margin`, `Pivot` | где элемент стоит и какого он размера |
| `Rotation` | поворот вокруг центра. **Раскладку не меняет**: иначе список из наклонённых карточек разъезжался бы от самого наклона |
| `Order` | порядок среди соседей (больше — поверх) |
| `Visible` | не рисуется и не ловит мышь, но **место в раскладке держит** |
| `Active` | выпадает из всего сразу: отрисовки, ввода, раскладки родителя |
| `Locked` | редактор: не выделяется мышью и не двигается |
| `Blend` | как элемент ложится на то, что под ним: `normal`, `add`, `multiply`, `screen`, `invert` (инверсия фона — прицел, видный на любой поверхности) |

**Visible и Active — разные вещи, и обе нужны.** Пока флаг был один, «спрятать
панель на время анимации, не сломав раскладку соседей» выразить было нечем, а
«убрать элемент из списка на время» означало удалить его и создать заново.
Спрятанный при этом **не ловит мышь**: прозрачная зона нажатия делается заливкой
с нулевой альфой, а спрятанный, который всё равно кликается, — это ловушка,
которую не видно ни на экране, ни в дереве.

**Имени и родителя в `Element` нет.** И то, и другое принадлежит сцене
(`NameComponent`, `HierarchyComponent`) и одинаково у элемента интерфейса и у
объекта сцены. Вторые копии внутри `Element` дали бы два имени у одной вещи и
вопрос «какое настоящее» при первом же расхождении — а заодно закрыли бы дорогу
единому инструменту анимации, который обязан одинаково работать и с
интерфейсом, и с объектами сцены.

**`Arrangement` — это компонент, а не раскладка элемента.** Он отвечает на
другой вопрос: как контейнер расставляет ДЕТЕЙ (ряд, столбец, сетка, перенос). Пока оба понятия
звались `Layout`, каждый разговор начинался с «какой Layout имеется в виду».


## Интерфейс — контекст, а не просто набор элементов

`sage/ui/components/InterfaceComponent.h`. Интерфейс в сцене — это ОБЪЕКТ с
компонентом «Интерфейс». Он ничего не рисует сам: он граница. Элемент
принадлежит ближайшему такому предку (`sage::ui::InterfaceOf`) — и никакому
другому.

```
Interface Object            <- объект с InterfaceComponent
└── HUD Panel               <- корневой элемент (Element + Fill)
    ├── Title               <- Element + Label
    └── HP Bar              <- Element + Fill + Bar
```

**Что было не так.** Корнем считался любой прямоугольник, у которого нет
родителя-прямоугольника. Пока интерфейс в сцене был один, это работало. Два
интерфейса — меню паузы и HUD — оказывались в ОДНОМ дереве редактора,
вперемешку: верстать один, не задевая другой, можно было только пряча чужие
объекты глазом в иерархии, то есть правя СЦЕНУ ради того, чтобы посмотреть на
один экран. Причина не в панели: у интерфейса не было собственного узла, и
«интерфейс» существовал лишь как наблюдение «эти элементы лежат рядом».

**Что даёт граница.** В сцене их может быть сколько угодно, и они не знают друг
о друге. Редактор вёрстки работает с ОДНИМ выбранным — дерево, холст и правки
относятся только к нему (`sage::ui::UIScope`). Опорное разрешение и порядок
показа стали свойствами ИНТЕРФЕЙСА, а не первого его элемента. Спрятать экран
целиком — одно поле, а не обход всех его элементов.

| Поле компонента | Зачем |
|---|---|
| `Visible` | интерфейс целиком, со всеми элементами |
| `ReceivesInput` | показывается, но не нажимается: заставка, титры, подсказка |
| `SortOrder` | порядок МЕЖДУ интерфейсами: HUD под меню паузы |
| `Canvas` | опорное разрешение и способ пересчёта — на весь экран сразу |

**Интерфейс и элемент — разные разделы инспектора.** У интерфейса нет и не
должно быть ни цвета, ни отступов, ни текста: это контекст, а не прямоугольник
на экране. Свойства элемента живут у самих элементов, внутри него.

**Элементы без интерфейса** в сцене остаются законными: их собирает код, скрипт
или тест. В редакторе они показываются отдельной строкой списка («Без
интерфейса»), а не подмешиваются к чужому экрану. Сцены, собранные до появления
границ, переводит миграция v12 → v13: каждый корень получает свой интерфейс, а
холст корня переезжает в него.

## Interface — структура интерфейса отдельным ресурсом (`.sageui`)

`sage/ui/Interface.h`, `sage/ui/InterfaceSource.h`. Интерфейс — самостоятельный
файл, как сцена, материал или клип: лежит в проекте, виден в панели ассетов,
правится в пространстве «Интерфейс», а в сцене стоит **одним объектом** со
ссылкой на файл.

**Главный контейнер — один на интерфейс.** Корень файла — невидимый контейнер
во весь экран; всё остальное лежит в нём или во вложенных контейнерах. Его
нельзя удалить, продублировать, скопировать и положить внутрь другого элемента
(`ui::MainContainer`, `ui::IsMainContainer`, `ui::CanReparent`); «в корень»
значит в него. HUD и меню паузы одного файла — два контейнера внутри главного,
а не два корня: у них одна область, один холст и общий порядок показа.

```cpp
sage::ui::Interface ui = sage::ui::Capture(scene, interfaceObject); // объект -> ресурс
ui.SaveFile(path, err);
sage::ui::Interface::LoadFile(path, ui, err);
entt::entity iface = sage::ui::Instantiate(scene, ui, parent);    // ресурс -> объект
entt::entity main  = sage::ui::MainContainer(scene, iface);
```

Формат — версия 2: `name`, `canvas` (режим, опорное разрешение — холст едет
вместе с файлом) и `root` (главный контейнер с детьми). Файл версии 1
(несколько `roots`) открывается сам: корни ложатся в главный контейнер, на
экране не меняется ничего.

**В сцене — одна строка.** Объект с `InterfaceComponent::Source = "assets/ui/menu.sageui"`
разворачивает содержимое файла под собой (`ui::SyncInterfaceSources`: при
чтении сцены, перед вводом и отрисовкой интерфейса). Развёрнутые сущности
помечены `InterfaceInstanceTag`:

* в файл сцены не пишутся (описание экрана одно — в его файле), в иерархии
  сцены не показываются, в копию объекта и префаб не попадают — копия
  разворачивает своё;
* после сохранения файла каждая сцена, где он стоит, показывает новый
  вариант сама (файл проверяется не чаще двух раз в секунду);
* скрипт во время игры работает с ними как с обычными объектами: находит по
  имени, меняет текст и значения;
* испорченный файл не роняет остальные интерфейсы — в журнале путь и причина.

Холст интерфейса из файла берётся из файла. Сцена задаёт только подключение:
активен ли интерфейс, порядок показа между интерфейсами, принимает ли ввод.

**Интерфейс старого вида** (элементы прямо в сцене, без `Source`) работает как
раньше. Кнопка инспектора «Вынести в файл и открыть» снимает его в
`assets/ui/<имя>.sageui` (`ui::Capture` оборачивает старые корни главным
контейнером), убирает элементы из сцены и ставит ссылку — одним шагом отмены.

**Буфер обмена — фрагмент**, а не интерфейс (`ui::InterfaceFragment`,
`CaptureFragment`, `InstantiateFragment`): несколько узлов без холста и без
главного контейнера. Вставка в элемент — внутрь него, в объект-интерфейс — в
его главный контейнер, в пустое место — своим интерфейсом.

* **Разворачивается, а не «загружается».** Тот же ресурс можно развернуть
  дважды (два окна инвентаря рядом), и копии не знают друг о друге.
* **Чужие объекты не попадают.** 3D-объект, случайно оказавшийся внутри
  поддерева интерфейса, в ресурс не поедет.
* **Запись одна на сцену и на ресурс** (`sage/ui/UISerialize.h`): элемент в
  сцене и в файле пишется одним кодом.

## Типы: элементы и контейнеры

Заготовка — это **данные, а не код редактора**: собрать кнопку одинаково должны
и меню редактора, и скрипт, собирающий диалог на лету, и игра без редактора.

**Элементы** (видимые):

| Тип | Из чего собран | Что настраивается |
|---|---|---|
| Text | `Label` | текст, шрифт, цвета по состоянию кнопки |
| Image | `Image` | картинка, режим, кусок листа |
| Icon | `Icon` | векторный значок движка |
| Button | `Fill` + `Interactable` + ребёнок-надпись | вид на каждое состояние, действие, события |
| Checkbox | `Range` (галка) + ребёнок-надпись | квадратик, отметка |
| Slider | `Range` | дорожка, заполнение, ручка |
| Progress Bar | `Fill` + `Bar` | фон (подложка), заполнение, режим «сжать/открыть» |
| Input Field | `Fill` + `Label` + `TextInput` | каретка, подсказка |

**Контейнеры** (держат детей, у каждого Arrangement):

| Тип | Из чего собран |
|---|---|
| Container | `Arrangement` — невидимый |
| Panel | `Arrangement` + оформление: **Appearance** None / Image (`Fill`) / Shape (`Shape`) |

У ребёнка контейнера-раскладки в инспекторе — раздел «В контейнере»: **Grow**
(доля свободного места: поле ввода занимает всё, что осталось от кнопки) и
**«Стоять по своему якорю»** (`IgnoreLayout`: значок-метка в углу карточки не
занимает строку). Прозрачность и приём мыши поддерева — общие настройки
любого элемента, а не добавка.

**«Экрана» как типа нет.** Полноэкранная подложка — это панель, растянутая на
весь родитель.

**Типов старого вида больше нет**: Group, Row, Column, Grid, Wrap Row,
Scroll View, Clip Area, Spacer и прежние имена (Label, Screen…) не
распознаются. Тип элементу, собранному кодом, назначает
`sage::ui::InferMissingTypes` — по набору частей.

## Форма (Shape) — элемент и оформление Panel

`sage::ui::Shape` (`components/Visual.h`) — один компонент на элемент **Shape**
(раздел Graphics) и на оформление Panel (Appearance: Shape, по умолчанию).

| Настройка | Значения |
|---|---|
| Geometry | Rectangle, Rounded Rectangle (скругление углов), Circle (вписан в меньшую сторону), Ellipse |
| Fill | None, Solid Color, Linear Gradient (конечный цвет, угол: 0 — слева направо, 90 — сверху вниз), Radial Gradient (от центра к краю) |
| Stroke | толщина (0 — нет), цвет, положение: Inside / Center / Outside |

Инспектор показывает только поля выбранной геометрии и заливки.

**Одна система отрисовки.** Форма строится КОНТУРОМ — списком точек
(`ShapeOutline`, `sage/ui/ShapeGeometry.h`), — и рисуется веером с цветом в
каждой вершине (`UIRenderer::FillPolygon`) и полосами (`StripPolygon`):
обводка — полоса между контурами с разным сдвигом, сглаживание края — полоса
в пиксель, гаснущая наружу. Градиент считается в вершинах
(`ShapeFillColor`), поэтому линейный и радиальный работают у любой формы.
Контуры с любым сдвигом совпадают по числу точек. Custom Shape (этап 4)
ляжет в ту же систему — своим контуром.

**Текст (Label):** кроме содержимого, шрифта и выравнивания — **Auto Size**
(кегль уменьшается, пока текст не поместится; больше заданного не
становится), **Line spacing** (доля высоты строки) и **Overflow**: Show all,
Cut off (обрезать по элементу), Ellipsis (оборвать «...», строки ниже края не
рисуются).

**Картинка (Image):** Source, Display mode — Stretch, Nine-Slice, Tile,
Aspect Fit, Aspect Fill; Tint; фильтрация и кратный масштаб — в
дополнительных настройках.

## Оформление: стиль движка или своё

У каждого видимого элемента — выбор в начале инспектора (`Element::Skin`):

- **Стиль движка** (`Engine`). Вы задаёте цвета; форму, рамку, градиент,
  тень и вид состояний (наведение, нажатие, фокус, недоступность) движок
  выводит сам из цвета по роли поверхности — кнопка, поле, панель, дорожка,
  ручка (`EngineLook` в `UIParts_Look.cpp`). Полей скругления, толщины и цвета
  рамки, картинок и девятины в инспекторе нет вовсе (`PartField::CustomOnly`).
  Новые элементы из меню создаются в этом стиле.
- **Своё** (`Custom`). Каждая часть и каждое состояние — своя картинка
  (девятина, замощение) и любой параметр. Переход на «своё» запекает вид
  движка в поля (`BakeEngineSkin`): элемент на экране не меняется.

Элементы, собранные кодом, и элементы старых сцен (без ключа `skin`) —
«своего» оформления: выглядят ровно так, как их настроили. Из скрипта —
свойство `Skin` (`"engine"` / `"custom"`).

На холсте щелчок по кнопке выбирает саму кнопку, а не её надпись
(`sage::ui::ControlOf`): надпись лежит поверх во весь прямоугольник, и
раньше ручки рамки растягивали надпись, а кнопка с девятиной оставалась
прежней. К надписи — двойной щелчок.

## Вид (Look): цвет или своя картинка на любой части

`sage::ui::Look` (`components/Visual.h`) — ОДИН набор настроек для любой
поверхности: подложка, вид кнопки при наведении/нажатии/фокусе/недоступности,
дорожка, заполнение и ручка ползунка, квадратик и отметка галки, заполнение
полосы.

| Поля | Когда видны |
|---|---|
| Цвет | всегда (с картинкой — оттенок) |
| Картинка | всегда; пусто — плашка цветом |
| Как ложится: растянуть / девятина / замостить / вписать / заполнить | когда выбрана картинка |
| Кусок листа, размер пикселя, кратный масштаб, фильтрация | когда выбрана картинка |
| Поля девятины, заполнение краёв и середины, «рисовать середину» | в режиме девятины |
| Скругление, градиент | у плашки цветом |
| Рамка, тень | всегда |

В таблице части вид — одно поле `PartField::Kind::Look`: в файл пишется
вложенным объектом, в редакторе раскрывается свёрнутой группой. Своя часть
игры получает вид одной строкой в таблице.

**Виды состояний** — у реакции на мышь (`Interactable`): «свой вид при
наведении/нажатии/фокусе/недоступности». Выключено — подложка подкрашивается
множителями яркости; включено — рисуется свой вид целиком (кнопка из набора
нарисована трижды). Надпись кнопки меняет цвет вместе с ней
(`Label::StateColors`: состояние берётся у ближайшего реагирующего предка), а
`PressedOffset` сдвигает содержимое нажатой кнопки на пару пикселей.

Старые ключи читаются: `trackColor`/`accentColor` ползунка — в дорожку и
ручку, `fillColor` полосы — в её заполнение, `stretchCross` раскладки — в
«поперёк: растянуть/к началу».

## Стили из файлов (`.sageuistyle`)

`sage/ui/UIStyle.h`. Стиль хранит ВИД элемента — все поля частей, кроме
содержимого (текст, значение, действие, события помечены в таблице как
`Content`). Элемент ссылается на файл полем `Element::Style`; правка файла
доходит до всех таких элементов прямо в открытой сцене (`ApplyStyles` раз в
кадр, файл перечитывается не чаще раза в полсекунды). В инспекторе: слот
стиля, «Сохранить этот вид как стиль», «Сохранить изменения в стиль»,
«Отвязать». Из скрипта — свойство `Style`.

## Интерфейс игры — набор компонентов, а не мешок на сорок полей

Весь интерфейс описывал ОДИН компонент: панель, надпись, картинка, полоса, поле
ввода, галка и ползунок были не разными вещами, а одним компонентом с полем
«вид». Отсюда следовало всё остальное. У надписи всё равно были скругление,
рамка, градиент, девятина и предел длины поля ввода — поля лежали в памяти,
показывались в инспекторе и сохранялись в сцену, ничего не значая. Свой вид
элемента (миникарта, радар) добавить было нельзя иначе как дописав ещё полей в
общий компонент и ещё одну ветку в отрисовку. Спросить у сцены «все элементы с
картинкой» было нечем — только «все элементы» с проверкой поля у каждого.

Теперь элемент — это **обязательный `Transform` плюс то, из чего он сделан**:

```
кнопка   = Transform + Fill + Interactable   (+ объект-надпись внутри)
картинка = Transform + Image
шкала    = Transform + Fill + Bar
список   = Transform + Fill + Mask + Layout  (дети раскладываются сами)
галка    = Transform + Range(Toggle) + Interactable (+ объект-надпись рядом)
```

Что это дало сверх наведения порядка:

* **Раскладка** (`Layout`): контейнер сам расставляет детей рядом, столбцом или
  сеткой. Меню из пяти кнопок раскладывалось вручную — каждому ребёнку свой
  отступ, посчитанный на бумаге; шестая кнопка означала пересчёт пяти чужих.
* **Холст** (`Canvas`): вёрстка под опорное разрешение вместо пикселей экрана.
  Кнопка 200x52, выставленная на 1080p, на 4K занимала четверть прежнего места.
* **Растяжение и поля** (`Transform::Stretch`): «панель во всю ширину с отступом
  20» больше не требует пересчёта скриптом на каждое изменение размера окна.
* **Группа** (`Group`): прозрачность и приём ввода на всё поддерево одним
  числом — вместо прохода скриптом по каждому ребёнку и попытки не забыть
  вернуть как было.
* **Имя действия** у кнопки (`Interactable::Action`): игра спрашивает «нажали ли
  `quit`», а не «нажали ли сущность номер 37». Связь меню с логикой держалась на
  номере, который меняется при любой пересборке сцены.
* **Диапазон** (`Range`) хранит значение в игровых единицах и умеет шаг: перевод
  долей 0..1 в громкость 0..100 больше не размазан по всем читателям.
* **Состояние отделено от настроек**: наведение, нажатие и каретка лежат в
  `Interactable::Runtime`, который сериализатор не пишет по определению. Раньше
  сохранённая сцена помнила, что кнопка была под курсором.

### Ни одной встроенности: часть рисует СЕБЯ и не трогает соседей

Разбиение на компоненты — это ещё не независимость. Пока правила «кто кого
двигает» живут в отрисовке, набор частей остаётся мешком с другой стороны:

* значок отодвигал надпись соседа вправо на свою ширину — но только если рядом
  было что-то ещё, а один в элементе занимал его целиком;
* галка сдвигала надпись за квадратик, и поставить подпись слева от галки было
  нельзя вообще;
* ползунок красил дорожку цветом ПОДЛОЖКИ, а ручку — цветом ШКАЛЫ, которую
  ради этого вешали рядом пустой; при этом подложка, оказавшись на таком
  элементе, переставала закрашивать его целиком.

Ни одно из этих правил нельзя было увидеть в инспекторе, отменить или
повторить у своей части. Теперь правило одно и оно короткое: **часть рисует
себя в прямоугольнике СВОЕГО элемента и не меняет ни положения, ни смысла
соседей.** Значок занимает свой прямоугольник, диапазон носит собственные цвета
(`TrackColor`, `AccentColor`, `BorderColor`, `Rounding`), подложка всегда
закрашивает элемент целиком.

Отсюда — то, ради чего всё и затевалось: **у панели нет встроенного текста**.
Нужна надпись на кнопке — это объект-надпись внутри кнопки, видимый в дереве:
его можно подвинуть, покрасить, выровнять, заменить картинкой, убрать или
добавить второй. Ровно так собраны и заготовки: `Button` — это подложка с
`Interactable` и ребёнок «Текст», `Checkbox` — квадратик и подпись рядом.

Единственное исключение задокументировано на месте: надпись не рисует себя,
если на элементе есть поле ввода, — его содержимое показывает САМО ПОЛЕ (оно
бывает скрыто точками и обрезано кареткой).

### Реестр частей: одна таблица вместо четырёх списков

Часть интерфейса раньше приходилось прописывать в четырёх местах: в отрисовке,
в записи сцены, в чтении сцены и в инспекторе редактора. Списки обязаны были
совпадать — и рано или поздно расходились: поле сохранялось, но не читалось, и
молча сбрасывалось при следующей загрузке.

Теперь часть объявляет ТАБЛИЦУ СВОИХ ПОЛЕЙ (`sage/ui/UIPart.h`), и по ней идут
все четверо:

```cpp
struct Sparkle { float Rate = 4.0f; glm::vec4 Color{1, 1, 1, 1}; };

static const std::vector<sage::ui::PartField> kFields = {
    {"rate",  SAGE_UI_TEXT("Rate"),   PartField::Kind::Float, offsetof(Sparkle, Rate), 0.0f, 60.0f},
    {"color", SAGE_UI_TEXT("Colour"), PartField::Kind::Color, offsetof(Sparkle, Color)},
};

sage::ui::RegisterPart(sage::ui::MakePart<Sparkle>("sparkle", SAGE_UI_TEXT("Sparkle"),
                                                   /*порядок слоя*/ 55, &kFields, DrawSparkle));
```

Всё: часть рисуется в нужном слое, пишется в сцену и читается из неё, а в
инспекторе у неё появляются подписанные поля с ползунками и палитрой — без
единой правки в движке, сериализаторе или редакторе. Регистрация по тому же
ключу ЗАМЕНЯЕТ встроенную часть: игра может переопределить отрисовку `label`,
не форкая движок. Подписи полей помечены `SAGE_UI_TEXT`, и
`scripts/check_localization.py` требует для них перевод наравне со строками
самого редактора — иначе новая часть выходила бы в русском интерфейсе
по-английски.

Старого компонента больше НЕТ — ни в сцене, ни в отрисовке. Рисование тоже
складывает слои, а не выбирает ветку по «виду элемента»: подложка, картинка,
шкала, значок и надпись рисуют своё поверх предыдущих, и любое их сочетание
осмысленно само по себе. Заодно заработало то, что было объявлено, но не
рисовалось: направление роста полосы (вертикальная шкала маны), выравнивание
надписи по обеим осям (подпись, прижатая к правому краю панели) и множители
подсветки из самого элемента.

Совместимость. Сцены, записанные до перехода, читаются по признаку `"kind"` и
раскладываются по компонентам при загрузке — и пересохраняются уже в новом виде.
Отказ от встроенностей тоже не ломает уже сделанное: миграция формата сцены
v5→v6 (`SceneSerializer.cpp`) переносит сдвинутую надпись и прижатый к краю
значок в дочерние объекты с тем же положением, а цвета дорожки и акцента —
внутрь самого диапазона. Сцена выглядит как раньше — но теперь это видно в
дереве, а не только в исходниках отрисовки.
Само описание старого формата уцелело ровно для этого и называется честно
(`sage::ui::LegacyElement`, только чтение): оно описывает прошлое, и ни одной
новой возможности интерфейса в нём нет по определению.
Скриптовый API остался прежним по виду (`obj:GetUI().Text = "..."`), но это
прокси: он пишет в ту часть, которой поле принадлежит, и **создаёт** её при
записи — `ui.Text = "Дальше"` на голой панели заводит ей надпись.

**Готовые экраны.** Заготовки отвечали на вопрос «что такое кнопка»; оставшийся
— «как из кнопок собирают экран» — оставался без ответа. В движке есть три
работающих экрана (`sage/ui/UIDemos.h`): главное меню, худ и настройки. Они
ставятся из меню редактора (Entity → Create UI → Демо-экраны), вызываются из
скрипта (`ui.SpawnDemo`) и разбираются в инспекторе. Собраны кодом, а не
файлами-сценами, намеренно: демо на диске устаревает молча, а собранное кодом
ломается на сборке и проверяется тестами.

### Экраны собирает скрипт, а не только редактор

Интерфейс, свёрстанный в редакторе, — это интерфейс, известный заранее. Меню
паузы, худ, экран настроек — да. А инвентарь, число ячеек в котором зависит от
игры, список рецептов и сетка предметов существуют только в рантайме, и собрать
их может только скрипт. До этого он мог создать элемент и покрасить его — и всё:
раскладка, холст и группа были видны инспектору и невидимы Lua.

```lua
local panel = SpawnObject("Инвентарь")
local e = panel:AddUI()
e.Stretch = UIStretch.Both        -- во весь кадр, а не «1920 на 1080»
e.Margin  = Vec4(24, 24, 24, 24)
e.Alpha   = 0.0                   -- прозрачность ВСЕГО поддерева (Group)

sage.ui.SetLayout(panel, {dir = "grid", columns = 8, spacing = 6, padding = 8})
sage.ui.SetCanvas(panel, {order = 40})   -- меню поверх верстака, верстак поверх худа

if sage.ui.HoveredAction() == "craft:plank" then ... end   -- что под курсором
if sage.ui.ClickedAction() == "craft:plank" then ... end   -- что нажали
```

`dir` — `"row"`, `"column"` или `"grid"`; `justify` — `"start"`, `"center"`,
`"end"`, `"between"`; `fit = true` подгоняет контейнер под содержимое;
`padding` принимает число («со всех сторон») или `Vec4(л, в, п, н)`.
`sage.ui.ClearLayout(panel)` снимает раскладку обратно.

**Перетаскивание.** Щелчок — это нажатие и отпускание на ОДНОМ элементе, а
перенос вещи из ячейки в ячейку — на разных: по одному `ClickedAction` их не
различить. Поэтому нажатие и отпускание отдаются раздельно, а курсор — в тех же
координатах, в которых свёрстан интерфейс (у окна свои, у letterbox-кадра свои,
у холста свой масштаб, и складывать их в скрипте значило бы повторять перевод,
уже сделанный движком):

```lua
local from = sage.ui.PressedAction()    -- на чём нажали в этом кадре
local to   = sage.ui.ReleasedAction()   -- над чем отпустили
local c    = sage.ui.Cursor()           -- куда рисовать то, что «в руке»
```

Порядок между корнями (`Canvas.SortOrder`) — не украшение: пока его не было
видно из скрипта, «меню поверх худа» держалось на порядке создания сущностей, то
есть на удаче. Кнопка «Выйти», оказавшаяся под ячейкой инвентаря, — это не
косметика.

**И клики работают в Play-режиме редактора.** Панель Game рисовала интерфейс
сцены, но ввод ему не передавал никто: `UpdateSceneUI` звал только плеер. Меню
проверялось исключительно сборкой игры. Теперь курсор панели переводится в
координаты игрового кадра (панель — единственная, кто знает, где нарисована её
картинка), и кнопка нажимается там же, где её верстают.

## Редактор интерфейса (панель «Интерфейс»)

Отдельная рабочая среда, а не режим вьюпорта. Пространство «Интерфейс» правит
**документ** — файл `.sageui`, — а не сцену уровня
(`editor/src/EditorLayer_InterfaceDoc.cpp`). Пока оно на экране, на месте
сцены стоит документ (объект-интерфейс с главным контейнером) со своей
историей отмены и флагом изменённости; уровень ждёт в стороне и не получает ни
одной правки вёрстки. Поэтому создание, удаление, дублирование, отмена и
инспектор работают с документом тем же кодом, что и со сценой.

Как открыть документ:

- двойной щелчок по `.sageui` в ассетах (или пункт «Открыть интерфейс»);
- двойной щелчок по объекту-интерфейсу в иерархии сцены или кнопка «Открыть
  интерфейс» в его инспекторе;
- переход в пространство с выделенным объектом-интерфейсом;
- список первой строкой дерева элементов: интерфейсы проекта, «новый»,
  «сохранить».

Без открытого файла пространство начинает с нового документа. `Ctrl+S`
сохраняет его; документ без файла ложится в `assets/ui/<имя>.sageui`.
Открытие другого файла и выход в пространство сцены сохраняют правки сами;
«Играть» в пространстве интерфейса играет сам документ — кнопки нажимаются в
предпросмотре.

Главный контейнер — первая строка дерева; на холсте у него нет рамки и ручек
(щелчок по пустому месту — рамка выделения). В инспекторе у него имя
интерфейса и холст (опорное разрешение), а не поля элемента.

- **Холст** — ИГРОВОЙ кадр в его собственном разрешении (из настроек игры) и
  соотношении сторон, вписанный в панель. Рисует его тот же путь, что и панель
  Game, вместе с игровым UI, поэтому видно ровно то, что увидит игрок. Правки
  видны в следующем же кадре. Масштаб — колесом (от курсора), панорама —
  средней кнопкой, `Home` — один к одному, `Shift+F` — вписать всё, включая
  уехавшее за границу экрана. Подложка (0…1) гасит игру под интерфейсом:
  меню верстают на ровном фоне, худ — поверх игры.
- **Слева — дерево элементов**: только сущности с `ui::Element`, с глазком
  видимости и стрелками порядка среди соседей, плюс две кнопки создания —
  «Элемент» и «Контейнер», продублировать, удалить. Новый элемент становится
  ДОЧЕРНИМ к выделенному. **Перетаскивание не теряет элемент**: бросок в себя
  или в своего потомка отвергается с подсказкой прямо у курсора
  (`sage::ui::CanReparent`), «в корень» — это главный контейнер интерфейса
  (`sage::ui::ReparentElement`), и каждое перетаскивание — одна запись в
  истории отката.
- **Справа — выравнивание, распределение, быстрые действия** и **свойства**
  элемента: тип и стиль, вид типа (у кнопки — вид каждого состояния), раскладка
  контейнера, поведение, положение (у ребёнка ряда — «В контейнере»), события.
  Свойства — ТОТ ЖЕ модуль, что рисует инспектор (`UIElementProperties.h`), а
  не вторая копия полей: два редактора одного компонента разошлись бы на первой
  же новой галке.
- **Сверху — сетка и привязки**: показ сетки, притяжка к ней с шагом, притяжка
  к краям и центрам соседей, рамки всех элементов.

Мышью работает `UICanvas` (`editor/src/UICanvas.cpp`): выбор, перетаскивание,
восемь ручек размера, рамка выделения, стрелки для доводки на пиксель,
направляющие привязки и подписи расстояний до краёв родителя. Математика
привязок — в движке (`sage/ui/UILayoutTools.h`) и покрыта юнит-тестами.

Преобразование «пиксель кадра ↔ пиксель панели» теперь записано ОДИН раз — в
`UICanvas`. Пока холстом был вьюпорт, та же формула жила и в рендерере
(он сам масштабировал холст), и обе половины надо было держать в согласии:
разойдись они на пиксель — мышь ловит не то, что видно.

## Твины (интерполяция значений)
Твины — одна система на весь движок (`sage/anim/Tween.h`), описана в
[анимации](animation.md#твины-быстрое-изменение-свойства-без-клипа). Для
интерфейса важно: у элемента твинятся положение, размер, поворот, **масштаб** и
**непрозрачность** (`Element::Scale` и `Element::Opacity` — рисуются вокруг
центра и множатся на прозрачность групп, раскладку не трогают), цвет заливки,
картинки и текста, кегль, скругление — всё, что есть в реестре свойств.

    Tween.to(button, "opacity", 0, 0.25, Ease.Out)
    Tween.to(button, {scale = 1.1}, 0.15, Ease.OutBack)

## Наборы интерфейса: спрайты из листа, девятина, фильтрация
Готовый UI-набор с itch.io — это один PNG на всё: рамки, кнопки, слоты, иконки
и шкалы лежат в общем листе. Чтобы такой набор можно было ВЗЯТЬ И
ИСПОЛЬЗОВАТЬ, движку нужны три вещи; без любой из них набор приходится резать
на сотню файлов вручную и всё равно получать мыло.

* **Спрайт — кусок листа в ПИКСЕЛЯХ исходника.** `Sprite = {x, y, w, h}` у
  `UI Element` (в Lua — `SetUISprite`). Именно в пикселях, а не в UV: в
  документации набора написано «26x26 начиная с (52,0)», и переводить это в
  доли текстуры должен движок.
* **Девятина (9-slice).** Панель нарисована как 26x28 с уголками по 8 пикселей.
  Растянуть её на 372x240 обычным квадом нельзя — углы размажутся вместе с
  серединой. `SliceBorder = {лево, верх, право, низ}` режет спрайт на девять
  кусков: углы рисуются как есть, края тянутся по одной оси, середина по обеим.
  `PixelScale` — во сколько раз пиксель исходника крупнее экранного (для
  рисунка по пикселям целое, иначе рамка идёт волнами). Подробности — в разделе
  [«Девятина»](#девятина-как-растягивать-картинку-рамку) ниже.
* **Пропорции картинки — режим, а не подгонка размеров.** Поле «Как ложится»
  (`Image::Mode`) знает пять значений: `Stretch` (растянуть под элемент),
  `9-slice`, `Tile`, а также два, сохраняющих соотношение сторон:
  **«Сохранять пропорции»** (`Fit`) показывает картинку ЦЕЛИКОМ, оставляя поля
  по краям, и **«Заполнить, сохраняя пропорции»** (`Cover`) занимает элемент
  без полей, отрезая лишнее по длинной стороне. Растяжение делает из портрета
  в широкой кнопке блин, а из герба 1:1 в полосе — овал; до этих режимов
  единственным лекарством было подбирать размер элемента под каждую картинку
  руками — и заново при её смене. Обрезка у `Cover` делается ИСХОДНИКОМ (из
  него берётся кусок нужных пропорций от середины), а не рисованием за
  границами элемента: обрезки у элемента может не быть, и картинка вылезла бы
  на соседей. Арифметика обоих режимов лежит отдельно (`sage/ui/ImageFit.h`) —
  ею же вписываются обложки ассетов в редакторе, чтобы «сохранять пропорции»
  не означало в двух местах разное.
* **Замощение с числом повторов.** В режиме `Tile` поле «Число повторов»
  (`Image::Repeat`, у вида — `Look::Repeat`; в Lua — `ui.Repeat`) задаёт,
  сколько копий уложить по ширине и высоте элемента, по осям отдельно; дробное
  число обрезает последнюю копию вместе с куском исходника. 0 по оси — картинка
  своим размером (× «размер пикселя исходника»), как было. Раскладка —
  `ui::SolveTiles` и `ui::TileSize`, проверяются числами.
* **Режим из скрипта** — `ui.Fit = "tile"` (`stretch`, `nineslice`, `tile`,
  `fit`, `cover`): земляной фон меню — плитка `tile` с `PixelScale`.
* **Фильтрация.** Поле «Фильтрация» (`Image::Filtering`, значения `Smooth` и
  `Nearest`; в Lua — `ui.Filter = "nearest"`) — на виду, не в «Ещё настройках».
  Тип фильтрации один на весь движок (`sage::TextureFiltering`,
  `sage/render/TextureFiltering.h`): тот же выбор у материала, шрифта, неба и
  частиц. `Nearest`
  грузит текстуру ближайшим соседом, без мипмапов и с целым масштабом на
  отрисовке: сглаживание превращает набор спрайтов в кашу, а мипмапы ЛИСТА ещё
  и подмешивают в края соседний спрайт. Фильтрация запоминается вместе с
  текстурой, и запрос той же картинки с другими настройками пересоздаёт её на
  месте.

  **Кратный масштаб — отдельная настройка** («Кратный масштаб»,
  `Image::SnapPixels`; в Lua — `ui.SnapPixels`). Округление масштаба до целого
  включалось заодно с резкой фильтрацией, и снаружи это выглядело так:
  переключаешь фильтрацию — резкость не меняется, зато картинка становится «на
  пиксель меньше», то есть единственным видимым следствием настройки было
  побочное. Это разные вопросы: фильтрация — чем сглаживать; кратный масштаб —
  можно ли рисовать пиксель исходника дробным числом экранных (при 3.125 одни
  штрихи растягиваются на четыре пикселя, соседние на три, и ровная рамка идёт
  волнами). Цена кратного масштаба — элемент заполняется не целиком, поэтому
  это выбор, а не следствие. Сцены переводит миграция формата 15: что было
  резким, продолжает считаться целым масштабом.

  **Размер пикселя исходника** (`PixelScale`) — сколько экранных пикселей
  занимает один пиксель файла; 0 — подогнать под элемент (то есть растянуть).
  Нужен наборам спрайтов: рамка 48x48, растянутая на 300x120, превращается в
  мыло, а при масштабе 3 её рисунок сохраняет свой размер.

  Движок не знает, нарисована картинка по пикселям или снята фотоаппаратом, —
  он знает, какой фильтр включить, поэтому настройка называется фильтрацией, а
  не жанром. Старые сцены с галкой `pixelArt` переводятся миграцией формата 14
  (`pixelArt: true` → `filter: 1`).

```lua
SetUIImage(panel, "assets/ui/basic.png", true) -- true = резкая фильтрация (Nearest)
SetUISprite(panel, 11, 11, 26, 28)             -- кусок листа
SetUISlice(panel, 8, 8, 8, 9, 3)               -- углы + масштаб пикселя
local w, h = ImageSize("assets/ui/basic.png")  -- размер листа для нарезки
```

Всё это настраивается и в инспекторе редактора (секция Image у `UI Element`),
и рисуется одинаково в редакторе и в собранной игре.

### Проверено на пиксельном интерфейсе

Пиксельный набор интерфейса (панель быстрого доступа, сердца, еда, полоса опыта, окно крафта из
атласа 512×512, кнопка-девятина по её `.mcmeta`) и пиксельный шрифт с
кириллицей собираются ОБЫЧНЫМИ частями, без единой строки особого кода:
кусок атласа — `Sprite`, кнопка — девятина с `PixelScale`, резкость —
`Nearest`, шрифт — `Label::Font` + `Nearest` + кратный масштаб, частичная
полоса опыта — картинка с урезанным `Sprite` в элементе нужной ширины.

Не хватило двух вещей, обе теперь есть:

* **тени и обводки текста** (в пиксельном интерфейсе весь текст с тенью на пиксель, цифры
  уровня — в обводке) — см. [«Текст и шрифты»](#текст-и-шрифты-truetype-и-картинкой);
* **целого масштаба холста** — `Canvas` в режиме «Целый масштаб»
  (`Canvas::Scale::IntegerFit`; в Lua —
  `ui.SetCanvas(root, {pixelScale = true, reference = Vec2(320, 240)})`).
  Масштаб — наибольшее целое, при котором опорный экран помещается в окно
  (1280×720 при опоре 320×240 — 3, 1920×1080 — 4), `MaxScale` ограничивает его
  сверху (как «масштаб интерфейса 2» в настройках игры). Дробный масштаб
  «подгонки под опорное разрешение» рисует одни пиксели картинки двумя
  экранными, а соседние одним — рамки идут волнами. Вёрстка при этом ведётся
  в логических пикселях набора.

## Лист спрайтов: картинка, нарезанная на именованные куски

Набор интерфейса или предметов — один PNG. Кусок по прямоугольнику брался и
раньше (`SetUISprite`), но числа писались руками в каждом месте. Лист
описывает нарезку ОДИН раз рядом с картинкой — `gui.png.sagesheet` (JSON: имя,
прямоугольник от левого верхнего угла и, если кусок — рамка, его девятина).

- **Окно «Нарезка спрайтов»** (меню «Окно», раздел инструментов): картинка —
  слотом; «Нарезать сеткой» (клетка, промежуток, поле, начало имени; пустые
  клетки пропускаются), «Найти куски» (каждый остров непрозрачных пикселей —
  кусок), щелчок по куску — имя, прямоугольник, девятина; «Сохранить».
- **Из скрипта:**

```lua
SetUISpriteNamed(slot, "assets/ui/gui.png", "slot")  -- картинка, кусок и девятина разом

local sheet = sprite_sheet("assets/ui/gui.png")      -- описание из .sagesheet
sheet.grid{w = 16, h = 16, pad = 2, prefix = "icon"} -- нарезать сеткой
sheet.auto{prefix = "piece"}                         -- по островам
sheet.set("panel", 0, 0, 16, 16, {4, 4, 4, 4})       -- кусок с девятиной
local r = sheet.rect("panel")                        -- {x, y, w, h, slice}
sheet.save()
```

Кусок с девятиной ложится в режиме «9-slice» сам. Ядро — `sage/ui/SpriteSheet.h`
(проверки `tests/test_spritesheet.cpp`).

## Девятина: как растягивать картинку-рамку

Геометрия нарезки живёт отдельно от рисования — `sage/ui/NineSlice.h`
(`sage::ui::Solve`). Это не украшение: раскладка девяти кусков — чистый счёт, и,
пока он был внутри функции отрисовки, единственным способом заметить ошибку был
взгляд на экран. Теперь её проверяет `tests/test_nineslice.cpp` — в том числе
случаи, которые видны не на всяком размере: рамка не вылезает за пределы
элемента, ужимается пропорционально на прямоугольнике уже собственных углов и
не выворачивается наизнанку.

**Масштаб пикселя по умолчанию — один к одному.** Раньше «не задан» у
девятины значило «подогнать под высоту элемента»: углы рамки 48x48 на кнопке
высотой 120 раздувались в два с половиной раза — углы тянулись вместе с
элементом, и снаружи это выглядело как «девятина не работает». Теперь пиксель
исходника — пиксель интерфейса (умноженный на масштаб холста), и угол остаётся
своего размера при любом размере элемента (`sage::ui::SlicedPixelScale`).
Крупнее — поле «размер пикселя».

Что умеет нарезка сверх четырёх чисел:

| Свойство | Зачем |
|---|---|
| `SliceEdgeFill`, `SliceCenterFill` — `Растянуть` / `Повторить` | У рисунка по пикселям растянутый край превращается в мыло: орнамент из 16 пикселей, растянутый на 300, перестаёт быть орнаментом. Правильный ответ — повторить кусок. Обрезанный последний повтор обрезает и кусок исходника, иначе хвост показывал бы не ту часть картинки. |
| `SliceDrawCenter` | У рамки-обводки середины нет: сквозь неё видно то, что под элементом. Отдельный флаг, а не «нулевая середина»: её размер считается из полей, и обнулить его, не сломав края, нельзя. |

### Описание живёт рядом с картинкой (`.sage9`)

Пока нарезка была четырьмя числами В ЭЛЕМЕНТЕ, одна и та же рамка на десяти
элементах означала десять копий одних и тех же чисел — и поправить её значило
найти все десять. `panel.png.sage9` описывает нарезку ОДИН раз; редактор
подхватывает его сам при выборе картинки, а скрипт берёт одной строкой:

```lua
SetUIImage(panel, "assets/ui/panel.png", true)
LoadUISlice(panel)              -- нарезка из panel.png.sage9
SetUISliceTiled(panel, true)    -- повторять, а не растягивать
SetUISliceDrawsCenter(panel, false) -- рамка-обводка без середины
```

Сайдкаром, а не заменой расширения: рядом могут лежать `panel.png` и
`panel.jpg`, и одно описание на двоих было бы неверным для обоих.

### Редактор девятины

Открывается кнопкой «Править по картинке…» у поля девятины любого вида (или
из меню «Окно» — тогда правится картинка и её `.sage9`). Окно правит ЭТОТ вид
ЭТОГО элемента **вживую**: тянешь линию — меняется элемент в сцене, каждое
движение — одна запись в истории отката.

- **Слева — картинка** (или её кусок из листа) с четырьмя линиями поверх.
  Углы, края и середина закрашены разными цветами, легенда рядом. Колесо —
  увеличение, средняя кнопка — сдвиг.
- **Справа — числа** (целые пиксели исходника), заполнение краёв и середины,
  «рисовать середину».
- **Предпросмотр** в размере самого элемента (размер можно поменять), тем же
  `sage::ui::Solve`, что и игра. Крупный элемент показывается уменьшенным
  целиком.
- **«Подобрать»**, **«Сохранить/Загрузить .sage9»**.

Раскладка — таблицей и дочерними окнами с прокруткой: при любой ширине окна
ничего не выходит за его края (прежнее окно в узком виде писало в консоль
тысячи строк «Code uses SetCursorPos() to extend window/parent boundaries»).
Самопроверка редактора открывает окно узким и проверяет, что ошибок ImGui нет.

Кнопка появляется у поля не по его имени, а по пометке в таблице части
(`PartField::Widget::NineSliceBorder`) — часть ИГРЫ со своей девятиной
получает её сама.

**Шрифт интерфейса** задаётся в настройках (`ui.font`, `ui.fontPixelHeight`,
`ui.fontFiltering` в `sage.cfg`), потому что `UIRenderer` создаёт движок и у игры
нет места, где вклиниться до первого кадра.

* `fontFiltering` — `"smooth"` или `"nearest"` (старая галка `fontPixelArt`
  читается как `"nearest"`). При `"nearest"` атлас берётся `Nearest`, без
  мип-уровней, а масштаб на отрисовке округляется до ЦЕЛОГО. Полупиксельное
  увеличение растягивает одни штрихи буквы на два экранных пикселя, а соседние
  на один — «M» выходит с ножками разной толщины, и весь текст идёт волнами.
* Символы, которых в шрифте НЕТ, в атлас не попадают: иначе stb запекает для
  них `.notdef` (рамка или «?»), глиф выглядит настоящим, и «шрифт не знает
  кириллицы» становится неотличимо от «знает». При загрузке шрифта без
  кириллицы движок предупреждает в лог — иначе русские надписи молча
  превращаются в ряд вопросительных знаков, и ошибку ищут в движке.
* Межстрочный интервал берётся у ШРИФТА (`UIRenderer::LineHeight`), а не из
  номинальной высоты строки: на пиксельном шрифте с целым масштабом глиф вдвое
  выше номинала, и абзац, разложенный по номиналу, налезает сам на себя.

## Интерактивный интерфейс: поля ввода, галки, ползунки
Рисовать интерфейс мало — в него надо тыкать. `sage::ui::UpdateSceneUI(scene,
input, w, h)` за кадр разбирает подсветку, нажатия, фокус, набор текста и
перетаскивание, и возвращает, что интерфейс СЪЕЛ:

```cpp
sage::ui::UIInputState in;   // мышь + символы от оконной системы
in.Mouse = {mx, my}; in.MousePressed = pressed; in.TypedText = typed;
sage::ui::UIInputResult r = sage::ui::UpdateSceneUI(scene, in, w, h);
if (r.WantsMouse) { /* игре этот щелчок не отдаём */ }
```

Виды элементов: `Input` (поле ввода — подсказка, предел длины, режим пароля,
мигающий курсор), `Checkbox`, `Slider` — плюс прежние `Panel/Label/Image/Bar/
Icon`. Любому из них флаг `Interactive` включает подсветку и нажатие, `Enabled`
— выключает; `SpriteHover`/`SpritePressed` подменяют спрайт под состояние (в
наборах кнопка нарисована трижды, и подменить картинку правильнее, чем
осветлить основную). Скрипт читает `Clicked`/`Changed` — флаги на ОДИН кадр.

Три решения, без которых это не работает:

* **Ввод приходит СТРУКТУРОЙ, а не опросом устройств внутри UI.** Интерфейс
  живёт и в игре, и в панели Game редактора (там мышь пересчитана в панель), и
  в тестах без окна. Опрашивай он устройства сам — он был бы привязан к GLFW, а
  редактор не смог бы отдать ему свои координаты. Заодно весь интерактив
  тестируется без единого окна (см. `tests/test_ui.cpp`).
* **Текст приходит СИМВОЛАМИ, а не клавишами.** Раскладка, Shift, мёртвые
  клавиши и композиция превращают нажатия в символы по правилам системы;
  повторять их в движке — значит получить ввод, работающий только на английской
  раскладке. Курсор при этом ходит по СИМВОЛАМ UTF-8, а не по байтам: шаг в
  байт разрезал бы кириллическую букву пополам.
* **Щелчок — это нажать И отпустить НА элементе.** Увести курсор с кнопки и
  отпустить — общепринятый способ передумать, и ломать его нельзя.

`WrapText` переносит длинный текст по ширине элемента (по словам, слишком
длинное слово — по символам) и обрезает его своим прямоугольником, если он не
влез по высоте: абзац, вылезший из панели на фон, выглядит хуже обрезанного и
читается как ошибка вёрстки.

**Сглаживание краёв** считается по производной SDF (`fwidth`), а не по
константе: константа верна ровно при одном масштабе интерфейса, на другом край
получается либо зубчатым, либо мыльным.

### Поворот элемента

`Element::Rotation` поворачивает элемент целиком — подложку, буквы И картинку.
Поворот картинки пропускался: её квад складывался из неповёрнутых углов, и у
кнопки поворачивалось всё, кроме её значка. Снаружи это читалось как
«изображение не поворачивается вообще».

## Текст и шрифты (TrueType и картинкой)
Текст в игровом интерфейсе рисует `UIRenderer` (`engine/src/sage/ui/`)
настоящим **TrueType-шрифтом** через класс `Font`
(`engine/src/sage/render/Font.*`, на базе
[stb_truetype](https://github.com/nothings/stb)). При создании `UIRenderer`
запекает глифы в атлас-текстуру (R8) и печатает текстурными квадами:

- **Unicode/UTF-8** — строки в `Text/TextCentered` декодируются как UTF-8, из
  коробки запечены латиница (Basic Latin + Latin-1), **кириллица** и типографская
  пунктуация (тире, кавычки, «…»). Игровые надписи можно писать по-русски —
  `games/testgame` так и делает (нижняя подсказка HUD).
- **Шрифт по умолчанию** — `engine/assets/fonts/sage-default.ttf` (DejaVu Sans,
  свободная лицензия Bitstream Vera). `sage_add_game()` копирует его рядом с
  каждой игрой автоматически, так что текст работает без ассетов в самой игре;
  если файл не найден, `UIRenderer` пробует системные шрифты, а в последнюю
  очередь откатывается на встроенный векторный `stb_easy_font` (ASCII-only) —
  движок рисует текст в любом случае.
- **Свой шрифт ВСЕГО интерфейса** — `ui.SetFont("assets/fonts/my.ttf",
  pixelHeight)`; метрики масштабируются от базовой высоты запекания,
  `MeasureText` учитывает пропорциональную ширину глифов.
- **Свой шрифт У ОТДЕЛЬНОЙ НАДПИСИ** — поле «Файл шрифта» у части «Текст»
  (`Label::Font`, в Lua — `ui.Font`). Пока шрифт был один на всю игру,
  «заголовок рубленым, а письмо рукописным» было нечем сделать: либо меняешь
  шрифт везде, либо не меняешь. Рядом — «Размер запекания шрифта»
  (`FontPixelHeight`: чёткость атласа, а не кегль) и «Пиксельный шрифт»
  («Фильтрация шрифта» — `FontFiltering`: `Nearest`, без мипмапов и с целым
  масштабом). Путь
  разрешается ТАК ЖЕ, как у картинки элемента, — через базу ассетов
  (`LocatePath`), иначе шрифт был бы виден в редакторе и пропадал в собранной
  игре. Файлы шрифтов запоминаются: одна надпись рисуется каждый кадр, и
  перечитывать файл было бы разорительно; не открывшийся файл жалуется в лог
  ОДИН раз и дальше молчит.
- **Шрифт-картинка (.png).** Пиксельные игры часто несут шрифт не TrueType-
  файлом, а листом символов: PNG, сетка 16×16 ячеек. `Font::Load` узнаёт его
  по расширению (`Font::LoadImageSheet`, `render/FontImage.cpp`) — путь в
  `ui.Font`/`ui.SetFont` такой же, как у `.ttf`. Ячейка N — символ N
  (Latin-1) или порядок из файла `<имя>.chars` рядом (UTF-8, символы подряд,
  U+0000 — пустая ячейка). Ширина символа читается по пикселям: последний
  непустой столбец ячейки → `round(ширина · 8 / ячейка) + 1` единиц восьмой
  доли ячейки (последняя — промежуток), пробел — 4 (`ImageFontUnits`).
  Высота строки — 9/8 ячейки, базовая линия — 7/8; фильтр — всегда
  «ближайший пиксель». Растеризовать такой лист через TrueType-копию значило
  бы получить «почти тот же» шрифт — другие ширины и кромки.
- **Кегль значит то, что написано.** Высота строки на экране — ровно
  `TextHeight(scale)` = 8·кегль пикселей у ЛЮБОГО файла шрифта: множитель
  глифа нормируется по высоте строки шрифта (`FontScale`), а не по высоте
  запекания атласа. Пока номинал вёрстки и реальная строка расходились,
  вёрстка мерила блок одним числом, а рисовала его другим — надпись съезжала
  вверх тем сильнее, чем крупнее кегль, и от смены шрифта ехал весь экран.
  Высота блока и центрирование (в том числе в поле ввода и у каретки)
  считаются по высоте строки шрифта.
- **Кратный масштаб шрифта** (`Label::FontSnapPixels`, в Lua —
  `ui.FontSnapPixels`) — отдельно от фильтрации, как и у картинки. Раньше
  округление масштаба глифа до целого включалось само у резкого шрифта, и это
  давало худший ответ на попытку изменить кегль: у мелких размеров масштаб
  упирался в единицу — текст стоял на месте и вдвое крупнее заданного, — а
  потом скачком удваивался. Сцены переводит миграция формата 16.
- **Начертание** — «Начертание» (`Label::Face`): обычный, жирный, курсив,
  жирный курсив; в Lua — `ui.Bold` и `ui.Italic`. Рисует их сам движок: жирный
  — вторым оттиском со сдвигом на доли кегля, курсив — наклоном глифов на 12°
  ОТНОСИТЕЛЬНО БАЗОВОЙ ЛИНИИ (вокруг верха строки уехал бы весь низ букв).
  Так сделано потому, что настоящие жирный и курсив — это ОТДЕЛЬНЫЕ файлы
  шрифта, а у половины бесплатных наборов есть только одно начертание;
  назначить свой `*-Bold.ttf` отдельным шрифтом по-прежнему можно, и выйдет
  лучше. Ширина строки учитывает и сдвиг жирного, и наклон курсива — иначе
  перенос и выравнивание по правому краю срезали бы последнюю букву.
- **Пределы кегля и отступа.** «Размер шрифта» — 0.1…128 (было 0.5…12, то есть
  около сотни экранных пикселей потолка: заголовок на весь экран задать было
  нечем, поле не пропускало даже введённое число), «Боковой отступ» — 0…512
  (было 0…64).
- **Выравнивание надписи из скрипта** — `ui.TextAlign` и `ui.TextVAlign`:
  `"start"`, `"center"`, `"end"`. Число в правом нижнем углу ячейки —
  `TextAlign = "end"`, `TextVAlign = "end"`. `ui.TextCentered` работает как раньше.
- **Тень и обводка текста** — «Сдвиг тени» / «Цвет тени» и «Толщина обводки» /
  «Цвет обводки» у части «Текст» (`Label::ShadowOffset`, `ShadowColor`,
  `OutlineWidth`, `OutlineColor`; в Lua — `ui.TextShadowOffset`,
  `ui.TextOutline` и цвета). Тень — копия текста под ним со сдвигом, обводка —
  восемь копий по кругу (четырёх не хватает: на диагоналях остаются просветы).
  У шрифта с целым масштабом сдвиги округляются до целых пикселей — дробная
  тень пиксельного шрифта выглядит грязной каймой. Раньше это собиралось
  ВТОРОЙ надписью, сдвинутой руками, и правка текста требовала править обе.
- **Несколько шрифтов в одном кадре** батчатся по атласу: у сегмента отрисовки
  есть поле «чей шрифт» (`UIRenderer::Segment::TextFont`). Без него глифы
  второго шрифта брались бы из картинки первого — то есть текст выходил бы
  кашей из случайных букв.

Редактор `SageEditor` рисует свой UI через ImGui (у него собственная загрузка
шрифта с кириллицей — `EditorTheme::LoadFont`), поэтому `Font`/`UIRenderer` —
это именно текст ВНУТРИ игры, не редактора.
