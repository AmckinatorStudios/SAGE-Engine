# Visual Scripting

Игровая логика объектов узлами и проводами. Visual Scripting и
[SAGE AI Graph](ai.md) — одна система визуального программирования с общей
основой и разными наборами узлов; Lua — язык программирования и расширения
обоих.

## Три способа и как они делят работу

| Способ | Для чего | Где |
|---|---|---|
| Visual Scripting | игровая логика общего назначения: двери, подбор, триггеры, интерфейс | `assets/visual/*.vgraph`, компонент **Visual Script** |
| SAGE AI Graph | поведение персонажей: решения, задачи, параллельное поведение | `assets/ai/*.aigraph`, компонент **AI** |
| Lua | функции, задачи, расширение обоих редакторов | `.lua` скрипты и библиотека `assets/ai`, `assets/visual` |

Все три работают в одном проекте и вызывают друг друга.

## Общая основа и разные наборы узлов

Одинаково в обоих редакторах: холст, создание и соединение узлов, палитра с
поиском и разделами, контекстные меню, типы данных и проверка совместимости
проводов, переменные (local, instance, shared, входы и выходы), проверка
графа, вывод выполнения, точки останова, подсветка и значения пинов в Play.

Разное — **набор узлов**. У каждого узла есть назначение
(`sage::ai::NodeDomain`):

| Назначение | Примеры | Где доступен |
|---|---|---|
| общий | Branch, Sequence, циклы, Wait, математика, сравнения, переменные, списки, структуры, объекты, Raycast, API движка, Call Function, Log | везде |
| ИИ | Call / Run / Wait For / Cancel Task, Task Status, Parallel, Emit Event (ИИ) | SAGE AI Graph |
| скрипт | On Start, On Update | Visual Scripting |

Палитра каждого редактора предлагает только свои и общие узлы; проверка
графа и запуск отказывают узлу чужого назначения с понятной причиной.
Инструменты ИИ (окно «Отладчик ИИ» с деревом задач) — только у SAGE AI Graph.

## Визуальный скрипт объекта

«Добавить компонент → Logic → Visual Script», граф — слотом (перетащить
`.vgraph`), ниже — переменные объекта (область Instance графа). В Play:

- **On Start** — один раз при старте объекта;
- **On Update** — каждый кадр, выход `dt`. Новый кадр не заводится, пока
  предыдущий ещё ждёт (Wait внутри On Update не плодит ветки);
- **On Event** — событие игры (`sage.events`), в том числе посланное узлом
  **Emit Game Event**, скриптом Lua или графом ИИ.

Объект удалили — его скрипт уходит вместе с ним. Из Lua:
`visual.of(obj).vars.locked = false`, `.emit(...)`, `.stop()`.

## Графы-функции — общая библиотека

Граф вида `function` — переиспользуемый блок для **обоих** редакторов: в нём
только общие узлы, его зовёт узел **Call Function** и в Visual Scripting, и в
SAGE AI Graph, а библиотека каждого редактора видит функции из обеих папок.
Так одинаковое не приходится делать дважды. Свои типы данных (`ai.type` /
`visual.type`) — тоже одна таблица на всех.

## Lua и визуальные графы

```lua
-- вызвать граф-функцию: выходы в тот же вызов (если функция не ждёт)
local out = visual.call("DamageFormula", {base = 10, armor = 3})
print(out.result)

visual.functions()        -- имена графов-функций
visual.graph(path)        -- загрузить граф
visual.of(obj)            -- выполнение Visual Script объекта
```

Из графа в Lua: **Call Lua Function** (любая глобальная функция по пути),
**Call Script** (функция скрипта объекта), **Call Operation**
(`ai.operation`), узлы API движка. Задачи на Lua зовёт SAGE AI Graph (Run
Task) — по правилам SAGE AI.

## Свои узлы и инструменты

```lua
-- assets/visual/mygame.lua
visual.node("game.add_score", {          -- узел Visual Scripting
    title = "Add Score", category = "My game",
    inputs = {{"points", "int", 1}},
    run = function(n) score = score + n.inputs.points end,
})
ai.node("game.threat", {pure = true, ...})                 -- узел SAGE AI Graph
ai.node("game.distance2d", {domain = "both", pure = true, ...})   -- обоим
```

`domain` — `"ai"`, `"script"` или `"both"`; без него — для того редактора,
чья функция (`ai.node` / `visual.node`). Остальное — как в
[ai.md](ai.md#свои-узлы-типы-и-правила-на-lua).

Плагин редактора: `editor.graph_pin(тип, fn)` — своё поле значения;
`editor.graph_tool(подпись, fn, {editor = "visual"})` — кнопка на панели
одного редактора (без `editor` — обоих).

## Редактор: проверка, вывод, отладка

«Окно → Visual Script» или двойной щелчок по `.vgraph` в Assets. Под холстом:

- **Проблемы** — проверка графа до Play: узел не того редактора, неизвестный
  узел, несовместимый провод, несуществующая переменная, невыбранная функция,
  узел, до которого не дойдёт поток. Узел с ошибкой обведён красным, знак «!»
  в заголовке объясняет причину; щелчок по строке — к узлу. Граф с ошибкой не
  запускается — та же проверка (`sage::ai::ValidateGraph`).
- **Вывод** — что граф сделал в Play: Log, ошибки узлов, конец выполнения с
  причиной.

Отладка на холсте (подсветка, значения пинов, F9, F10) — та же, что у
SAGE AI Graph.

## Как это устроено

- Документ (`GraphDoc`), выполнение (`GraphBehavior`), типы, переменные,
  проверка и отладчик — общие (`engine/src/sage/ai/`). Визуальный скрипт —
  граф вида `script`, его выполняет тот же мир, что и ИИ, от имени
  компонента Visual Script (`ScriptEngine::UpdateVisualScripts`).
- Назначение узла — `NodeType::Domains`; правило «можно ли узлу в граф этого
  вида» — одно (`sage::ai::NodeAllowed`) для палитры, проверки и запуска.
- Редактор — один класс `AiGraphPanel` в двух режимах (`GraphEditorMode::Ai`
  и `::Visual`): общий холст и инструменты, свои виды графов, папка и набор
  узлов.

Проверки: `tests/test_visual_script.cpp`, самопроверка редактора
`visual-script`, кадровая `AI_GRAPH` (рисует оба окна).
