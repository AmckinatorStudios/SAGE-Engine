# Script Graph

Визуальное программирование игровой логики объектов: события, условия,
переменные, функции и игровые действия — узлами и проводами, без обязательного
кода. Поведение ИИ строится в отдельном инструменте — [AI Graph](ai.md).

## Три инструмента логики

| Инструмент | Файл | Для чего |
|---|---|---|
| SAGE Lua | `.slua` | текстовая игровая логика |
| **Script Graph** | `.sgraph` | визуальная игровая логика объектов |
| AI Graph | `.aigraph` | поведение ИИ: задачи, условия, управление поведением |

Создаются окном «Создать…» (меню панели Assets «Скрипт или граф…» или «+» у
слота): компактный список с разделами «Скрипты» и «Искусственный интеллект».
Тип однозначно задаёт файл, редактор, набор узлов и правила выполнения;
созданный граф сразу открывается в своём редакторе. Обычный Lua и Visual
Script прежних версий новыми файлами не создаются.

## Файл и компонент

Script Graph — файл `.sgraph` (JSON), по умолчанию в `assets/visual`. Новый
граф создаётся с событиями On Start и On Update.

«Добавить компонент → Logic → Script Graph» (или перетащить `.sgraph` на объект
в иерархии или во вьюпорте): граф и **переменные объекта** (область Instance).
Объект удалили — его граф уходит вместе с ним. Из Lua:
`visual.of(obj).vars.locked = false`, `.emit(...)`, `.stop()`.

Вид графа задаёт расширение: `.sgraph` — только Script Graph (объекта или
функция). Файл с видом `behavior` внутри `.sgraph` не загружается — ошибка с
причиной.

## Раздельные наборы узлов

| Назначение | Где | Примеры |
|---|---|---|
| Игровая логика | Script Graph (объект и функция) | Branch, Sequence, циклы, Wait, переменные, математика, игровые действия, Call Function |
| События объекта | Script Graph объекта (не функция) | On Start, On Update, On Fixed Update, On Collision, On Trigger, On Signal |
| ИИ | только AI Graph | Task Start, Decide, Task Sequence, Move To Target, условия ИИ |

Палитра показывает только допустимые узлы; проверка графа, загрузка и запуск
отказывают узлу не своего назначения и называют его. Общих узлов «на всякий
случай» нет — оба набора несёт только Reroute (излом провода).

## Узлы Script Graph

| Раздел | Узлы |
|---|---|
| События | **On Start**, **On Update** (`dt`), **On Fixed Update** (`dt`, постоянный шаг физики), **On Collision Enter / Exit**, **On Trigger Enter / Exit** (`other` — второй объект), **On Signal** (clicked, pressed, value_changed, сигнал скрипта…), **On Event** (событие игры `sage.events`), **Emit Game Event** |
| Поток | Start, Sequence, Branch, Loop While, For Loop, For Each, Break, Parallel, Wait, Wait Until, Wait For Event, Return, End Branch, Select |
| Переменные и данные | Get / Set Variable (local, instance, shared, input, output), математика, сравнения, логика, строки, векторы, повороты, списки, структуры |
| Игровые действия | Self, Find Object, Object Info, Distance To, Set Position, Look At, Move To, Get / Set Property (`Light.Intensity`, `Transform.Position`), Call Script, Raycast, Line Of Sight, Can See, Find Nearby, Find Path, узел на каждую функцию API движка |
| Функции | Call Function, Call Lua Function, Call Operation, Log |

On Destroy в Script Graph нет: граф объекта выполняется после удаления
объекта уже не может (исполнять нечем) — для этого есть хук `OnDestroy`
скрипта SAGE Lua.

## Как выполняется

- Узлы **с потоком** (треугольные пины) идут по порядку, **чистые** (только
  данные) вычисляются, когда их спросили, — каждый раз свежими.
- **On Update** и **On Fixed Update** не накапливают выполнения: новый кадр
  (шаг) не начинается, пока ветка прошлого ещё ждёт (Wait внутри не плодит
  копий). Три шага физики за кадр — три срабатывания On Fixed Update.
- События объекта приходят по шине сигналов сцены — тем же путём, что
  `crate.collision:connect(...)` в скрипте.
- Больше 10 000 узлов за кадр без ожидания — граф останавливается с причиной
  «похоже на бесконечный цикл», а не вешает игру.

## Функции

Граф вида «функция» (переключатель вида слева в редакторе, тот же `.sgraph`) —
переиспользуемый блок игровой логики: входы, выходы, без событий объекта. Его
зовёт узел **Call Function** с параметрами и результатами; из Lua —
`visual.call("DamageFormula", {base = 10})`. Функции ищутся в библиотеке
проекта (`assets/visual`, `assets/ai`).

## Lua и Script Graph

```lua
local out = visual.call("DamageFormula", {base = 10, armor = 3})   -- функция
visual.functions()        -- имена функций
visual.graph(path)        -- загрузить граф
visual.of(obj)            -- выполнение Script Graph объекта
```

Из графа в Lua: **Call Lua Function**, **Call Script** (функция скрипта
объекта), **Call Operation** (`ai.operation`), узлы API движка.

## Свои узлы и инструменты

```lua
-- assets/visual/mygame.slua (или .lua)
visual.node("game.add_score", {          -- узел Script Graph
    title = "Add Score", category = "My game",
    inputs = {{"points", "int", 1}},
    run = function(n) score = score + n.inputs.points end,
})
ai.node("game.threat", {pure = true, ...})                      -- узел AI Graph
ai.node("game.distance2d", {domain = "both", pure = true, ...})  -- обоим
```

`domain` — `"script"`, `"ai"` или `"both"`; без него — для редактора той
функции, которой объявлен узел. Плагин редактора: `editor.graph_pin`,
`editor.graph_tool(подпись, fn, {editor = "visual"})`, `editor.logic_kind` —
свой язык в окне «Создать…».

## Редактор

«Окно → Script Graph», двойной щелчок по `.sgraph` или перетаскивание файла в
окно. Холст с поиском узлов в палитре (по названию и разделам), проверка
проводов до соединения, выделение, группы, комментарии, Reroute, отмена,
сохранение положения узлов в файле. Под холстом:

- **Проблемы** — проверка до Play: узел не своего графа, неизвестный узел,
  несовместимый провод, нет переменной, не выбрана функция, нет события, узел,
  до которого не дойдёт поток. Узел с ошибкой обведён красным, знак «!»
  объясняет причину, щелчок по строке — к узлу. Граф с ошибкой не запускается.
- **Вывод** — Log, ошибки узлов, конец выполнения с причиной.

Отладка на холсте — подсветка шагов, значения пинов, F9 / F5 / F10.

## Старые файлы .vgraph

Visual Script прежних версий (`.vgraph`) **не создаётся**, но и не теряется:
файлы не переименовываются и не удаляются. Script Graph объекта и функции из
`.vgraph` открываются в редакторе Script Graph и работают в компоненте как
прежде (сохраняются в тот же файл). Граф задачи ИИ (`task`) из `.vgraph`
открывается с пометкой «старый формат»; узлы, ставшие узлами AI Graph, в нём
отмечаются ошибкой проверки — такую задачу переносят в AI Graph или на SAGE
Lua.

## Как это устроено

- Документ (`GraphDoc`), выполнение (`GraphBehavior`), типы и отладчик —
  общая основа (`engine/src/sage/ai/`); различаются вид графа, набор узлов
  (`NodeType::Domains`, `sage::ai::NodeAllowed`) и правила выполнения
  (события объекта — Script Graph; Task Start и результат корневой ветки — AI
  Graph).
- Вид графа по файлу — `sage::ai::CheckGraphFile` (загрузка, редактор).
- Компонент Script Graph запускает граф от имени объекта
  (`ScriptEngine::UpdateVisualScripts`), сигналы объекта подключает
  `ConnectVisualSignals`, постоянный шаг — `EmitVisualFixedStep`.
- Редактор — `AiGraphPanel` в двух режимах (`GraphEditorMode::Ai` и
  `::Visual`): своя палитра, папка, расширение и виды графов.

Проверки: `tests/test_visual_script.cpp`, `tests/test_ai_behavior.cpp`
(события Script Graph), самопроверка редактора `visual-script`, кадровая
`AI_GRAPH`.
