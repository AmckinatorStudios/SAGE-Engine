# Журнал изменений SAGE Engine

Список правок на пути от **0.5 к 1.0**. Версия до выхода 1.0 не меняется — в
файле `VERSION` остаётся `0.5.0`, — поэтому записи идут по датам, новые сверху.
Каждое слияние в `main` добавляет сюда свои строки (правило — в `CLAUDE.md`).
Подробности и причины — в `docs/`, здесь только что изменилось для того, кто
пользуется движком.

Разделы записи: **Исправлено** — то, что работало неправильно; **Добавлено** —
новые возможности; **Изменено** — то, что работает иначе и может потребовать
правки своих скриптов или сцен; **Ускорено** — производительность.

## 0.5.0 → 1.0 (в работе)

### 2026-10-31 (резкие и стабильные тени, рабочий и быстрый объёмный свет)

**Исправлено**
- Тени дрожали при движении камеры: привязка каскадов к сетке текселей не
  работала (центр округлялся в базисе, построенном от него самого). Теперь
  округление — в неподвижном базисе света, радиус каскада квантуется.
- Тени были одинаково мыльными по всей длине. Теперь полутень растёт с
  расстоянием до заслона: у основания предмета тень резкая, вдали — мягкая,
  как у настоящего солнца. Базовый фильтр уже (1.25 текселя вместо 1.75).
- Объёмный свет почти ничего не добавлял в кадр: лучи были видны только при
  взгляде прямо на солнце (g = 0.76), а воздух в тени не светился вовсе. Теперь
  g = 0.55 по умолчанию и дымка рассеивает свет неба — даль уходит в цвет
  неба, лучи отделены от тени.

**Добавлено**
- «Среда → Тени → Размер солнца» (`shadows.sunAngle`, по умолчанию 0.8°) —
  ширина полутени; 0 — резкие тени.
- `volumetricSkyScatter` в `sage.cfg` — доля неба, рассеянного дымкой.

**Ускорено**
- Тени: ранний выход по поиску заслонов — освещённый пиксель стоит 9 чтений
  карты вместо 32 на каскад (то же у теней ламп).
- Объёмный свет и облака — втрое с лишним быстрее (замер 138 → 43 мс): половина
  разрешения по умолчанию, одна выборка тени на шаг при накоплении, 24 шага,
  шум облаков из 3D-текстуры вместо хэша, дешёвая карта облаков, 4 шага света.

### 2026-10-31 (SAGE AI: AI Graph решает, задачи — в Visual Scripting и Lua)

**Добавлено**
- Узел Decide в AI Graph — выбор задачи по приоритетам: варианты с условием,
  приоритетом и «можно прервать», перепроверка раз в N секунд и на события,
  отдых варианта после конца (повтор после неудачи), выходы active/reason.
- Каналы задач и приоритеты (`ai.task{channels = {"legs"}, interruptible =
  false}`, `t.start(имя, входы, {priority = N})`, настройка Priority у Run/Call
  Task): задачи на разных каналах идут параллельно, на одном — более важная
  вытесняет прерываемую, иначе запуск не удаётся с причиной.
- Узел Move To (задачи и скрипты): движение к точке через контроллер
  персонажа объекта, выходы arrived/failed/distance.
- Профиль задач (`World::Stats()`, вкладка «Профиль» отладчика ИИ): запуски,
  шаги, время, самый долгий шаг, исходы.
- Отладчик ИИ: последнее решение у выполнения («почему выбрана эта задача»),
  фильтр истории «Решения».
- В графе задачи — «Занимаемые каналы» и «Можно прервать».
- `ai.node{domain = "task"}`; пример охранника целиком —
  `tests/test_ai_concept.cpp`.

**Изменено**
- AI Graph — только графы решений (вид Behavior); графы задач делаются в
  Visual Script (`assets/visual`). Граф задачи из старого проекта в
  `assets/ai` открывается в Visual Script сам и работает как раньше.
- Действия над миром (Set Position, Look At, Set Property, Call Script, Move
  To) — только в задачах и скриптах; управление задачами (Call/Wait/Cancel
  Task, Task Status, Emit Event ИИ) — только в AI Graph. Run Task и Parallel —
  общие. Граф с узлом не своего назначения не проходит проверку.
- `ai.node` без `domain` теперь доступен и графам задач Visual Scripting.
- Отмена задачи всегда с причиной (`World::Cancel(run, причина)`, «решение AI
  Graph: …», «прервана задачей … за канал …»).

**Исправлено**
- `LoadAiLibrary` с абсолютным путём не находил графы и Lua-файлы библиотеки.
- Задача ветки, снятой решением, отменялась только в конце шага — новая
  задача успевала «вытеснить» её за канал с неверной причиной.

### 2026-10-31 (Visual Scripting и общая система визуального программирования)

**Добавлено**
- Visual Scripting — игровая логика объекта узлами (docs/visual_scripting.md):
  окно «Visual Script», графы `assets/visual/*.vgraph`, компонент «Visual
  Script» (граф и переменные объекта), входы On Start и On Update (`dt`; новый
  кадр не стартует, пока прошлый ждёт), On Event, узел Emit Game Event
  (событие слышат скрипты, связи инспектора и графы).
- Общая основа с SAGE AI Graph: один редактор в двух режимах, общие документ,
  выполнение, типы, переменные и отладка; у каждого редактора — свой набор
  узлов (назначение узла: общий, ИИ, скрипт). Задачи ИИ в Visual Scripting не
  предлагаются и не запускаются, On Update — в графах ИИ.
- Графы-функции — общая библиотека обоих редакторов: узел Call Function,
  из Lua — `visual.call(name, inputs)` (выходы в тот же вызов),
  `visual.functions()`.
- Свои узлы: `visual.node` (Visual Scripting), `ai.node` (ИИ), `domain =
  "both"` — обоим; `visual.type` — общая таблица типов. Плагин:
  `editor.graph_tool(…, {editor = "visual"})`.
- Проверка графа до Play в обоих редакторах: панель «Проблемы» под холстом
  (неизвестный узел, узел не того редактора, несовместимый провод,
  несуществующая переменная, не выбрана задача или функция, узел, до которого
  не дойдёт поток), красная обводка и «!» у узла. Граф с ошибкой не
  запускается. Панель «Вывод» — Log, ошибки и конец выполнений графа в Play.

**Исправлено**
- Открытие другого графа больше не теряет несохранённые правки текущего.
- «Сохранить как» не перезаписывает другой граф с тем же именем.
- Переименование переменной графа переносит за собой узлы Get/Set Variable и
  пины Return; занятое имя не применяется.
- Переименование графа переносит его точки останова.
- Значение у пина обрезается по символам, а не по байтам (русский текст не
  ломается).
- «Показать в редакторе графов» из отладчика ИИ открывает граф в его
  редакторе; отладчик ИИ показывает только задачи ИИ.

### 2026-10-31 (тени всех ламп, хроматическая аберрация, движок — инструмент)

**Исправлено**
- Тени ламп пропадали, если точечных источников больше двух (прожекторов —
  больше четырёх) или если лампа слабее соседних: мест в атласе было 4 + 2, и
  раздавались они самым ярким. Теперь тень получает каждый источник с
  «Отбрасывает тени»: ламп больше — плитки атласа мельчают, затем атлас растёт
  (до 8192). Шейдеру массивы по местам больше не нужны — проекцию прожектора и
  плитку он считает сам, поэтому лимита uniform-переменных тоже нет.
- Хроматическая аберрация: при заметной силе контур распадался на три копии со
  щелями, у края кадра выборка уходила за кадр, сила упиралась в 1% кадра.
  Теперь это спектральная кайма (как у объектива), выборка не выходит за кадр,
  сила без потолка.

**Добавлено**
- Параметры аберрации «Чистый центр» (радиус без эффекта) и «Качество» (число
  выборок по спектру).

**Изменено**
- Правило «движок — инструмент, а не конструктор» (CLAUDE.md): решения под
  конкретную игру или жанр в движок не входят. `games/voxelworld` — отдельная
  игра: по умолчанию не собирается (`-DSAGE_BUILD_VOXELWORLD=ON`), в smoke-тест
  и релиз не входит, описание — в её `README.md`.

### 2026-10-31 (универсальная система рендеринга)

**Добавлено**
- Свой рендер (docs/render_pipeline.md). Рендерер — подключаемая часть:
  `RenderPipeline` + реестр `RenderPipelineRegistry` + исполнитель
  `PipelineRenderer`. Встроенный PBR — одна из реализаций (`"sage.pbr"`,
  `StandardPipeline`), его этапы переопределяются наследником, а в кадр
  вставляются свои проходы по имени (`AddExtension`, `AddPassBefore/After`,
  `DisablePass`).
- Граф кадра `RenderGraph`: ресурсы по описанию (цели и буферы создаёт и
  держит в пуле граф), импорт чужих и виртуальные ресурсы, проходы
  графика/вычисления/свой, привязка цели и очистка по LoadOp, барьер после
  вычислений, отбрасывание ненужного, время каждого прохода на CPU и GPU,
  `Describe()`.
- `ShaderLibrary`: шейдеры любых стадий (вершинная, фрагментная,
  геометрическая, вычислительная), `#include` со встроенными
  `<sage/common.glsl>` и `<sage/pbr.glsl>`, ошибки с файлом и строкой (и во
  включённых файлах; форматы Mesa, NVIDIA, AMD/Intel), правка на лету — шейдер
  с ошибкой не заменяет рабочий.
- `ShaderMaterial` — материал своего шейдера: любые параметры, текстуры,
  буферы и состояние отрисовки, без привязки к PBR.
- `EffectChain` — свои эффекты пост-обработки и их цепочки в любом порядке.
- RHI: `Capabilities()`, `CreateProgram` (без исключений, ответ по стадиям),
  вычислительные шейдеры (`Dispatch`, `ShaderBarrier`), буферы шейдеров
  (`CreateBuffer`, `BindBuffer`), запись в текстуры (`BindImage`,
  `Texture2DDesc::ShaderWrite`), целые атрибуты вершин (`AttribType::UInt`).
  Реализовано для OpenGL (вычисления — при OpenGL 4.3) и Null; Vulkan честно
  отвечает «не умею».
- Пример `games/voxelworld` — блочная песочница целиком на своём рендерере:
  чанки с упакованными вершинами, сглаженный свет и затенение углов, свет по
  уровням блоков (небо и свой), карта света вычислительным шейдером с
  запасным путём на CPU, вода и стекло, смена дня и ночи, своя
  пост-обработка, интерфейс расширением графа. Входит в smoke-тест (шаг 13).

### 2026-10-31 (SAGE AI, часть 2: SAGE AI Graph)

**Добавлено**
- SAGE AI Graph — поведение узлами и проводами (docs/ai.md). Графы поведения,
  задач и графы-функции (`assets/ai/*.aigraph`) — это задачи мира ИИ: граф
  зовёт Lua-задачу и наоборот, параметры и результаты передаются одинаково.
- Узлы: Sequence, Branch, циклы (While, For, For Each, Break), Parallel (все /
  первая — проигравшая ветка снимается вместе со своей задачей), Wait, Wait
  Until, Call Task, Run Task, Wait For Task, Cancel Task, Return; события (On
  Event, Wait For Event, Emit); переменные local / instance / shared / входы /
  выходы; математика, логика, строки, списки, структуры, повороты.
- Мир движка в графе: свой объект, поиск, позиция и направление, расстояние,
  Raycast, прямая видимость, «видит ли» (дальность + угол + заслон), поиск
  рядом, путь (навигация проекта через `ai.path_finder`), свойства
  компонентов и функции скриптов по имени, и узел на каждую функцию API
  скриптов — новый `Bind` в движке появляется в палитре сам.
- Свои узлы, типы и правила проводов на Lua: `ai.node`, `ai.type`,
  `ai.connect_rule`, `ai.convert_rule`; `ai.graph`, `ai.load_library`,
  `ai.agent_of`. Библиотека ИИ проекта (`assets/ai`) грузится в Play и в
  собранной игре.
- Компонент «AI» объекта: граф поведения слотом, общая область, память на
  старте; в Play объект сам получает ИИ и запускает граф.
- Окно «AI Graph»: холст с группами и комментариями, палитра с поиском (провод
  в пустоту — только подходящие узлы), проверка совместимости проводов с
  причиной, свойства узла, переменные графа, отмена, копирование. Двойной
  щелчок по `.aigraph` в Assets открывает граф.
- Отладка: подсветка шагавших и текущих узлов, значения пинов, точки останова
  (F9) и шаг по узлам (F10), окно «Отладчик ИИ» — дерево всех задач (граф,
  Lua, C++) с причиной конца, живые переменные, история.
- Плагины редактора: `editor.graph_pin` (своё поле значения типа),
  `editor.graph_tool` (кнопка на панели графа).
- Значения движка: поворот, список и структура (`sage::vars::Value`); таблица
  Lua в переменных ИИ становится списком или структурой.

**Изменено**
- Пока окно графа ИИ в фокусе, Ctrl+Z / Ctrl+Y / Ctrl+S / Del / Ctrl+D
  относятся к графу, а не к сцене.
- Событие `sage.events.Emit` слышат и графы ИИ (On Event, Wait For Event).

### 2026-10-31 (SAGE AI, часть 1: система задач)

**Добавлено**
- SAGE AI — основа игрового ИИ без встроенных сценариев (docs/ai.md). Задача —
  своя единица поведения: `ai.task("MoveTo", {inputs = …, outputs = …, run =
  function(t) … end, cancel = …})`. Долгая задача — линейный код с
  `t.wait(сек)`, `t.wait_event`, `t.wait_until` и не начинается заново каждый
  кадр.
- Состояния выполнения `running` / `succeeded` / `failed` / `cancelled`,
  ручка `h` (`h.status`, `h.ok`, `h.outputs`, `h.cancel()`), вложенные
  (`t.run`) и параллельные (`t.start` + `t.wait_all` / `t.wait_any`) задачи.
  Дочерняя задача не переживает родителя; отмена идёт изнутри наружу.
- Экземпляр ИИ `ai.agent(self, {shared = "guards"})`; переменные трёх
  областей — `t.locals` (выполнение), `t.instance` (персонаж), `t.shared`
  (именованная общая область, `ai.shared("guards")`).
- События ИИ (`ai.emit`, `brain.emit`) и операции (`ai.operation`, `ai.call`).
- Задачи и операции на C++ (`ScriptEngine::AI()`, `sage::ai::MakeTask`) в той же
  библиотеке, что и на Lua: задачи зовут друг друга по имени, не зная, на чём
  написана другая. Точка подключения визуального SAGE AI Graph —
  `TaskDefinition` / `TaskBehavior`.

  ассетов — едет весь набор, в порядке на экране. Работает везде, куда
  бросали один предмет: иерархия, папки ассетов (сетка и дерево), вьюпорт,
  объекты на папку — по префабу на каждый.
- Порядок объектов в списке сцены: бросок на верхнюю четверть строки ставит
  группу перед ней, на нижнюю — после, на середину — внутрь. Порядок
  сохраняется в сцене (ключ `order`), переживает копирование и префабы,
  `obj.children` в скриптах отдаёт детей в этом порядке. Для своего кода —
  `Scene::MoveObjects`, `Scene::ChildrenOf`.
- Папки в панели ассетов переносятся перетаскиванием (раньше — только файлы);
  перенос папки в саму себя или во вложенную отклоняется.

**Исправлено**

- После очистки консоли кнопки уровней и статусная строка продолжали
